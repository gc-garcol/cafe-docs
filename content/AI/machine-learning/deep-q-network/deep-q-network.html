Deep Q-Network

Q-learning with a neural network in place of the table, plus two tricks that keep it from falling apart while it learns.

#reinforcement learning#dqn#experience replay#target network

Try it first

A corridor of eight cells. Reaching the right end pays +1, the left end pays nothing, and the discount shrinks the value of far-away reward. A small network reads the cell and outputs a value for going left and right. Press Run and bars should climb toward the dark markers. Then switch off the replay buffer or the target network and watch learning get shakier.

Readout

    

  






  
1. When a table is too small

  
A Q table needs one row per state. A game screen has astronomically many states. A Deep Q-Network (DQN) replaces the table with a neural network $Q_\theta(s,a)$, which generalizes between similar states. DeepMind used it to play Atari games from raw pixels.






  
2. The learning target

  
Treat Q-learning as regression. For a transition $(s,a,r,s')$ the network should output

  
$$y=r+\gamma\max_{a'}Q_{\theta^-}(s',a')$$

  
and the loss is $(y-Q_\theta(s,a))^2$, minimized by gradient descent, just as in Backpropagation. Unlike ordinary supervised learning, the target $y$ itself depends on the network, so the goal keeps moving. Two tricks tame that.






  
3. Trick 1: experience replay

  
Consecutive steps are nearly identical and strongly correlated, which makes gradient descent unstable. DQN stores the last transitions in a replay buffer and trains on small random batches from it. This breaks the correlation and lets each experience be reused many times.






  
4. Trick 2: the target network

  
In the target $y$, the max uses a frozen copy $\theta^-$ of the network, refreshed only every $C$ steps. Without it, each update shifts its own target and the values can chase each other and diverge. Set sync to 1 above to see the effect.
