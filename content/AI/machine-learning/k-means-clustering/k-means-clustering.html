K-means Clustering

Find groups in data that has no labels. Drop $k$ centers, let every point join its nearest one, move each center to the middle of its group, and repeat until nothing changes.

1. The idea

  
A cluster is a group of points that sit close together. K-means describes each cluster by one point, its center, also called a centroid. Every data point belongs to the cluster whose center is nearest. You choose $k$, the number of clusters, in advance.

  
Good centers make points close to them. Good assignments make each point close to its center. K-means improves one while holding the other fixed.






  
2. The goal

  
K-means searches for the centers $\mu_1, \dots, \mu_k$ and the assignments that make the total squared distance as small as possible. This total is the inertia, or within-cluster sum of squares:

  
$$J = \sum_{j=1}^{k} \sum_{x_i \in C_j} \lVert x_i - \mu_j \rVert^2$$

  
Here $C_j$ is the set of points assigned to cluster $j$. A small $J$ means tight, compact groups. There is no label to compare against, so $J$ is the only score the algorithm sees.






  
3. The loop

  
The algorithm, also called Lloyd's algorithm, repeats two steps.

  
    
    
  1. Assign. Give each point to its nearest center: $c_i = \arg\min_j \lVert x_i - \mu_j \rVert^2$.
    2. 
    
  2. Update. Move each center to the mean of its points: $\mu_j = \dfrac{1}{|C_j|}\sum_{x_i \in C_j} x_i$.
    3. 
  

  
The mean is the right move because it is the single point that minimizes the sum of squared distances to a set. So neither step can make $J$ larger. Since there are only finitely many ways to split the points, $J$ must stop changing, and the loop ends. In the lab, the run finishes when an Assign step changes no point.






  
4. What can go wrong

  
    
    
  • Bad starts. The result is only a local minimum. Two centers born in the same blob can leave another blob with none. Press New centers a few times and compare the inertia. Real libraries run many starts and keep the best, and use k-means++ to spread the first centers apart.
    • 
    
  • Choosing k. Inertia always falls as $k$ grows, down to zero when $k$ equals the number of points. So look for the elbow in Fig 2, where adding another cluster stops helping much.
    • 
    
  • Round blobs only. Distance to a center favors clusters of similar size and round shape. Long curved shapes or rings get cut in pieces.
    • 
    
  • Scale matters. A feature measured in thousands will outvote one measured in tenths. Standardize features first.
    • 
    
  • Outliers. A far point pulls its center toward it, because a mean is not robust.
    • 
  






  
5. The same thing in code

  
function kmeans(points, k, maxIter = 100) {
  // start from k distinct data points
  let centers = shuffle(points).slice(0, k).map(p => [...p]);
  let labels = new Array(points.length).fill(-1);

  for (let iter = 0; iter < maxIter; iter++) {
    // assign: nearest center for each point
    let changed = false;
    points.forEach((p, i) => {
      const c = nearest(p, centers);
      if (c !== labels[i]) { labels[i] = c; changed = true; }
    });
    if (!changed) break;

    // update: each center becomes the mean of its points
    centers = centers.map((old, j) => {
      const mine = points.filter((_, i) => labels[i] === j);
      return mine.length ? mean(mine) : old;
    });
  }
  return { centers, labels };
}

  
Each pass costs $O(n\,k\,d)$ for $n$ points in $d$ dimensions, which is why k-means scales to millions of rows.
