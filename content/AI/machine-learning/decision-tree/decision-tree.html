1. Questions, not equations

  
A tree predicts by asking a chain of simple questions such as "is $x_1 < 100$?". Each question sends the point left or right. A leaf holds the answer, the majority class of the training points that reached it. Reading the path from the root to a leaf gives a rule a person can follow, which is why trees are called interpretable.






  
2. Choosing the best question

  
We need a score for how mixed a group is. The Gini impurity of a node whose class shares are $p_c$ is

  
$$G = 1 - \sum_{c} p_c^2$$

  
It is $0$ when the node is pure and $0.5$ when two classes are evenly mixed. A split sends $n_L$ points left and $n_R$ right. Its quality is the weighted impurity of the two children, and the tree picks the feature and threshold that make it smallest:

  
$$\min_{j,\,t}\;\; \frac{n_L}{n}\,G_L + \frac{n_R}{n}\,G_R$$

  
Candidate thresholds are the midpoints between neighboring sorted values. Entropy, $-\sum p_c \log p_c$, is a common alternative score and behaves almost the same.






  
3. Growing the tree

  
    
    
  1. Start with all the training points in one node.
    2. 
    
  2. If the node is pure, or a limit is reached, make it a leaf.
    3. 
    
  3. Otherwise find the best split, send points left and right, and repeat on each side.
    4. 
  

  
This is greedy: each split is best on its own, with no look ahead. A pattern like XOR, where no single question helps by itself, is a known weakness, because the first split shows no gain.






  
4. Overfitting and how to stop it

  
Left alone, a tree keeps splitting until every training point is correct, which means it memorizes the noise. Fig 2 shows the symptom: training accuracy climbs to 100% while test accuracy stalls. Common fixes are

  
    
    
  • limit the maximum depth, as in the lab,
    • 
    
  • require a minimum number of points in each leaf,
    • 
    
  • prune branches that do not help on validation data,
    • 
    
  • average many trees, which is the idea behind random forests.
    • 
  






  
5. The same thing in code

  
function gini(rows) {
  const n = rows.length, a = rows.filter(r => r.label === 0).length / n;
  return 1 - a * a - (1 - a) * (1 - a);
}

function grow(rows, depth, maxDepth) {
  if (depth === maxDepth || gini(rows) === 0) return { leaf: majority(rows) };

  let best = null;
  for (const feature of [0, 1]) {
    for (const t of midpoints(rows, feature)) {
      const L = rows.filter(r => r.x[feature] < t);
      const R = rows.filter(r => r.x[feature] >= t);
      const score = (L.length * gini(L) + R.length * gini(R)) / rows.length;
      if (!best || score < best.score) best = { feature, t, score, L, R };
    }
  }
  if (!best) return { leaf: majority(rows) };
  return { feature: best.feature, t: best.t,
           left:  grow(best.L, depth + 1, maxDepth),
           right: grow(best.R, depth + 1, maxDepth) };
}






  
6. Strengths and limits

  

    
Strength
readable
Each prediction comes with a short list of rules.

    
Strength
no scaling
Only the order of values matters, so there is no need to standardize features.

    
Limit
unstable
A small change in the data can change the top split, and with it the whole tree.

  

  
A tree draws boxes, while Logistic Regression draws one slanted line and k-NN draws a curved boundary. For the full map, see Machine Learning Algorithm Groups. Structurally a tree is a binary tree of questions, like the ones in AVL Tree, but learned rather than balanced.
