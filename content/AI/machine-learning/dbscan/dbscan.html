DBSCAN

Clusters are crowds, not circles. Grow a cluster outward from any point that has enough close neighbors, and leave lonely points as noise.

1. Density, not distance to a center

  
DBSCAN, short for Density-Based Spatial Clustering of Applications with Noise, calls a region a cluster when it is dense enough. It needs two settings: a radius $\varepsilon$ and a count minPts. It does not need the number of clusters, and clusters can have any shape.






  
2. Three kinds of point

  

    
KindRule

    
      
Coreat least minPts points, itself included, lie within $\varepsilon$

      
Bordernot core, but within $\varepsilon$ of a core point

      
Noiseneither. It belongs to no cluster.

    
  






  
3. The algorithm

  
Scan the points. Take an unvisited core point and start a new cluster. Put all its $\varepsilon$-neighbors in the cluster. Any neighbor that is itself core adds its own neighbors, and so on, until the cluster stops growing. Border points join but do not spread. Repeat with the next unvisited core point.

  
Two core points within $\varepsilon$ of each other always end in the same cluster, so clusters are chains of overlapping balls.






  
4. Choosing the settings

  
    
    
  • Raise $\varepsilon$ and clusters merge, and noise disappears. Lower it and clusters split into pieces and more points turn to noise.
    • 
    
  • minPts is often set near $2\times$ the number of dimensions, and at least 3.
    • 
    
  • To pick $\varepsilon$, sort every point's distance to its $k$-th nearest neighbor. The "knee" of that curve is a good value.
    • 
  






  
5. Strengths and limits

  
    
    
  • Finds odd shapes and marks outliers by itself.
    • 
    
  • One $\varepsilon$ cannot fit clusters of very different densities. HDBSCAN removes that limit.
    • 
    
  • Distances lose meaning in many dimensions, so it works best on a few.
    •
