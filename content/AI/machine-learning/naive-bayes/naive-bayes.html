A classifier built from counting. Use Bayes' theorem to ask how likely each class is given the evidence, and pretend every clue is independent so the math stays simple.

1. Bayes' theorem as a classifier

  
We want the chance of a class $c$ given the features $x$. Bayes' theorem flips it into things we can count:

  
$$P(c \mid x) = \frac{P(x \mid c)\,P(c)}{P(x)} \;\propto\; P(c)\,P(x \mid c)$$

  
The denominator is the same for every class, so to pick a class we only compare the numerators. The prior $P(c)$ is how common the class is. The likelihood $P(x \mid c)$ is how typical these features are inside the class.






  
2. The naive part

  
Writing the likelihood of many features together needs a huge table. Naive Bayes assumes the features are independent once the class is known:

  
$$P(x_1,\dots,x_d \mid c) = \prod_{j=1}^{d} P(x_j \mid c)$$

  
That is rarely true, since "free" and "winner" tend to arrive together. Yet the ranking of classes is often still right, because the errors from each feature partly cancel. Each $P(x_j \mid c)$ is just a count divided by a total.

  
Naive is the assumption. The counts are honest.






  
3. Log-odds make it additive

  
Products of small numbers underflow, and they are hard to read. Take logs and the product becomes a sum. For two classes, the log-odds of spam is the prior log-odds plus one term per word:

  
$$\log\frac{P(\text{spam}\mid x)}{P(\text{ham}\mid x)} = \log\frac{P(\text{spam})}{P(\text{ham})} + \sum_{j=1}^{d} \log\frac{P(x_j \mid \text{spam})}{P(x_j \mid \text{ham})}$$

  
These are the bars in Fig 1. Convert the total back to a probability with the sigmoid $\sigma(z)=1/(1+e^{-z})$, the same function used in Logistic Regression. In fact, Naive Bayes for two classes is a linear model, with weights taken from counts rather than learned by descent.






  
4. Learning is counting

  
    
    
  • The prior is the fraction of training emails in each class.
    • 
    
  • The chance of a word given a class is the number of emails of that class containing it, divided by the size of the class.
    • 
    
  • Smoothing. A word never seen in spam would give probability 0 and veto everything. Laplace smoothing adds 1 to the count and 2 to the total: $p = \dfrac{n+1}{N+2}$.
    • 
    
  • A word that is absent counts too, with probability $1-p$. This version is called Bernoulli Naive Bayes. Another version counts how many times each word occurs.
    • 
  






  
5. The same thing in code

  
function spamProbability(present, prior, counts, nSpam, nHam) {
  let z = Math.log(prior / (1 - prior));       // prior log-odds
  for (const w of Object.keys(counts)) {
    const ps = (counts[w].spam + 1) / (nSpam + 2);  // smoothed P(word | spam)
    const ph = (counts[w].ham  + 1) / (nHam  + 2);  // smoothed P(word | ham)
    z += present[w] ? Math.log(ps / ph)
                    : Math.log((1 - ps) / (1 - ph));
  }
  return 1 / (1 + Math.exp(-z));                    // sigmoid
}






  
6. Strengths and limits

  

    
Strength
fast
One pass over the data to train. It copes well with thousands of features and little data.

    
Strength
readable
Every feature has a clear contribution to the decision, like the bars above.

    
Limit
correlated
Repeated, dependent clues get counted twice, so the probabilities are overconfident. Use the ranking, not the exact number.
