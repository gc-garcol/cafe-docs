Optimizers: SGD, Adam and Newton's Method

Plain gradient descent takes the same kind of step everywhere. Better optimizers adapt the step to the shape of the loss.

#optimization#sgd#adam#newton

Try it first

A long, narrow valley: steep across, flat along. Four optimizers start from the same point and race to the minimum at the center. Drag the step slider to replay the first 60 steps. Raise the learning rate and watch plain descent zigzag. Turn the noise up and see why stochastic gradients wander.

Readout

    

  






  
1. Gradient descent, again

  
Gradient Descent moves against the gradient: $\theta\leftarrow\theta-\eta\,\nabla L(\theta)$. In a narrow valley the gradient points mostly across it, so the path zigzags while progress along the floor is slow. A small $\eta$ is safe but slow. A large $\eta$ bounces. Push the rate toward 0.19 and the zigzag grows, and at 0.2 it would diverge.






  
2. Stochastic gradient descent

  
The true gradient averages over all training data, which is costly. SGD estimates it from one example or a small mini-batch. The estimate is noisy but cheap, so you can take many more steps for the same work:

  
$$\theta\leftarrow\theta-\eta\,\nabla L_{\text{batch}}(\theta)$$

  
The noise slows precise convergence, because the iterate keeps jittering around the minimum. A decaying learning rate calms it. The same noise can help escape sharp local dips. Momentum keeps a running average of past gradients, which smooths zigzags.






  
3. Adam

  
Adam gives every parameter its own step size. It keeps a running mean $m$ of the gradient (momentum) and a running mean $v$ of its square, corrected for their start at zero:

  
$$m\leftarrow\beta_1 m+(1-\beta_1)g,\quad v\leftarrow\beta_2 v+(1-\beta_2)g^2,\quad \theta\leftarrow\theta-\eta\,\frac{\hat m}{\sqrt{\hat v}+\epsilon}$$

  
Dividing by $\sqrt{\hat v}$ makes steep directions take smaller steps and flat ones larger steps, so progress is even in the valley. Typical values are $\beta_1=0.9$, $\beta_2=0.999$. It is the default for most deep networks.






  
4. Newton's method

  
Newton uses curvature as well, through the Hessian $H$ of second derivatives:

  
$$\theta\leftarrow\theta-H^{-1}\nabla L(\theta)$$

  
It rescales each direction by how curved it is, so the valley looks round. On a pure bowl it reaches the minimum in a single step. Near the end it converges very fast. The catch is cost: for $d$ parameters the Hessian has $d^2$ entries and the inversion about $d^3$ operations, impossible for millions of weights. It also needs the Hessian to be positive definite. Quasi-Newton methods such as L-BFGS approximate it cheaply.
