1. What convolution computes

  
Place a small grid of weights, the kernel $K$, over a patch of the image. Multiply each weight by the pixel under it and add everything up. That sum is one output value. Slide the kernel to the next position and repeat. For a kernel of size $k$:

  
$$Y_{i,j} = \sum_{u=0}^{k-1}\sum_{v=0}^{k-1} K_{u,v}\; X_{i+u,\,j+v} + b$$

  
The sum is large where the patch looks like the kernel and small or negative where it does not. A vertical edge kernel lights up on vertical edges, and the output is a feature map of where that pattern occurs. Deep learning libraries call this convolution, but strictly it is cross-correlation, because the kernel is not flipped. Since the weights are learned, the flip makes no difference.

  
The same few weights are reused at every position, so a pattern is found wherever it appears.






  
2. Output size, stride and padding

  
A kernel cannot hang over the edge unless you pad the image with zeros. Stride is how many pixels the kernel jumps each step. For input size $n$, kernel $k$, padding $p$ and stride $s$:

  
$$n_{\text{out}} = \left\lfloor \frac{n + 2p - k}{s} \right\rfloor + 1$$

  

    
ChoiceEffect on the output

    
      
Padding 0 ("valid")Shrinks by $k-1$ pixels in each direction. Edge pixels are used less.

      
Padding 1 with $k=3$ ("same")Keeps the size when stride is 1. Try it in the lab: 8×8 stays 8×8.

      
Stride 2Roughly halves the size. A cheap way to downsample.

    
  






  
3. Why it beats a fully connected layer

  
A dense layer from an 8×8 image to a 6×6 map needs $64 \times 36 = 2304$ weights. The convolution above needs $9$ (plus a bias). That is the gain from two assumptions that suit images:

  
    
    
  • Local connectivity. Each output looks only at a small patch, because nearby pixels matter most.
    • 
    
  • Weight sharing. The same kernel is used everywhere, so a pattern need not be relearned at every position. A shifted input gives a shifted feature map, a property called translation equivariance.
    • 
  

  
Real layers apply many kernels at once. A layer with $C_{\text{in}}$ input channels and $C_{\text{out}}$ filters of size $k$ has $C_{\text{out}}(C_{\text{in}}k^2+1)$ parameters, whatever the image size.






  
4. Activation and pooling

  
A convolutional layer is usually the filter, then a nonlinearity, then optionally a pooling step.

  
    
    
  • ReLU sets negative responses to zero, keeping only "the pattern is here". See Activation Functions.
    • 
    
  • Max pooling keeps the largest value in each 2×2 block. It halves the size, and a small shift of the pattern no longer changes the result.
    • 
  

  
Stack many such layers and the network builds up a hierarchy. Early filters respond to edges and colors, middle ones to textures and parts, and late ones to whole objects. Finish with a few dense layers or a global average to classify. Training the kernels uses backpropagation exactly as for dense layers, with the gradients summed over every position where a weight was used.






  
5. The same thing in code

  
function conv2d(X, K, stride = 1, pad = 0) {
  const n = X.length + 2 * pad, k = K.length;
  const at = (i, j) => X[i - pad]?.[j - pad] ?? 0;      // zero padding
  const out = [];
  for (let i = 0; i + k <= n; i += stride) {
    const row = [];
    for (let j = 0; j + k <= n; j += stride) {
      let s = 0;
      for (let u = 0; u < k; u++)
        for (let v = 0; v < k; v++) s += K[u][v] * at(i + u, j + v);
      row.push(s);
    }
    out.push(row);
  }
  return out;
}
