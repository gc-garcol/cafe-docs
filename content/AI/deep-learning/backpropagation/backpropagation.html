Backpropagation

How a network learns which of its weights to blame. One forward pass computes the loss, one backward pass hands every weight its gradient, using nothing but the chain rule.

1. The setup

  
For one example $(\mathbf{x}, t)$, the forward pass of the network above is:

  
$$z_i = \sum_j w_{ij}x_j + b_i,\quad h_i = \tanh z_i,\quad \hat{y} = \sum_i v_i h_i + c,\quad L = \tfrac12(\hat{y}-t)^2$$

  
Training needs $\partial L/\partial\theta$ for every parameter $\theta$ (nine here). Computing each one separately is wasteful. Backpropagation gets all of them in one backward sweep, at about the cost of one more forward pass.






  
2. The chain rule, one link at a time

  
If $L$ depends on $u$ and $u$ depends on $\theta$, then $\dfrac{\partial L}{\partial\theta} = \dfrac{\partial L}{\partial u}\cdot\dfrac{\partial u}{\partial\theta}$. Walk back from the loss and reuse what you already have. Each quantity below is the error signal of a node:

  

    
StepFormulaMeaning

    
      
Output$\delta_y = \hat{y} - t$How far the prediction is from the target

      
Output weights$\dfrac{\partial L}{\partial v_i} = \delta_y\,h_i,\quad \dfrac{\partial L}{\partial c} = \delta_y$Error times the input each weight saw

      
Hidden output$\dfrac{\partial L}{\partial h_i} = \delta_y\,v_i$Error sent backward along the link

      
Through tanh$\delta_i = \dfrac{\partial L}{\partial h_i}\,(1 - h_i^2)$Scaled by the activation slope

      
Hidden weights$\dfrac{\partial L}{\partial w_{ij}} = \delta_i\,x_j,\quad \dfrac{\partial L}{\partial b_i} = \delta_i$Again error times input

    
  

  
Every weight's gradient is the error at its output times the value at its input.

  
In a deeper network the same two moves repeat: multiply by the transposed weight matrix to pass the error back, then by the activation slope. In matrix form, $\boldsymbol{\delta}^{(l)} = \big(W^{(l+1)}\big)^{\mathsf T}\boldsymbol{\delta}^{(l+1)}\odot f'(\mathbf{z}^{(l)})$. That product of slopes is why activation functions decide whether gradients survive depth.






  
3. The update

  
With all gradients in hand, gradient descent moves each parameter downhill:

  
$$\theta \leftarrow \theta - \eta\,\frac{\partial L}{\partial\theta}$$

  
Press Step a few times with a rate of $0.1$. The prediction slides toward the target and the loss drops. Raise the rate near $0.5$ and the loss can overshoot, as in the gradient descent doc. With many examples, the gradients are averaged over a batch before the update.






  
4. Why it is fast

  
    
    
  • Reuse. The error signal at a node is computed once and shared by every weight that feeds it.
    • 
    
  • Cost. The backward pass costs about the same as the forward pass, however many parameters there are. Perturbing each parameter in turn would cost one forward pass per parameter.
    • 
    
  • Memory. The backward pass needs the forward values $h_i$ and $z_i$, so frameworks store them. This is why training uses far more memory than running a model.
    • 
    
  • Automatic. Frameworks such as PyTorch and JAX record the computation graph and apply the chain rule for you. You write the forward pass only.
    • 
  






  
5. The same thing in code

  
function forward(p, x) {
  const h = p.W.map((row, i) => Math.tanh(row[0] * x[0] + row[1] * x[1] + p.b[i]));
  const y = h[0] * p.v[0] + h[1] * p.v[1] + p.c;
  return { h, y };
}

function backward(p, x, t) {
  const { h, y } = forward(p, x);
  const dy = y - t;                              // error at the output
  const dz = h.map((hi, i) => dy * p.v[i] * (1 - hi * hi));
  return {
    v: h.map(hi => dy * hi),   c: dy,
    W: dz.map(d => [d * x[0], d * x[1]]),  b: dz
  };
}
