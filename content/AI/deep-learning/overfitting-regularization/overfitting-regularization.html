Overfitting and Regularization

A model that memorizes its training data fails on new data. See why, how to spot it with a validation set, and how a penalty on large weights pulls the fit back.

Try it first

Twelve noisy training points (orange) come from a smooth curve. A polynomial of the degree you choose is fitted to them. Forty validation points (blue) were never used to fit, so they show how well the model generalizes. Raise the degree and the curve starts to chase noise: training error keeps falling while validation error turns upward. Then raise the penalty $\lambda$ and watch the wiggles flatten.

1. Fitting is not learning

  
A model's real job is to do well on data it has not seen. Training error only measures how well it memorized. The gap between the two is the generalization gap.

  
    
    
  • Underfitting. The model is too simple. Both errors are high. Degree 1 in the lab is a straight line through a wave.
    • 
    
  • Good fit. Both errors are low and close. Degree 3 to 5 is about right here.
    • 
    
  • Overfitting. The model is flexible enough to follow the noise. Training error is tiny, validation error is large. Degree 12 passes through nearly every training point and swings wildly between them.
    • 
  

  
Training error always falls with more capacity. Validation error tells the truth.

  
A neural network is the same story with more knobs. A network with millions of weights and a few thousand examples can memorize them all. This is the classic bias and variance trade-off: simple models have high bias, flexible ones have high variance.

Once you pick settings by looking at validation error, it becomes a little optimistic. The test set is the only number that has not been tuned against.






  
3. Regularization: penalize large weights

  
Wild fits need huge coefficients. L2 regularization, also called ridge regression or weight decay, adds a cost for large weights to the loss:

  
$$L_{\text{total}} = \frac{1}{N}\sum_{n}\big(\hat{y}_n - y_n\big)^2 + \lambda \sum_{j} w_j^{2}$$

  
The penalty $\lambda$ sets the trade-off. At $\lambda=0$ the fit is free to chase noise. A moderate $\lambda$ keeps the weights small and the curve smooth. A very large $\lambda$ squeezes every weight to zero and the model underfits. Try the slider at degree 12: a small penalty tames the wiggles without lowering the degree. In gradient descent the penalty adds $2\lambda w$ to each gradient, so every step also shrinks the weight slightly, hence "decay". The bias term is not penalized.

  
L1 regularization, $\lambda\sum_j |w_j|$, instead drives many weights exactly to zero, which gives sparse models.






  
4. Other ways to fight overfitting

  

    
MethodHow it helps

    
      
More dataThe best cure. Noise averages out and memorizing gets harder.

      
Data augmentationFlip, crop or jitter examples to make new ones. Common for images.

      
DropoutRandomly switch off a fraction of neurons each step, so none can be relied on alone.

      
Early stoppingStop training when validation loss stops improving, before the network memorizes noise.

      
Smaller modelFewer layers or neurons means less capacity to memorize.

      
Normalization layersStabilize training and often give a mild regularizing effect.

    
  






  
5. The same thing in code

  
// ridge regression for a polynomial: solve (X'X + lambda*I) w = X'y
function ridgeFit(xs, ys, degree, lambda) {
  const X = xs.map(x => Array.from({ length: degree + 1 }, (_, k) => x ** k));
  const A = new Array(degree + 1).fill(0).map(() => new Array(degree + 1).fill(0));
  const b = new Array(degree + 1).fill(0);
  X.forEach((row, n) => row.forEach((r, i) => {
    b[i] += r * ys[n];
    row.forEach((c, j) => { A[i][j] += r * c; });
  }));
  for (let i = 1; i <= degree; i++) A[i][i] += lambda;   // skip the bias
  return solve(A, b);                              // Gaussian elimination
}
