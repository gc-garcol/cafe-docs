Activation Functions

The small nonlinear bend after every layer. Without it a deep network is just one linear map. With the wrong one, gradients fade to nothing before they reach the first layer. This page plots fourteen activations with their slopes, from sigmoid to the SwiGLU blocks inside today's language models, and covers softmax, initialization and which models use what.

1. Why a network needs one

  
A layer computes $W\mathbf{x} + \mathbf{b}$. Feed that into the next layer and you get $W_2(W_1\mathbf{x}+\mathbf{b}_1)+\mathbf{b}_2$, which is still a matrix times $\mathbf{x}$ plus a vector. Any number of purely linear layers collapse into one. The activation $f$ breaks this:

  
$$\mathbf{h} = f(W\mathbf{x} + \mathbf{b})$$

  
Applied entry by entry, it lets the network bend its decision boundary. With a nonlinear $f$, a wide enough network with one hidden layer can approximate any continuous function on a bounded region (the universal approximation theorem). Depth makes that far more efficient. See the Deep Learning Overview lab, where a single neuron draws only a line.

  
No nonlinearity, no depth. A hundred linear layers equal one.






  
2. What makes a good activation

  

    
PropertyWhy it mattersWho has it

    
      
Non-saturatingA slope that does not go to zero for large inputs keeps gradients flowing.ReLU family, GELU, Swish, Mish on the positive side

      
Nonzero slope for $z < 0$Neurons cannot "die" and stop learning.Leaky ReLU, ELU, SELU, GELU, Swish, Mish

      
Zero-centered outputMean activations near zero keep the next layer's updates balanced.Tanh, ELU, SELU (approximately)

      
SmoothA continuous derivative gives a smoother loss surface and helps optimizers.Sigmoid, tanh, softplus, GELU, Swish, Mish

      
CheapApplied to every unit, billions of times. Exponentials and erf cost more than a comparison.ReLU, Leaky ReLU, ReLU6, hard sigmoid, hard swish

      
BoundedKeeps values in a fixed range: good for gates, probabilities and low-precision hardware.Sigmoid, tanh, softsign, ReLU6, hard sigmoid

    
  

  
No function wins on every row, which is why so many exist. The default moved from sigmoid (1980s), to tanh (1990s), to ReLU (2010s), to GELU and SwiGLU in transformers today.






  
3. Classic: sigmoid and tanh

  

    
Name$f(z)$$f'(z)$Range

    
      
Sigmoid $\sigma$$\dfrac{1}{1+e^{-z}}$$\sigma(z)\,(1-\sigma(z))$, at most $0.25$$(0,1)$

      
Tanh$\dfrac{e^{z}-e^{-z}}{e^{z}+e^{-z}}$$1-\tanh^2 z$, at most $1$$(-1,1)$

      
Softsign$\dfrac{z}{1+|z|}$$\dfrac{1}{(1+|z|)^2}$$(-1,1)$

      
Hard sigmoid$\min\!\big(1, \max(0, \tfrac{z}{6} + \tfrac12)\big)$$\tfrac16$ on $(-3,3)$, else $0$$[0,1]$

    
  

  
Tanh is a sigmoid shifted and stretched: $\tanh z = 2\sigma(2z) - 1$. Being zero-centered and four times steeper at the origin, it trains better as a hidden activation. Both saturate: for $|z| > 4$ the slope is nearly zero, and stacked layers multiply those small slopes together.

  
They are still everywhere as gates. In an LSTM, sigmoid outputs in $(0,1)$ act as soft switches for what to forget, store and emit, and tanh squashes the cell values. Softsign approaches its limits polynomially instead of exponentially, so it saturates more gently. The hard sigmoid replaces the curve with three straight pieces, which is much cheaper on phones and in integer arithmetic. Its slope $\tfrac16$ is the slope used by PyTorch and Keras 3; older Keras versions used $0.2z + 0.5$.






  
4. The ReLU family

  
The rectified linear unit $\max(0, z)$ made deep networks trainable at scale (AlexNet, 2012). Its slope is exactly $1$ for every positive input, so gradients pass through active units without shrinking, and it costs one comparison. Its weakness is the flat half: a unit whose input is always negative gets zero gradient and stops learning. Every variant below changes the negative side.

  

    
Name$z > 0$$z \le 0$Notes

    
      
ReLU$z$$0$The default for CNNs and MLPs.

      
Leaky ReLU$z$$\alpha z$, with fixed $\alpha \approx 0.01$Keeps a small gradient; never fully dies.

      
PReLU$z$$\alpha z$, with $\alpha$ learnedOne $\alpha$ per channel, trained with the weights (He et al., 2015).

      
RReLU$z$$\alpha z$, $\alpha$ random in trainingThe randomness acts as a regularizer; the mean is used at test time.

      
ReLU6$\min(z, 6)$$0$Capped, so it survives low-precision arithmetic (MobileNetV2).

      
ELU$z$$\alpha\,(e^{z} - 1)$Smooth, tends to $-\alpha$; pushes mean activations toward zero.

      
SELU$\lambda z$$\lambda\alpha\,(e^{z}-1)$$\lambda \approx 1.0507$, $\alpha \approx 1.6733$: self-normalizing.

      
CELU$z$$\alpha\,(e^{z/\alpha} - 1)$ELU rewritten so the slope is continuous at $0$ for every $\alpha$.

    
  

  
SELU deserves a note. Its two constants are chosen so that, in a plain fully connected network with LeCun-normal initialization, activations converge toward zero mean and unit variance layer after layer without batch normalization (Klambauer et al., 2017). The promise holds only under those conditions: dropout must be replaced by alpha dropout, and it does not carry over to convolutions or residual connections. In Fig 1 its slope is above $1$ on parts of the curve, which is fine because the normalization keeps inputs near zero.

  
ReLU is not differentiable at $0$. Frameworks simply use $0$ as the slope there. The exact value almost never matters, because an input landing exactly on $0.0$ is rare.






  
5. Smooth activations: GELU, Swish, Mish

  
These look like ReLU from a distance, but they are smooth, dip slightly below zero for negative inputs, and are not monotonic. Empirically they train a little better in deep networks, at a higher compute cost.

  

    
Name$f(z)$MinimumNotes

    
      
Softplus$\ln(1 + e^{z})$none, $> 0$A smooth ReLU. Its derivative is exactly $\sigma(z)$. Used for positive outputs.

      
GELU$z\,\Phi(z)$$\approx -0.17$Weights $z$ by how likely a standard normal is below it. BERT, GPT, ViT.

      
Swish$z\,\sigma(\beta z)$$\approx -0.28$ at $\beta=1$Found by automated search (Ramachandran et al., 2017).

      
SiLU$z\,\sigma(z)$$\approx -0.28$Swish with $\beta = 1$. EfficientNet, YOLOv5 and later.

      
Mish$z \tanh\!\big(\ln(1+e^{z})\big)$$\approx -0.31$Slightly smoother than Swish. YOLOv4.

      
Hard swish$z \cdot \dfrac{\mathrm{ReLU6}(z+3)}{6}$$-0.375$Piecewise approximation of Swish for mobile chips (MobileNetV3).

    
  

  
GELU is usually computed with one of two approximations instead of the error function inside $\Phi$:

  
$$\mathrm{GELU}(z) \approx \tfrac12 z\left(1 + \tanh\!\Big[\sqrt{2/\pi}\,\big(z + 0.044715\,z^3\big)\Big]\right) \approx z\,\sigma(1.702\,z)$$

  
The second form shows that GELU and Swish are close cousins: both multiply $z$ by a sigmoid-like gate of itself. Swish's $\beta$ slides between two extremes. Set $\beta = 0$ in Fig 1 and you get the straight line $z/2$. Push $\beta$ up and the curve sharpens into ReLU, since $\sigma(\beta z)$ becomes a step function.

  
$$\lim_{\beta \to \infty} z\,\sigma(\beta z) = \max(0, z), \qquad z\,\sigma(0 \cdot z) = \tfrac{z}{2}$$






  
6. Gated linear units: GLU to SwiGLU

  
Modern language models mostly do not put a plain activation in their feed-forward blocks. They use a gated linear unit: two linear projections of the same input, one passed through an activation and used as a gate, multiplied element by element with the other.

  
$$\mathrm{GLU}(\mathbf{x}) = \sigma(\mathbf{x}W) \odot (\mathbf{x}V), \qquad \mathrm{FFN}_{\mathrm{SwiGLU}}(\mathbf{x}) = \big(\mathrm{SiLU}(\mathbf{x}W) \odot \mathbf{x}V\big)\,W_2$$

  

    
VariantGate activationUsed in

    
      
GLUSigmoidGated convolutional language models (Dauphin et al., 2017)

      
ReGLUReLUExperiments in Shazeer (2020)

      
GeGLUGELUT5 v1.1, Gemma

      
SwiGLUSiLU (Swish)PaLM, LLaMA, Mistral, Qwen and most open LLMs

    
  

  
The product of two linear paths is a quadratic interaction, which gives the block more expressive power per parameter. In Shazeer's comparison, GeGLU and SwiGLU gave the lowest perplexity among the variants tested. A gated block has three weight matrices instead of two, so to keep the parameter count equal the hidden width is cut from $4d$ to about $\tfrac{2}{3} \cdot 4d = \tfrac{8}{3}d$. LLaMA rounds that to a multiple of 256.

  
An older idea in the same spirit is maxout: compute $k$ linear pieces and keep the largest, $\max_i (\mathbf{w}_i^{\mathsf T}\mathbf{x} + b_i)$. It learns its own convex piecewise-linear activation, at $k$ times the parameters.






  
7. Output layers and softmax

  
The last layer's activation is not a tuning choice. It is set by what the output means, and it is paired with a specific loss:

  

    
TaskOutput activationLoss

    
      
Real numberNone (identity)Mean squared error

      
Positive numberSoftplus or $\exp$MSE, or a likelihood such as Poisson

      
Value in a rangeTanh or sigmoid, rescaledMSE

      
Two classes, or multi-labelSigmoid per outputBinary cross-entropy

      
One of $K$ classesSoftmaxCross-entropy

    
  

  
Softmax turns a vector of scores (logits) into probabilities that are positive and sum to $1$. A temperature $T$ controls how peaked the result is:

  
$$\mathrm{softmax}(\mathbf{z})_i = \frac{e^{z_i / T}}{\sum_{j} e^{z_j / T}}$$


  

  
At $T \to 0$ softmax becomes argmax: all probability on the largest logit. At large $T$ it tends to uniform. Language models sample with $T$ below $1$ for focused text and above $1$ for more variety. Knowledge distillation trains a small model on a large model's softmax at high $T$, where the near-misses carry information.

  
Three practical details

  
    
    
  • Subtract the max. $e^{1000}$ overflows. Softmax does not change when every logit shifts by the same amount, so compute $e^{z_i - \max_j z_j}$ instead.
    • 
    
  • Use log-softmax with the loss. $\log \mathrm{softmax}(\mathbf{z})_i = z_i - \log\sum_j e^{z_j}$, computed with the log-sum-exp trick, avoids taking the log of a value that underflowed to $0$. Framework losses such as CrossEntropyLoss take raw logits for this reason.
    • 
    
  • The gradient is simple. With probabilities $\mathbf{p}$ and one-hot target $\mathbf{y}$, the gradient of cross-entropy with respect to the logits is $\mathbf{p} - \mathbf{y}$. Sigmoid with binary cross-entropy gives the same form, $p - y$. That cancellation is why these pairs are standard.
    • 
  






  
8. Vanishing and dying gradients

  
Backpropagation multiplies one slope per layer. If every slope is below $1$, the product shrinks exponentially with depth:

  
$$\frac{\partial L}{\partial \mathbf{h}_1} \;\propto\; \prod_{l=1}^{n} f'(z_l)\;\le\; \big(\max f'\big)^{n}$$

  
Sigmoid has $\max f' = 0.25$, so ten layers shrink the signal by at least $0.25^{10} \approx 10^{-6}$. The early layers barely learn. In Fig 1, pick sigmoid, set $z = 0$ (its best case) and move the Layers slider. The real product also includes the weights, so it can be larger or smaller, but saturated slopes always pull it down.

  
    
    
  • Saturation. At large $|z|$, sigmoid and tanh go flat and the slope is near zero. Drag $z$ to $4$ and read the slope.
    • 
    
  • Dying ReLU. If $z<0$ for every input, the slope is $0$ and the neuron never updates again. A too-large learning rate or a big negative bias can kill a large share of units. Leaky ReLU, ELU and the smooth functions keep a small gradient there.
    • 
    
  • Exploding gradients. A product of factors above $1$ grows instead. Careful initialization, normalization layers and gradient clipping handle this.
    • 
    
  • Residual connections sidestep the product altogether: $\mathbf{h}_{l+1} = \mathbf{h}_l + F(\mathbf{h}_l)$ adds an identity path whose slope is always $1$. That, more than the choice of activation, is what makes networks with hundreds of layers trainable.
    • 
  






  
9. Activations and initialization

  
Weights are initialized so that the variance of activations stays roughly constant from layer to layer. The right scale depends on the activation, because ReLU zeroes half of its inputs and so halves the variance:

  

    
Scheme$\mathrm{Var}(W)$Pairs with

    
      
Xavier / Glorot$\dfrac{2}{n_{\text{in}} + n_{\text{out}}}$Tanh, sigmoid, softsign

      
He / Kaiming$\dfrac{2}{n_{\text{in}}}$ReLU, Leaky ReLU (with a gain), GELU, Swish

      
LeCun$\dfrac{1}{n_{\text{in}}}$SELU (required for self-normalization)

    
  

  
Here $n_{\text{in}}$ and $n_{\text{out}}$ are the number of inputs and outputs of the layer. For Leaky ReLU with slope $\alpha$, the He variance becomes $\frac{2}{(1+\alpha^2)\,n_{\text{in}}}$. PyTorch's nn.init.calculate_gain returns these factors. With normalization layers (BatchNorm, LayerNorm) in the network, the exact choice matters much less.

11. Which one to pick

  

    
Default
ReLU
CNNs and MLPs. Fast, well understood, pairs with He initialization. Switch to Leaky ReLU if many units die.

    
Transformers
GELU or SwiGLU
GELU in encoder models and small transformers; SwiGLU in the feed-forward blocks of large language models.

    
Mobile, quantized
ReLU6, hard swish
Piecewise linear, bounded, no exponentials. Friendly to 8-bit integer inference.

  

  
    
    
  • Deep CNNs where a small accuracy gain matters: SiLU or Mish, at some extra compute.
    • 
    
  • Plain deep MLP without normalization: SELU with LeCun-normal initialization and alpha dropout.
    • 
    
  • Gates and attention-style weights: sigmoid. Recurrent state: tanh.
    • 
    
  • Output layer: follow the table in section 7, never a hidden-layer habit.
    • 
  

  
The activation is rarely the biggest lever. Architecture, normalization, learning rate and data usually matter more. Change it last, and measure.






  
12. The same thing in code

  
const sigmoid  = z => 1 / (1 + Math.exp(-z));
const relu     = z => Math.max(0, z);
const leaky    = (z, a = 0.01) => (z > 0 ? z : a * z);
const elu      = (z, a = 1) => (z > 0 ? z : a * Math.expm1(z));
const softplus = z => Math.max(z, 0) + Math.log1p(Math.exp(-Math.abs(z)));  // stable for large |z|
const silu     = z => z * sigmoid(z);
const gelu     = z => 0.5 * z * (1 + Math.tanh(Math.sqrt(2 / Math.PI) * (z + 0.044715 * z ** 3)));
const mish     = z => z * Math.tanh(softplus(z));
const hswish   = z => z * Math.min(Math.max(z + 3, 0), 6) / 6;

// slopes used by backpropagation
const dSigmoid = z => { const s = sigmoid(z); return s * (1 - s); };
const dTanh    = z => 1 - Math.tanh(z) ** 2;
const dRelu    = z => (z > 0 ? 1 : 0);
const dSilu    = z => { const s = sigmoid(z); return s * (1 + z * (1 - s)); };

function softmax(zs, T = 1) {
  const m = Math.max(...zs);            // subtract the max for stability
  const e = zs.map(z => Math.exp((z - m) / T));
  const s = e.reduce((a, b) => a + b, 0);
  return e.map(v => v / s);
}

// SwiGLU feed-forward block for one token vector x (matrices as arrays of rows)
const matvec = (M, x) => M.map(row => row.reduce((s, w, i) => s + w * x[i], 0));
function swiglu(x, W, V, W2) {
  const g = matvec(W, x).map(silu);      // gate
  const u = matvec(V, x);                // value
  return matvec(W2, g.map((gi, i) => gi * u[i]));
}

  
In PyTorch the same functions are nn.ReLU, nn.LeakyReLU, nn.PReLU, nn.ReLU6, nn.ELU, nn.SELU, nn.GELU(approximate='tanh'), nn.SiLU, nn.Mish, nn.Hardswish, nn.Hardsigmoid, nn.Softplus and nn.Softsign, with functional forms in torch.nn.functional.






  
13. Common mistakes

  
    
    
  • Applying softmax in the model and then passing its output to CrossEntropyLoss, which applies log-softmax again. Pass raw logits.
    • 
    
  • Using softmax for multi-label problems, where several classes can be true at once. Use one sigmoid per class.
    • 
    
  • Putting ReLU on the output of a regression model, so it can never predict a negative value.
    • 
    
  • Sigmoid or tanh in every hidden layer of a deep network without residual connections or normalization.
    • 
    
  • Mixing activation and initialization: Xavier with ReLU halves the variance at each layer; SELU without LeCun initialization loses self-normalization.
    • 
    
  • Using a large learning rate with ReLU and finding that much of the network has died. Check the fraction of units that are never active.
    • 
    
  • Forgetting the max-subtraction in a hand-written softmax and getting NaN for large logits.
    •
