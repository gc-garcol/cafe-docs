Merkle Tree

Hash every item, then hash the hashes in pairs until one value is left. That single root fingerprints the whole set, and any one item can be proved with only log n hashes.

1. The idea

  
Hashing a big set in one go gives you a fingerprint, but proving that one item belongs to the set means sending the whole set. A Merkle tree fixes that by hashing in a tree shape.

  
Leaves are the hashes of the items. Each inner node is the hash of its two children put side by side. The top node is the Merkle root.

  
leaf[i]   = H( item[i] )
parent    = H( left || right )
root      = the one node left at the top

  
Change one item and every hash on its path to the root changes. Nothing else does.






  
2. Build: pair up, hash, repeat

  
Hash each item, then hash neighbours in pairs. Each round halves the count. When a level has an odd number of nodes, a common choice is to pair the last node with a copy of itself. Another is to promote it unchanged.

  
function build(items) {
  let level = items.map(H);
  const levels = [level];
  while (level.length > 1) {
    const next = [];
    for (let i = 0; i < level.length; i += 2) {
      const right = level[i + 1] ?? level[i];   // duplicate the odd one out
      next.push(H(level[i] + right));
    }
    levels.push(level = next);
  }
  return levels;                                  // last level holds the root
}

  
Building touches every node once, so it costs O(n) hashes. The tree holds about 2n nodes.






  
3. Prove: send only the siblings

  
To prove that item i is in the set, send the item plus one sibling hash per level. The verifier hashes the item, then folds in each sibling, putting it on the left or the right depending on the bit of i at that level. If the result equals the trusted root, the item is in the set.

  
function verify(item, index, proof, root) {
  let h = H(item);
  for (const sib of proof) {
    h = (index & 1) === 0 ? H(h + sib) : H(sib + h);
    index >>= 1;
  }
  return h === root;
}

  
For eight items the proof has three hashes. For a million items it has about twenty. Try Fig 1 with Tamper on: the proof was made for the original set, so the rebuilt root no longer matches.

5. Where it shows up

  
    
    
  • Git and other content-addressed stores link objects by hash, which forms a Merkle DAG.
    • 
    
  • Blockchains put a Merkle root of the transactions in each block header, so light clients can check one transaction without the whole block.
    • 
    
  • Distributed databases such as Cassandra and Dynamo-style stores compare Merkle trees between replicas to find which key ranges differ.
    • 
    
  • Certificate Transparency logs use Merkle trees so anyone can verify that a certificate is in the log and that the log is append-only.
    • 
  

  
Security note: if leaf and inner hashes use the same input format, an attacker can pass an inner node off as a leaf. Prefix leaves and inner nodes with different tags, for example 0x00 and 0x01.
