Red-Black Tree

A binary search tree that paints every node red or black. A few color rules keep the longest path at most twice the shortest, so lookups stay O(log n) while updates need very little restructuring.

Try the machine first

This tree holds up to 15 numbers. Insert a value and read the log: the new node always starts red, then the tree fixes any broken rule by recoloring or rotating. Try inserting 10, 20, 30 in a row, then 5 and 1.

1. The rules

  
A red-black tree is a BST where each node carries one extra bit, its color. Five rules must hold at all times:

  
    
    
  • Every node is red or black.
    • 
    
  • The root is black.
    • 
    
  • Missing children (nulls) count as black.
    • 
    
  • A red node never has a red child.
    • 
    
  • Every path from a node down to its null descendants has the same number of black nodes, called the black height.
    • 
  

  
Black nodes form a perfectly balanced skeleton. Red nodes are slack that lets the tree absorb an insert without moving much.

  
Why does that bound the height? The shortest possible path is all black. The longest alternates red and black, so it is at most twice as long. That gives a height of at most 2 log₂(n + 1).






  
2. Insert and fix up

  
Insert like a normal BST and color the new node red. A red node cannot change any black height, so only one rule can break: a red node may now have a red parent. Walk up and repair it. Let z be the red node, P its red parent, G its grandparent (it exists, because a red node is never the root), and U its uncle.

  

    
UncleShapeFix

    
      
RedAnyRecolor P and U black, G red. Continue from G.

      
BlackZig-zag (z is an inner child)Rotate at P to make it a straight line, then use the next row.

      
BlackStraight line (z is an outer child)Rotate at G, color P black and G red. Done.

    
  

  
function fixInsert(z) {
  while (z.parent && z.parent.red) {
    const p = z.parent, g = p.parent;
    const left = (p === g.left);
    const u = left ? g.right : g.left;

    if (u && u.red) {            // case 1: push the problem up
      p.red = u.red = false;
      g.red = true;
      z = g;
    } else {                     // cases 2 and 3: rotate and stop
      if (z === (left ? p.right : p.left)) {
        z = p;
        left ? rotateLeft(z) : rotateRight(z);
      }
      z.parent.red = false;
      z.parent.parent.red = true;
      left ? rotateRight(z.parent.parent) : rotateLeft(z.parent.parent);
      break;
    }
  }
  root.red = false;
}

  
Recoloring can repeat up the tree, at most O(log n) times, but rotations happen at most twice per insert. That is the main practical win over AVL: fewer pointer changes per update.






  
3. Delete in one paragraph

  
Delete starts like a BST delete: a node with two children is replaced by its in-order successor, so you always remove a node with at most one child. Removing a red node breaks nothing. Removing a black node leaves one path with a missing black, called a "double black". The fix looks at the sibling and its children: recolor if the sibling is black with black children, rotate if one of its children is red, and rotate to turn a red sibling into a black one. It takes at most three rotations and O(log n) recolorings. The demo above skips delete because the case analysis is long, but the idea is the same as insert: local rotations and recoloring that preserve the five rules.

5. Where it shows up

  
    
    
  • Standard library maps and sets: C++ std::map and std::set, and Java TreeMap and TreeSet.
    • 
    
  • Operating systems: the Linux kernel uses red-black trees for the process scheduler and memory areas.
    • 
    
  • Interval and order-statistic trees: extra data is stored in each node on top of the same balancing.
    • 
  

  
Compared with an AVL tree, a red-black tree has slightly taller shapes and slightly slower lookups, but cheaper updates. If you want a simpler idea, a skip list gives similar ordered operations with random levels instead of rotations.
