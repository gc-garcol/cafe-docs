Data structures · Prefix trees

Trie

A tree where each edge is one character and each path from the root spells a prefix. Words that share a start share nodes, so lookup and prefix search cost O(L) in the length of the word, no matter how many words are stored.

Try the machine first

The trie below stores up to 12 lowercase words. Insert adds a word, Search checks for an exact word, and Starts with walks down a prefix and lists every word beneath it. Nodes with a double ring mark the end of a stored word.

1. The idea

  
A hash set answers "is this exact word here?" but knows nothing about prefixes. A sorted array can find prefixes with binary search, but inserting is slow. A trie (say "try", from retrieval) stores the shared start of words only once and makes prefixes a first-class idea.

  
Each node has up to 26 children, one per letter, and a flag that says whether a stored word ends there. The root stands for the empty string.

  
class Node {
  children = new Map();   // letter -> Node
  end = false;           // does a word finish here?
}

  
The path is the key. Nothing stores the whole word, because walking from the root spells it.






  
2. Insert and search

  
Insert walks down one letter at a time, creating a node whenever the letter is missing, and sets the end flag on the last node. Search walks the same way. If a letter is missing, the word is absent. If the walk finishes, the word exists only when the end flag is set.

  
function insert(root, word) {
  let n = root;
  for (const ch of word) {
    if (!n.children.has(ch)) n.children.set(ch, new Node());
    n = n.children.get(ch);
  }
  n.end = true;
}

function find(root, s) {            // returns the node for prefix s, or null
  let n = root;
  for (const ch of s) {
    n = n.children.get(ch);
    if (!n) return null;
  }
  return n;
}

const contains   = (r, w) => find(r, w)?.end === true;
const startsWith = (r, p) => find(r, p) !== null;

  
Try searching for ca in the demo. The path exists, but the node has no end flag, so it is a prefix and not a stored word.






  
3. Prefix search and autocomplete

  
To list every word that starts with ca, walk down to the node for ca, then run a depth-first search from there. Visiting children in alphabetical order returns the words already sorted.

  
function complete(root, prefix) {
  const out = [], start = find(root, prefix);
  if (!start) return out;
  (function dfs(n, s) {
    if (n.end) out.push(s);
    for (const ch of [...n.children.keys()].sort()) dfs(n.children.get(ch), s + ch);
  })(start, prefix);
  return out;
}

  
The cost is O(L) to reach the prefix, plus the size of the part of the trie under it. That is why tries power autocomplete: the work depends on the answer, not on the dictionary.






  
4. Cost and trade-offs

  

    
Insert
O(L)
One step per letter.

    
Search
O(L)
Independent of word count.

    
Prefix
O(L + k)
k is the size of the result.

The weak spot is memory. An array of 26 pointers per node wastes space when nodes have few children. Store children in a hash map or a sorted list instead, or compress chains with a radix tree, where a run of single-child nodes becomes one edge labeled with a whole string.
