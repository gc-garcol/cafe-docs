Bayes' Theorem

How to update a belief when new evidence arrives. Start from how common something is, weigh it against how well the evidence points to it, and get the probability you should believe now.

1. The idea

  
You start with a belief, the prior. You see some evidence. The evidence is more likely if your belief is true than if it is false, so you raise the belief. The new belief is the posterior. How far it moves depends on two things: how strong the evidence is, and how likely the belief was to begin with.

  
The second part is the one people forget. A strong test for a very rare thing still gives mostly false alarms, because there are so many more healthy people to be wrong about.

  
New belief = old belief, scaled by how well the evidence fits.






  
2. The formula

  
Let $H$ be the hypothesis and $E$ the evidence. The chance of both happening can be written two ways:

  
$$P(H \cap E) = P(E \mid H)\,P(H) = P(H \mid E)\,P(E)$$

  
Divide both sides by $P(E)$ and you get Bayes' theorem:

  
$$P(H \mid E) = \frac{P(E \mid H)\,P(H)}{P(E)}$$

  
The bottom part, $P(E)$, is all the ways the evidence can show up. Split it into two cases, with the hypothesis true and false:

  
$$P(E) = P(E \mid H)\,P(H) + P(E \mid \neg H)\,P(\neg H)$$

  

    
TermNameMeaning

    
      
$P(H)$PriorBelief before the evidence

      
$P(E \mid H)$LikelihoodChance of the evidence if $H$ is true

      
$P(E)$EvidenceChance of the evidence overall

      
$P(H \mid E)$PosteriorBelief after the evidence

    
  






  
3. Count people instead

  
The formula is easier to trust when you count. Take the default sliders: 1% of people have the condition, the test catches 90% of them, and it falsely flags 9% of the rest. Out of 1000 people:

  
    
    
  • 10 have it, and 9 of them test positive.
    • 
    
  • 990 do not, and about 89 of them test positive anyway.
    • 
    
  • So 98 people test positive, and only 9 of them have it.
    • 
  

  
A positive result means about $9 / 98 \approx 9\%$, not 90%. That is the same number the formula gives. Counting is just Bayes' theorem with the fractions multiplied out.






  
4. Base rate neglect

  
People often answer with the hit rate, 90%, because it is the number the test advertises. That swaps $P(E \mid H)$ for $P(H \mid E)$. They are different questions: "how many sick people test positive" and "how many positive people are sick". Drag the base rate slider up to 30% and watch the answer climb. The test did not change. Only the population did.






  
5. Updating again and again

  
Today's posterior is tomorrow's prior. In odds form, each piece of evidence just multiplies the odds by a fixed number, the likelihood ratio:

  
$$\underbrace{\frac{P(H \mid E)}{P(\neg H \mid E)}}_{\text{posterior odds}} = \underbrace{\frac{P(H)}{P(\neg H)}}_{\text{prior odds}} \times \underbrace{\frac{P(E \mid H)}{P(E \mid \neg H)}}_{\text{likelihood ratio}}$$

  
With the defaults the ratio is $0.90 / 0.09 = 10$. Prior odds of about $1 : 99$ become about $10 : 99$ after one positive test, which is roughly 9%. A second independent positive test multiplies by 10 again, giving about $100 : 99$, or roughly 50%.






  
6. The same thing in code

  
function posterior(prior, hit, falseAlarm) {
  const pEvidence = hit * prior + falseAlarm * (1 - prior);
  return (hit * prior) / pEvidence;
}

posterior(0.01, 0.90, 0.09);   // 0.092  (about 9%)
posterior(0.092, 0.90, 0.09);  // 0.503  (a second positive test)






  
7. Where it shows up

  
    
    
  • Spam filters: how likely is a message to be spam, given that it contains a certain word?
    • 
    
  • Medicine: reading screening tests and weighing a result against how common the disease is.
    • 
    
  • Machine learning: naive Bayes classifiers, Bayesian optimization, and Bayesian inference over model weights.
    • 
    
  • Search and robotics: Kalman and particle filters keep updating where an object is, as sensor readings come in.
    • 
    
  • Probabilistic data structures: a Bloom Filter says "maybe present", and Bayes' theorem tells you how much to trust that answer.
    • 
  

  
The result is only as good as the inputs. A wrong base rate or independence that does not hold will give a confident, wrong answer.
