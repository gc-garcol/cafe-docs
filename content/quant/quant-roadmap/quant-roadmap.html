Quant Roadmap

A study path into quantitative finance that mixes math, programming, markets and machine learning. Seven phases, each with what to learn, the docs in this site that cover it, and one project that proves you learned it.

#quant#roadmap#finance#machine learning

Before you start: pick a target

"Quant" is not one job. The three common roles share the same base, then split. Choose a lean early, but keep phases 0 to 3 common to all of them.

Quant researcher

Finds signals and builds models. Heavy on statistics, machine learning and careful testing.

Quant trader

Makes pricing and risk decisions live. Heavy on probability, fast mental math and market intuition.

Quant developer

Builds the pricing, data and execution systems. Heavy on software engineering and performance.

Math gives you the language, code gives you the proof, markets tell you what is true.

The path

Blue topics with a link are docs on this site. The rest are outside topics to study from books or courses. Use the filter to see one track at a time.

  1. 0
    Months 0 to 3

    Calculus and linear algebra

    Everything later is built on these two. You should be able to differentiate, integrate, expand a function in a series, and work with matrices and eigenvalues without a lookup.

    Limits Derivatives Integrals Taylor Series Matrices Determinants Vector Spaces Eigenvalues and Eigenvectors Matrix Diagonalization Python, NumPy, pandas SQL basics

    ProjectFit a straight line to price data using only NumPy and the normal equations, then check it against a library.

  2. 1
    Months 3 to 6

    Probability and statistics

    The core of the job. Expectation, variance, conditional probability, the main distributions, the law of large numbers and the central limit theorem, then estimation and hypothesis tests.

    Binomial Theorem Bayes' Theorem Gaussian Distribution Expectation, variance, covariance LLN and CLT Maximum likelihood Hypothesis tests, p-values Linear Regression

    ProjectSimulate a million coin-flip strategies and show how many look "profitable" by pure luck. This is the multiple testing problem in its simplest form.

  3. 2
    Months 6 to 9

    Markets and derivatives pricing

    Learn what is traded and how it is priced. Start with returns, bonds, futures and options, then move to the model that ties them together. Stochastic calculus is the hardest step here, so go slowly.

    Returns, compounding, time value Futures, forwards, options payoffs No-arbitrage and put-call parity Random walks, Brownian motion Itô's lemma Black-Scholes and the Greeks Binomial trees Monte Carlo pricing Fourier Transform

    The standard model for a stock price $S$ is geometric Brownian motion, with drift $\mu$, volatility $\sigma$ and a Wiener process $W$:

    $$dS_t=\mu S_t\,dt+\sigma S_t\,dW_t$$

    ProjectPrice a European call three ways: the closed form, a binomial tree and Monte Carlo. Make all three agree, then plot how fast each converges.

  4. 3
    Months 9 to 12

    Time series, portfolios and backtesting

    Real prices are noisy, dependent and non-stationary. This phase is about measuring that honestly, building portfolios from several assets, and testing a strategy without fooling yourself.

    Stationarity, autocorrelation ARMA and GARCH Mean-variance portfolios CAPM and factor models Principal Component Analysis Risk: VaR, drawdown Backtesting without look-ahead Transaction costs and slippage

    The usual yardstick for a strategy is the Sharpe ratio, the mean excess return over its standard deviation:

    $$\text{Sharpe}=\frac{\mathbb{E}[R-R_f]}{\sigma(R-R_f)}$$

    ProjectBuild a simple momentum or mean-reversion backtest on daily data. Add costs, split the data into in-sample and out-of-sample, and report what survives.

  5. 4
    Months 12 to 15

    Machine learning for markets

    Financial data has a very low signal-to-noise ratio, so the main skill is not picking a fancy model but controlling overfitting. Learn the standard models, then learn how to validate them on time-ordered data.

    ML Algorithm Groups Ridge and Lasso Regression Logistic Regression Decision Tree Random Forest Gradient Descent Optimizers Overfitting and Regularization Gradient boosting Walk-forward and purged cross-validation Feature engineering, leakage

    ProjectPredict next-day direction with regularized regression and a tree model. Use walk-forward validation. Expect weak results, and write down why a small edge is still hard to keep.

  6. 5
    Months 15 to 18

    Deep learning and reinforcement learning

    Optional for some roles, central for others. Neural nets help with rich inputs such as order books and text. Reinforcement learning fits problems where actions change the next state, such as execution and market making.

    Deep Learning Overview Backpropagation Activation Functions Convolution and CNNs Autoencoder Q-learning and Dyna-Q Policy Gradients Sequence models, transformers

    ProjectTrain a small agent to execute a large order over a day in a simulated market, and compare it with a plain time-sliced schedule.

  7. 6
    In parallel, all along

    Engineering and interview skills

    Run this track next to the others, not after them. Trading systems care about correctness and latency, and interviews test fast probability and clean code under pressure.

    C++ or Rust for speed Python for research Data structures and algorithms Heap Skip List Timer Wheel Aeron Transport Probability puzzles Mental arithmetic and estimation

    ProjectWrite a limit order book that matches buy and sell orders by price and time. Use heaps or ordered maps, add tests, and measure its throughput.

How to use this path

  • Do the project before moving on. Reading a chapter is not the same as being able to use it. Each project is small on purpose.
  • Keep a notebook of mistakes. Most quant skill is knowing the ways a result can be wrong: look-ahead bias, survivorship bias, overfitting, costs you forgot.
  • Be sceptical of your own edge. If a backtest looks great, assume a bug first. Test on data you never touched while building it.
  • Revisit math often. Phases 2 to 4 reuse phases 0 and 1 constantly. A second pass is faster and teaches more.
