Backtesting Without Look-Ahead

A backtest replays a strategy on history to estimate how it would have done. It is easy to write one that cheats without meaning to: by using information that was not available at the time, or by trying many versions and keeping the luckiest.

  2. Turn on Look-ahead. The signal now uses today's close to decide today's position. The orange curve shoots up with a Sharpe far above anything real.
  3. Turn it off and press Tune window in-sample. The best of 40 windows is picked on the first 70% of the data. It looks good there, and then fails on the last 30%.
  4. Press New prices a few times. The tuned window changes every time, which is a sign it was noise.

1. Look-ahead bias

A signal computed from data up to day $t$ can only trade from day $t+1$. The honest P&L lags the position by one bar:

$$\text{PnL}_t = \text{pos}_{t-1}\cdot r_t, \qquad \text{pos}_{t-1} = f(P_0, \dots, P_{t-1})$$

Forgetting the lag lets the position see the return it is paid on. Other forms are subtler: using a closing price for a decision made before the close, financial statements dated by period end instead of release date, index members chosen with today's list, or normalizing with statistics of the whole sample.

signal = np.sign(price - price.rolling(n).mean())
pos = signal.shift(1)                       # trade on the next bar, never the same one
pnl = pos * price.pct_change()
# bug: pnl = signal * price.pct_change()   uses today's close to earn today's return

2. Overfitting the parameters

Trying many windows and keeping the best is a multiple-testing problem. The maximum of $m$ noisy Sharpe ratios is biased upward, roughly by

$$\mathbb E\big[\max_{i\le m}\widehat{\text{SR}}_i\big] \approx \sqrt{\frac{2\ln m}{\text{years}}}$$

for strategies with zero true Sharpe. With 40 windows and 7 years of data that is about 1.0, a number many people would trade. The fix is to keep some data untouched: decide everything on the in-sample part, then evaluate exactly once on the out-of-sample part. Walk-forward testing repeats this through time.

3. A checklist

  • Every input is stamped with the time it became known, not the time it describes.
  • Positions are lagged by at least one bar, and fills use prices you could have traded at.
  • The universe includes delisted and bankrupt assets, to avoid survivorship bias.
  • Costs, slippage, borrow fees and funding are included.
  • The number of variants tried is recorded, and the Sharpe ratio is deflated for it.
  • A final out-of-sample period is touched only once.

Pitfalls

  • If a backtest looks great, assume a bug first. Real daily strategies with a Sharpe above 3 after costs are rare.
  • Re-running the out-of-sample test after each tweak turns it into in-sample data.
  • Rolling indicators need warm-up. Do not trade before the window is full.
  • Vectorized code makes look-ahead easy to write. An event-driven loop that only sees past bars is slower but safer.
