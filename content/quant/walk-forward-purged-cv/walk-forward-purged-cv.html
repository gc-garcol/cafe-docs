Walk-forward and purged cross-validation

Ordinary cross-validation assumes every row is independent. Market data is not: neighboring rows share information, and labels built from future returns overlap. Split by time, purge the overlap, and the scores you report start meaning something.

1. Why ordinary cross-validation fails here

  
K-fold cross-validation shuffles rows into $K$ groups, trains on $K-1$ of them and scores the last. That is fair only if rows are independent draws. Market data breaks this in two ways at once.

  
    
    
  • Features have memory. A 20-day volatility or a moving average changes slowly. Monday's and Tuesday's rows look almost the same, so a model that has seen Monday in training "recognizes" Tuesday in test.
    • 
    
  • Labels overlap. A typical target is the forward return over $h$ days. The labels of two rows $i$ and $j$ use some of the same daily returns whenever $|i-j| \le h$:
    • 
  

  
$$y_t = \ln\frac{P_{t+h}}{P_t} = \sum_{s=1}^{h} r_{t+s} \qquad\Rightarrow\qquad \operatorname{Corr}(y_i, y_j) = \max\!\left(0,\ 1 - \frac{|i-j|}{h}\right) \text{ for i.i.d. } r$$

  
Put both together and a shuffled split hands the model test answers in disguise. Its training set contains near-copies of every test row, with labels that share most of the same future. The score is high, and it says nothing about how the model will do on next month's data.

  
The question a validation scheme must answer is "how would this have done if I had trained it then and used it after?" Shuffling asks a different question.






  
2. Walk-forward validation

  
The simplest honest scheme copies deployment. Cut the timeline into blocks. Train on everything before a block, test on the block, then move forward one block and repeat. Every prediction is made by a model that only saw the past.

  

    

      
Expanding window

      
Train on all history up to the test block. More data each fold, so later folds are more stable. Old regimes keep their weight.

    

    

      
Rolling window

      
Train on a fixed number of recent blocks. Adapts faster to changing markets, at the cost of fewer samples and noisier fits.

    

  

  
function walkForward(n, folds, h, rolling = null) {
  const size = Math.floor(n / (folds + 1)), splits = [];
  for (let f = 1; f <= folds; f++) {
    const testStart = f * size, testEnd = Math.min(n, testStart + size);
    const trainEnd = testStart - h;                  // purge: last label must end before the test
    const trainStart = rolling ? Math.max(0, trainEnd - rolling) : 0;
    splits.push({ train: range(trainStart, trainEnd), test: range(testStart, testEnd) });
  }
  return splits;
}

  
Note the gap of $h$ rows before each test block. The last training row's label reaches $h$ steps ahead, straight into the test period, so even walk-forward needs purging. Walk-forward has two weaknesses: early folds train on little data, and it produces a single path through history, so one lucky or unlucky stretch can dominate the result.






  
3. Purging and embargo

  
Blocked K-fold keeps each fold contiguous in time, but uses data from both sides of the test block. That gives every fold the same amount of training data and uses all of history, which walk-forward cannot. It needs two repairs.

  
Purging removes every training row whose label interval overlaps a test label interval. With row $i$'s label covering $[t_i, t_i + h]$, training row $j$ is dropped when

  
$$[t_j,\ t_j + h] \;\cap\; \bigcup_{i \in \text{test}} [t_i,\ t_i + h] \;\ne\; \varnothing \quad\Longleftrightarrow\quad \min_{i \in \text{test}} |t_i - t_j| \le h$$

  
Embargo drops a few more rows right after each test block. Features with memory, such as a 50-day average, carry information from the test period into the rows just after it, even when the labels no longer overlap. A common choice is about 1% of the sample, or at least the longest feature lookback.

  
function purgedKFold(n, folds, h, embargo) {
  const size = Math.ceil(n / folds), splits = [];
  for (let f = 0; f < folds; f++) {
    const a = f * size, b = Math.min(n, a + size);    // test rows [a, b)
    const train = [];
    for (let j = 0; j < n; j++) {
      if (j >= a - h && j < b + h) continue;         // purge both sides
      if (j >= b + h && j < b + h + embargo) continue; // embargo after the test
      train.push(j);
    }
    splits.push({ train, test: range(a, b) });
  }
  return splits;
}

  
Rows after the test block are purged too: their features may be fine, but the test labels near the end of the block reach into them. In Fig 1, select K-fold, blocked to see the purple leaky rows on both edges of each test block, then Purged K-fold + embargo to see them removed.






  
4. Leakage lab

  
This lab builds data with no signal at all unless you add some. Daily returns are pure noise, the label is the sum of the next $h$ returns, and the features are three slowly drifting AR(1) series that have nothing to do with them:

  
$$x^{(m)}_t = \phi\, x^{(m)}_{t-1} + \sqrt{1-\phi^2}\,\varepsilon^{(m)}_t \ \ (m = 1, 2, 3), \qquad y_t = \sum_{s=1}^{h} r_{t+s} + \beta\sqrt{h}\, x^{(1)}_t$$

  
A $k$-nearest-neighbor model predicts each test label from the training rows with the closest feature vectors. Each dot is one of 16 random data sets of 500 days. The score is the information coefficient (IC), the correlation between predictions and realized labels. With $\beta = 0$ the honest answer is zero.

Things to try. With the defaults, shuffled K-fold reports a large positive IC on pure noise. Blocked K-fold leaks much less, only through the edges of each test block. Purged K-fold and walk-forward sit around zero, where they belong. Small negative values are normal noise for a model with nothing to learn. Set $\phi$ to 0 and the leak disappears even for shuffled folds: neighbors in feature space are no longer neighbors in time. Then add a true signal $\beta$: the honest schemes find part of it, and the shuffled one still overstates it.






  
5. Combinatorial purged cross-validation

  
Walk-forward gives one path through history, and a single path is a single sample of a very noisy quantity. Combinatorial purged cross-validation (CPCV), from Marcos López de Prado, gets many. Cut the data into $N$ groups. Every choice of $k$ groups is a test set, with the rest purged, embargoed and used for training. That gives

  
$$\text{splits} = \binom{N}{k}, \qquad \text{backtest paths} = \frac{k}{N}\binom{N}{k} = \binom{N-1}{k-1}$$

  
Each group appears in the test set of $\binom{N-1}{k-1}$ splits, so the out-of-sample predictions can be stitched into that many complete paths through history. With $N = 6$ and $k = 2$ there are 15 splits and 5 paths. Instead of one Sharpe ratio you get a distribution of them, and a strategy whose median path loses money is easy to spot. Select Combinatorial purged in Fig 1 to see all splits for $k = 2$.

  
The cost is compute: every split is a full model fit, and $\binom{N}{k}$ grows fast. Some paths also train on data from after their test period, which is fine for estimating skill but does not mimic deployment the way walk-forward does.






  
6. Tuning without fooling yourself

  
Validation protects one model. Trying many models on the same validation data quietly undoes it, because you end up reporting the luckiest one. Two habits help.

  
    
    
  • Nest the search. Inside each training window, run a second walk-forward to choose hyperparameters. Only the outer test blocks are scored. Keep a final hold-out period that nobody looks at until the end.
    • 
    
  • Count your trials. If you try $N$ independent strategies with true Sharpe ratio zero, the best one still looks good. Its expected Sharpe ratio grows like $\sqrt{2\ln N}$ times the standard error. Bailey and López de Prado's deflated Sharpe ratio compares the observed Sharpe ratio with this expected maximum:
    • 
  

  
$$\mathbb{E}\Bigl[\max_{n \le N} \widehat{SR}_n\Bigr] \approx \sigma_{SR}\left[(1-\gamma)\,\Phi^{-1}\!\Bigl(1 - \frac1N\Bigr) + \gamma\,\Phi^{-1}\!\Bigl(1 - \frac{1}{N e}\Bigr)\right]$$

  
Here $\gamma \approx 0.5772$ is the Euler–Mascheroni constant, $\Phi^{-1}$ the normal quantile, and $\sigma_{SR}$ the standard deviation of Sharpe ratio estimates across trials. With 100 trials the best of pure noise already sits about $2.5\,\sigma_{SR}$ above zero. See hypothesis tests for the multiple-testing view of the same problem.

8. Common mistakes

  
    
    
  • Fitting preprocessing on all data. Scalers, PCA, feature selection and target encoding must be fit inside each training window. A z-score that uses the full-sample mean already knows the future. See feature engineering and leakage.
    • 
    
  • Forgetting the label horizon in walk-forward. Training right up to the test start leaks the last $h$ labels.
    • 
    
  • Using index positions instead of timestamps. With irregular data or several assets per day, purge by the actual time each label starts and ends, not by row number.
    • 
    
  • Mixing assets across a split. If stock A on Monday is in training and stock B on Monday is in test, market-wide moves leak. Split by date for all assets together.
    • 
    
  • Reporting the average of folds without the spread. Five folds with ICs of 0.08, −0.02, 0.01, 0.06 and −0.04 are not "an IC of 0.02". Show every fold.
    • 
    
  • Rerunning until it works. Every look at the test period is a trial. Count them.
    • 
  






  
9. Where it shows up

  
    
    
  • Alpha research: scoring return forecasts, factor models and ML signals before any capital is risked. It pairs with backtesting without look-ahead.
    • 
    
  • Model tuning: choosing the depth and learning rate of gradient boosting, or the penalty of ridge and lasso.
    • 
    
  • Libraries: scikit-learn's TimeSeriesSplit is walk-forward with an optional gap. Purged K-fold and CPCV come from Advances in Financial Machine Learning and are implemented in several open-source packages.
    • 
    
  • Beyond finance: demand forecasting, energy load, medical records of the same patient over time, and any data where rows near each other are not independent.
