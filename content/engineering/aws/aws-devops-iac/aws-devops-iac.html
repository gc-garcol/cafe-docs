1. Terraform

  
Describe infrastructure in HCL files, and Terraform builds it through providers, such as the AWS provider. It keeps state, a record of what it manages. plan shows the difference between config, state and reality, and apply performs it. Reuse code with modules. Store state remotely, for example in S3 with locking, so a team shares it safely.


terraform init
terraform plan
terraform apply






  
2. CloudFormation

  
AWS's own IaC service. A JSON or YAML template describes resources, and a stack is a deployed instance of it. Change sets preview an update. If a stack update fails, it rolls back. Drift detection finds manual changes. StackSets deploy to many accounts and Regions. The CDK lets you write in a programming language and generates the template.







  
3. CodePipeline

  
A managed release pipeline made of stages. A typical flow is source (a Git repo), build and test with CodeBuild, then deploy with CodeDeploy, CloudFormation or ECS. Add a manual approval before production. Pipelines can run Terraform too. GitHub Actions and similar tools can play the same role.
