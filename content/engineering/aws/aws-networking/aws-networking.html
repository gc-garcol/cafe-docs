1. VPC

  
A Virtual Private Cloud is your isolated network in one Region. You pick its address range, such as 10.0.0.0/16. Security groups and network ACLs filter traffic. VPC endpoints reach AWS services such as S3 without the internet, and peering or Transit Gateway link VPCs.







  
2. Subnet

  
A subnet is a slice of the VPC address range inside one AZ. It is public when its route table sends 0.0.0.0/0 to an Internet Gateway, and private otherwise. Put load balancers in public subnets, and app servers and databases in private ones, in at least two zones.







  
3. Route Table

  
Rules that map destination ranges to targets. Every table has a local route for the VPC itself. Targets include an Internet Gateway, a NAT Gateway, a peering connection, a Transit Gateway and endpoints. The most specific matching route wins. Each subnet uses exactly one route table.







  
4. NAT

  
A NAT Gateway lets private instances start outbound connections, for updates or external APIs, while staying unreachable from the internet. It sits in a public subnet and is tied to one zone, so use one per zone for resilience. It bills per hour and per GB, so a VPC endpoint for S3 or DynamoDB can save money.







  
5. ALB

  
The Application Load Balancer works at layer 7. It routes HTTP and HTTPS by host name, path, header or query string to target groups of instances, IPs or Lambda functions. It terminates TLS, supports WebSockets and gRPC, and can authenticate users with OIDC.







  
6. NLB

  
The Network Load Balancer works at layer 4 for TCP, UDP and TLS. It handles millions of requests per second with very low latency, and gives a static IP per zone, including Elastic IPs. It keeps the client source address and is the base for PrivateLink services. Choose it for non-HTTP protocols or fixed-IP needs.
