AWS Messaging and Streaming

Decoupling parts of a system. Queues, topics, event routing and streams, and when to use each.

Queue versus fan-out

A queue gives each message to one consumer. A topic copies each message to every subscriber. Publish a message in each mode and watch where it lands.

1. SQS

  
A managed queue. Producers send, consumers pull. A standard queue has nearly unlimited throughput with at-least-once delivery and best-effort order. A FIFO queue keeps order within a message group and removes duplicates. A received message is hidden for the visibility timeout, and the consumer must delete it when done. Messages that keep failing move to a dead-letter queue. Use long polling to cut empty reads.







  
2. SNS

  
A pub/sub topic that pushes. Subscribers can be SQS queues, Lambda functions, HTTP endpoints, email and mobile push. The classic pattern is fan-out: one topic to many queues, so each service gets its own durable copy. Subscription filter policies let each subscriber receive only the messages it wants.







  
3. EventBridge

  
A serverless event bus. Events come from AWS services, your apps and SaaS partners. Rules match an event pattern on its JSON and route it to targets such as Lambda, Step Functions or another bus. It also runs schedules, keeps an archive you can replay, and has a schema registry. Choose it to react to things that happen, with loose coupling.







  
4. MSK

  
Managed Streaming for Apache Kafka runs Kafka brokers for you across zones, with Kafka's own APIs and tools. Pick it when you already use Kafka, need its ecosystem or very high throughput with long retention. MSK Serverless removes capacity planning.







  
5. Kinesis

  
Data Streams are ordered logs split into shards. Records with the same partition key go to the same shard in order, and many consumers can read the same data again for the retention period (24 hours up to 365 days). Firehose loads a stream into S3, Redshift or OpenSearch with no consumer code.
