Rust CLI Project: minigrep

This chapter ties the previous ones together in one program: minigrep, a stripped-down grep that prints the lines of a file that contain a query. The interesting part is not the search but the shape of the code: what goes in main, what goes in the library, and how errors travel.

1. Reading arguments and a file

$ cargo new minigrep && cd minigrep
$ cargo run -- needle haystack.txt     # arguments after -- go to the program
use std::env;
use std::fs;

fn main() {
    let args: Vec<String> = env::args().collect();
    let query = args.get(1).cloned().unwrap_or_else(|| "the".into());
    let path = args.get(2).cloned().unwrap_or_else(|| "/etc/hosts".into());

    println!("Searching for {query} in {path}");
    let contents = fs::read_to_string(&path).expect("should be able to read the file");
    println!("{} bytes", contents.len());
}

env::args() panics if an argument is not valid Unicode; env::args_os() returns OsString values instead. collect is one of the few functions that needs a type annotation, because it can build many kinds of collection. The first element is the program's name.

2. Refactoring for modularity

A main that parses, validates, reads and searches does too much and cannot be tested. The usual split for a binary project:

main.rslib.rs
Collect the argumentsParse and validate them into a Config
Call Config::build and runContain run and all the program logic
Handle the error: print it, set the exit codeReturn errors as Result

main becomes small enough to check by reading, and everything else can be tested from lib.rs.

A Config struct

Returning a tuple (query, path) loses the meaning of each value. A struct names them. The arguments are owned by args, so the struct either borrows them with a lifetime or clones them. Cloning two short strings once costs nothing measurable and keeps the code simple; chapter 13 removes the clone with an iterator.

Errors instead of panics

args[1] panics with "index out of bounds", a message about the program, not the user's mistake. A constructor named build (not new, which by convention never fails) returns a Result with a helpful message.

use std::error::Error;
use std::fs;

pub struct Config {
    pub query: String,
    pub file_path: String,
    pub ignore_case: bool,
}

impl Config {
    pub fn build(args: &[String]) -> Result<Config, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }
        let query = args[1].clone();
        let file_path = args[2].clone();
        let ignore_case = std::env::var("IGNORE_CASE").is_ok();
        Ok(Config { query, file_path, ignore_case })
    }
}

pub fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(config.file_path)?;
    let results = if config.ignore_case {
        search_case_insensitive(&config.query, &contents)
    } else {
        search(&config.query, &contents)
    };
    for line in results {
        println!("{line}");
    }
    Ok(())
}

pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let mut results = Vec::new();
    for line in contents.lines() {
        if line.contains(query) {
            results.push(line);
        }
    }
    results
}

pub fn search_case_insensitive<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let query = query.to_lowercase();
    let mut results = Vec::new();
    for line in contents.lines() {
        if line.to_lowercase().contains(&query) {
            results.push(line);
        }
    }
    results
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn case_sensitive() {
        let query = "duct";
        let contents = "Rust:\nsafe, fast, productive.\nPick three.\nDuct tape.";
        assert_eq!(vec!["safe, fast, productive."], search(query, contents));
    }

    #[test]
    fn case_insensitive() {
        let query = "rUsT";
        let contents = "Rust:\nsafe, fast, productive.\nPick three.\nTrust me.";
        assert_eq!(vec!["Rust:", "Trust me."], search_case_insensitive(query, contents));
    }

    #[test]
    fn build_needs_two_args() {
        let args = vec![String::from("minigrep")];
        assert!(Config::build(&args).is_err());
    }
}

Box<dyn Error> in run means "any error type", so ? can forward the io::Error from read_to_string and anything added later.

3. A thin main

// src/main.rs
use std::env;
use std::process;

use minigrep::Config;

fn main() {
    let args: Vec<String> = env::args().collect();

    let config = Config::build(&args).unwrap_or_else(|err| {
        eprintln!("Problem parsing arguments: {err}");
        process::exit(1);
    });

    if let Err(e) = minigrep::run(config) {
        eprintln!("Application error: {e}");
        process::exit(1);
    }
}

run returns () on success, so there is no value to unwrap: if let Err(e) handles only the failure. process::exit(1) ends the process immediately with a non-zero exit code, which shells and scripts use to detect failure.

4. Test-driven search

The search function above was written test first:

  • Write a test that fails, and run it to see it fail for the reason you expect.
  • Write or change just enough code to make it pass.
  • Refactor while keeping the tests green, then repeat.

The first version of search returned vec![]; the test failed, which proved the test was able to fail. Then the loop over contents.lines() with contains made it pass.

The lifetime 'a links the results to contents, not to query: the returned slices point into the file contents, so they must not outlive it. Without the annotation the compiler cannot tell which of the two parameters the slices come from.

5. Environment variables

Case-insensitive search is switched on by an environment variable, so users can set it once per shell session. env::var returns a Result; is_ok() means "set to anything".

$ cargo run -- to poem.txt
Are you nobody, too?
How dreary to be somebody!

$ IGNORE_CASE=1 cargo run -- to poem.txt
Are you nobody, too?
How dreary to be somebody!
To tell your name the livelong day
To an admiring bog!

# PowerShell
PS> $Env:IGNORE_CASE=1; cargo run -- to poem.txt

A common refinement: let a command-line flag override the environment variable, so the more explicit setting wins.

6. Errors go to stderr

println! writes to standard output; eprintln! writes to standard error. Redirecting output to a file should capture results, not error messages, or the user sees nothing and gets a file full of complaints.

$ cargo run > output.txt
Problem parsing arguments: not enough arguments     # still on the terminal

$ cargo run -- to poem.txt > output.txt             # results in the file

7. Check yourself

Read each snippet and decide whether the compiler accepts it. Every answer was checked with rustc (edition 2024).

Q1 Does this compile?
fn search<'a>(q: &str, text: &'a str) -> Vec<&'a str> {
    text.lines().filter(|l| l.contains(q)).collect()
}
fn main() {
    let r;
    {
        let text = String::from("a\nb");
        r = search("a", &text);
    }
    println!("{r:?}");
}

The results borrow from text, which is dropped at the end of the block, before r is printed.

Q2 Does this compile?
fn search<'a>(q: &str, text: &'a str) -> Vec<&'a str> {
    text.lines().filter(|l| l.contains(q)).collect()
}
fn main() {
    let text = String::from("a\nb");
    let r;
    {
        let q = String::from("a");
        r = search(&q, &text);
    }
    println!("{r:?}");
}

The results are tied only to text. The query may be dropped early.

Q3 Does this compile?
use std::env;
fn main() {
    let args = env::args().collect();
    println!("{}", args.len());
}
