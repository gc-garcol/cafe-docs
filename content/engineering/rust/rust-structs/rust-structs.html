Rust Structs

A struct groups related values under one name, with a named field for each. Add an impl block and the struct gets methods, so data and the operations on it live together. Structs and enums are how Rust programs model their domain.

1. Defining and instantiating

struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}

fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username,      // field init shorthand: same as username: username
        email,
        sign_in_count: 1,
    }
}

fn main() {
    let mut user1 = build_user(String::from("a@example.com"), String::from("ana"));
    user1.email = String::from("ana@example.com"); // whole instance must be mut
    println!("{} {}", user1.username, user1.email);
}

Fields are accessed with dot notation. Mutability belongs to the binding, not to fields: either the whole instance is mut or none of it is. Fields are private outside the module unless marked pub (chapter 7).

Struct update syntax

..other fills the remaining fields from another instance. It works like assignment, so non-Copy fields are moved out of other.

does not compile
struct User { active: bool, username: String, email: String, sign_in_count: u64 }

fn main() {
    let user1 = User { active: true, username: "ana".into(), email: "a@x.com".into(), sign_in_count: 1 };
    let user2 = User { email: String::from("b@x.com"), ..user1 };
    println!("{}", user1.username); // error[E0382]: username was moved into user2
}

Had user2 also set its own username, only Copy fields (active, sign_in_count) would have been taken from user1, and user1 would still be fully usable.

2. Tuple structs and unit-like structs

A tuple struct has a name but unnamed fields. It is the newtype pattern: Meters(f64) and Seconds(f64) have the same layout but are different types, so the compiler stops you from mixing them up.

struct Color(u8, u8, u8);
struct Meters(f64);
struct AlwaysEqual; // unit-like: no fields, zero bytes

fn main() {
    let black = Color(0, 0, 0);
    let Color(r, g, b) = black;    // destructure
    let d = Meters(3.5);
    let _marker = AlwaysEqual;
    println!("{r} {g} {b} {} {}", black.0, d.0);
}

A unit-like struct carries no data. It is useful when you need a type to implement a trait on, or as a marker.

KindSyntaxUse for
Classic structstruct P { x: f64, y: f64 }Most data: fields have meaningful names.
Tuple structstruct P(f64, f64);Newtypes and small wrappers where names add nothing.
Unit-likestruct Marker;Trait implementations, type-level markers.

3. Ownership of struct data

User uses String, not &str, so every instance owns all of its data, and the data lives as long as the struct. A struct can hold references, but then it needs lifetime parameters, so the compiler can prove the struct does not outlive what it points to:

struct Excerpt<'a> {
    text: &'a str,
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first = novel.split('.').next().unwrap();
    let e = Excerpt { text: first };
    println!("{}", e.text);
}

Start with owned fields. Reach for references in structs once you know you need them; chapter 10 covers the syntax.

4. Printing with derive(Debug)

println!("{}") needs the Display trait, which structs do not implement automatically, because there is no single obvious way to show one. Debug is meant for developers and can be derived:

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let scale = 2;
    let rect = Rectangle { width: dbg!(30 * scale), height: 50 };
    println!("{rect:?}");   // Rectangle { width: 60, height: 50 }
    println!("{rect:#?}");  // pretty, one field per line
    dbg!(&rect);            // prints file:line and the value to stderr
}

dbg! takes ownership of its argument and returns it, which is why it can wrap an expression inline. Pass a reference when you want to keep the value. Other derivable traits include Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord and Default.

5. Methods

Methods are functions defined in an impl block whose first parameter is self. The three forms say how the method uses the instance:

ReceiverShort forMeaning
&selfself: &SelfRead the instance. The common case.
&mut selfself: &mut SelfChange the instance.
selfself: SelfConsume it, usually to turn it into something else.
#[derive(Debug)]
struct Rectangle { width: u32, height: u32 }

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
    fn scale(&mut self, k: u32) {
        self.width *= k;
        self.height *= k;
    }
    fn into_square(self) -> Rectangle {
        let side = self.width.max(self.height);
        Rectangle { width: side, height: side }
    }
}

fn main() {
    let mut r = Rectangle { width: 30, height: 50 };
    let small = Rectangle { width: 10, height: 40 };
    println!("area {} holds small: {}", r.area(), r.can_hold(&small));
    r.scale(2);
    let sq = r.into_square(); // r is moved here
    println!("{sq:?}");
}

Automatic referencing

There is no -> operator. When you call r.area(), Rust adds &, &mut or * so the receiver matches the signature. r.area() and Rectangle::area(&r) are the same call. This works because the receiver type is explicit in every method.

A method can share a name with a field: r.width reads the field, r.width() calls the method. That is how getters are usually written.

6. Associated functions

Functions in an impl block without self are associated functions. They are called with ::, and are typically constructors. new is a convention, not a keyword. Self is an alias for the type the block is for.

#[derive(Debug)]
struct Rectangle { width: u32, height: u32 }

impl Rectangle {
    fn new(width: u32, height: u32) -> Self {
        Self { width, height }
    }
    fn square(size: u32) -> Self {
        Self { width: size, height: size }
    }
}

impl Rectangle { // several impl blocks are allowed
    fn is_square(&self) -> bool { self.width == self.height }
}

fn main() {
    let a = Rectangle::new(3, 4);
    let b = Rectangle::square(5);
    println!("{a:?} {}", b.is_square());
}

Multiple impl blocks for one type are legal. They become useful with generics and traits, where a block can apply only to some type parameters.

7. Check yourself

Read each snippet and decide whether the compiler accepts it. Every answer was checked with rustc (edition 2024).

Q1 Does this compile?
struct P { x: i32, y: i32 }
fn main() {
    let p = P { x: 1, y: 2 };
    p.x = 5;
}

Mutability is per binding. p is not mut, so none of its fields can be assigned.

Q2 Does this compile?
struct P { x: i32 }
fn main() {
    let p = P { x: 1 };
    println!("{:?}", p);
}

P does not implement Debug. Add #[derive(Debug)].

Q3 Does this compile?
struct C { n: u32 }
impl C {
    fn bump(&mut self) { self.n += 1; }
}
fn main() {
    let mut c = C { n: 0 };
    c.bump();
    c.bump();
    println!("{}", c.n);
}

Calling c.bump() auto-borrows &mut c. Each borrow ends when the call returns.

Q4 Does this compile?
struct S { name: String }
impl S { fn into_name(self) -> String { self.name } }
fn main() {
    let s = S { name: "a".into() };
    let n = s.into_name();
    println!("{} {}", n, s.name);
}

into_name takes self by value, so s is moved and cannot be used after the call.
