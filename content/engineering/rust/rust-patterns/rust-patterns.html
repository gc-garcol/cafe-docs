Rust Patterns and Matching

A pattern describes the shape of a value and pulls parts out of it. Patterns are not limited to match: every let, every function parameter and every for loop uses one. Knowing the full syntax makes a lot of Rust code shorter and lets the compiler check more cases.

fn main() {
    let favorite_color: Option<&str> = None;
    let is_tuesday = false;
    let age: Result<u8, _> = "34".parse();

    if let Some(color) = favorite_color {
        println!("Using your favorite color, {color}, as the background");
    } else if is_tuesday {
        println!("Tuesday is green day!");
    } else if let Ok(age) = age {          // shadows age inside the branch
        if age > 30 { println!("Using purple as the background color"); }
        else { println!("Using orange as the background color"); }
    } else {
        println!("Using blue as the background color");
    }

    let mut stack = vec![1, 2, 3];
    while let Some(top) = stack.pop() {
        print!("{top} ");
    }
    println!();

    for (index, value) in ['a', 'b', 'c'].iter().enumerate() {
        println!("{value} is at index {index}");
    }

    let (x, y, _) = (1, 2, 3);
    print_coordinates(&(x, y));
}

Unlike match, an if let chain is not checked for exhaustiveness; forgetting the last else is not caught.

2. Refutability

An irrefutable pattern matches every possible value: x, (a, b). A refutable pattern can fail: Some(x) does not match None. let, for and parameters need irrefutable patterns, because there is no sensible thing to do on failure.

does not compile
fn main() {
    let some_option_value: Option<i32> = None;
    let Some(x) = some_option_value; // error[E0005]: refutable pattern in local binding
}

The fix is let ... else or if let. The opposite, an if let with an irrefutable pattern, compiles with a warning, because the if is pointless.

3. Literals, variables, | and ranges

fn main() {
    let x = 1;
    match x {
        1 | 2 => println!("one or two"),        // either
        3..=5 => println!("three through five"), // inclusive range
        _ => println!("anything"),
    }

    let c = 'c';
    match c {
        'a'..='j' => println!("early ASCII letter"),
        'k'..='z' => println!("late ASCII letter"),
        _ => println!("something else"),
    }

    // a named variable in a pattern is a NEW binding that shadows
    let x = Some(5);
    let y = 10;
    match x {
        Some(50) => println!("Got 50"),
        Some(y) => println!("Matched, y = {y}"),   // y = 5, not a comparison with 10
        _ => println!("Default case, x = {x:?}"),
    }
    println!("at the end: x = {x:?}, y = {y}");
}

The Some(y) arm is a classic surprise: it does not compare with the outer y, it introduces a new y for that arm. To compare with an outer variable, use a match guard (below). Ranges work with numbers and char, the types whose values the compiler can enumerate.

4. Destructuring

Structs

struct Point { x: i32, y: i32 }

fn main() {
    let p = Point { x: 0, y: 7 };
    let Point { x: a, y: b } = p;     // rename
    let Point { x, y } = p;           // shorthand: same names
    println!("{a} {b} {x} {y}");

    match p {
        Point { x, y: 0 } => println!("On the x axis at {x}"),   // literal in a field
        Point { x: 0, y } => println!("On the y axis at {y}"),
        Point { x, y } => println!("On neither axis: ({x}, {y})"),
    }
}

Enums, nested

enum Color { Rgb(i32, i32, i32), Hsv(i32, i32, i32) }

enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(Color),
}

fn main() {
    let msgs = [
        Message::ChangeColor(Color::Hsv(0, 160, 255)),
        Message::Move { x: 3, y: 4 },
        Message::Write("hi".into()),
        Message::Quit,
        Message::ChangeColor(Color::Rgb(1, 2, 3)),
    ];
    for msg in msgs {
        match msg {
            Message::Quit => println!("quit"),
            Message::Move { x, y } => println!("move to {x},{y}"),
            Message::Write(text) => println!("text: {text}"),
            Message::ChangeColor(Color::Rgb(r, g, b)) => println!("rgb {r} {g} {b}"),
            Message::ChangeColor(Color::Hsv(h, s, v)) => println!("hsv {h} {s} {v}"),
        }
    }
}

Mixed structs, tuples and references

struct Point { x: i32, y: i32 }

fn main() {
    let ((feet, inches), Point { x, y }) = ((3, 10), Point { x: 3, y: -10 });
    println!("{feet}'{inches}\" at ({x}, {y})");

    let points = vec![Point { x: 1, y: 2 }, Point { x: 3, y: 4 }];
    let sum: i32 = points.iter().map(|&Point { x, y }| x * x + y * y).sum();
    println!("{sum}");
}

When you match on a reference with a non-reference pattern, Rust automatically binds the fields by reference ("default binding modes"). match &opt { Some(s) => .. } gives s: &String, without moving out of opt.

5. Ignoring values: _ and ..

fn foo(_: i32, y: i32) { println!("only uses y: {y}"); } // ignored parameter

fn main() {
    foo(3, 4);

    let mut setting_value = Some(5);
    let new_setting_value = Some(10);
    match (setting_value, new_setting_value) {
        (Some(_), Some(_)) => println!("Can't overwrite an existing customized value"),
        _ => setting_value = new_setting_value,
    }
    println!("setting is {setting_value:?}");

    let numbers = (2, 4, 8, 16, 32);
    let (first, _, third, _, fifth) = numbers;
    let (head, .., tail) = numbers;               // .. skips the middle
    println!("{first} {third} {fifth} {head} {tail}");

    let _unused = 5;                              // no unused-variable warning
}

_x and _ differ. _x is still a binding, so it moves the value into it; _ binds nothing and leaves the value where it is.

does not compile
fn main() {
    let s = Some(String::from("Hello!"));
    if let Some(_s) = s {
        println!("found a string");
    }
    println!("{s:?}"); // error[E0382]: borrow of partially moved value: `s`
}
fn main() {
    let s = Some(String::from("Hello!"));
    if let Some(_) = s {             // _ does not bind: nothing moves
        println!("found a string");
    }
    println!("{s:?}");
}

.. must be unambiguous: (.., second, ..) is an error, since the compiler cannot know how many values each .. skips.

6. Match guards

A match guard is an if condition after a pattern. The arm runs only if the pattern matches and the condition is true. Guards can use any expression, including outer variables.

fn main() {
    let num = Some(4);
    match num {
        Some(x) if x % 2 == 0 => println!("The number {x} is even"),
        Some(x) => println!("The number {x} is odd"),
        None => (),
    }

    let x = Some(5);
    let y = 10;
    match x {
        Some(50) => println!("Got 50"),
        Some(n) if n == y => println!("Matched, n = {n}"),   // compares with outer y
        _ => println!("Default case, x = {x:?}"),
    }

    let z = 4;
    let flag = false;
    match z {
        4 | 5 | 6 if flag => println!("yes"),   // guard applies to the whole | pattern
        _ => println!("no"),
    }
}

The compiler does not consider guards when checking exhaustiveness: Some(x) if x % 2 == 0 plus Some(x) if x % 2 != 0 still needs a catch-all, because it cannot prove the two conditions cover everything.

7. @ bindings

name @ pattern tests a value against a pattern and also binds it. It is how you keep the value when the pattern is a range or alternation.

enum Message { Hello { id: i32 } }

fn main() {
    let msg = Message::Hello { id: 5 };
    match msg {
        Message::Hello { id: id @ 3..=7 } => println!("Found an id in range: {id}"),
        Message::Hello { id: 10..=12 } => println!("Found an id in another range"),
        Message::Hello { id } => println!("Found some other id: {id}"),
    }

    let v = [1, 2, 3, 4, 5];
    match v {
        [first, rest @ ..] => println!("{first} then {rest:?}"),    // slice patterns
    }
    if let [.., last] = v { println!("last = {last}"); }
}

8. Check yourself

Read each snippet and decide whether the compiler accepts it. Every answer was checked with rustc (edition 2024).

Q1 Does this compile?
fn main() {
    let opt: Option<u8> = Some(1);
    let Some(n) = opt;
}

Some(n) is refutable, but a plain let needs an irrefutable pattern. Use let Some(n) = opt else { .. };.

Q2 Does this compile?
fn main() {
    let t = (1, 2, 3, 4);
    let (a, .., d) = t;
    println!("{a} {d}");
}

One .. in a tuple pattern is unambiguous: it skips the middle elements.

Q3 Does this compile?
fn main() {
    let t = (1, 2, 3, 4);
    let (.., b, ..) = t;
}

Two .. make the position of b ambiguous, so it is an error.

Q4 Does this compile?
fn main() {
    let n = 7;
    let kind = match n {
        x if x < 0 => "negative",
        x if x >= 0 => "non-negative",
    };
}

Guards are ignored by the exhaustiveness check. Even though the two conditions cover all integers, a catch-all arm is required.

Q5 Does this compile?
fn main() {
    let v = vec![String::from("a")];
    match v.first() {
        Some(s) => println!("{s}"),
        None => {}
    }
    println!("{}", v.len());
}

first() returns Option<&String>, so s is a reference and nothing is moved out of v.
