Rust Enums and Pattern Matching

An enum says a value is exactly one of a fixed set of variants, and each variant can carry its own data. Combined with match, which forces you to handle every variant, enums let the compiler check that no case is forgotten. Option uses this to replace null.

1. Defining an enum

Each variant of an enum can hold different data: nothing, a tuple, or named fields. All variants are the same type, so one function can take any of them.

#[derive(Debug)]
enum IpAddr {
    V4(u8, u8, u8, u8),
    V6(String),
}

#[derive(Debug)]
enum Message {
    Quit,                       // no data
    Move { x: i32, y: i32 },    // named fields
    Write(String),              // one value
    ChangeColor(u8, u8, u8),    // several values
}

impl Message {
    fn call(&self) {
        println!("{self:?}");
    }
}

fn main() {
    let home = IpAddr::V4(127, 0, 0, 1);
    let lo = IpAddr::V6(String::from("::1"));
    println!("{home:?} {lo:?}");
    Message::Move { x: 1, y: 2 }.call();
    Message::Write("hi".into()).call();
}

With structs you would need four types and a shared trait to pass them around. The enum keeps them in one type, and its size is the size of the largest variant plus a tag. A variant name is also a constructor function: IpAddr::V6 has type fn(String) -> IpAddr.

2. Option instead of null

Rust has no null. A value that might be absent has type Option<T>, defined in the standard library as:

enum Option<T> {
    None,
    Some(T),
}
fn main() {}

Option, Some and None are in the prelude, so you use them without a path. The point is that Option<i32> and i32 are different types. You cannot add them, and you cannot forget to check:

does not compile
fn main() {
    let x: i8 = 5;
    let y: Option<i8> = Some(5);
    let sum = x + y; // error[E0277]: cannot add `Option<i8>` to `i8`
}

To get the i8 out you must handle None. Everywhere else, any value of type T is guaranteed to be there. Tony Hoare called null references his "billion-dollar mistake"; Option keeps the idea of absence but moves the check to compile time.

3. The match control flow construct

match compares a value against patterns in order and runs the first arm that fits. Each arm is pattern => expression. Fig 1 steps through one.

#[derive(Debug)]
enum UsState { Alaska, Alabama }

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter(UsState),
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => {
            println!("Lucky penny!");
            1
        }
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter(state) => {     // binds the inner value
            println!("State quarter from {state:?}!");
            25
        }
    }
}

fn main() {
    println!("{}", value_in_cents(Coin::Quarter(UsState::Alaska)));
    println!("{}", value_in_cents(Coin::Penny));
    let _ = (Coin::Nickel, Coin::Dime, UsState::Alabama);
}

Matching Option

fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        None => None,
        Some(i) => Some(i + 1),
    }
}

fn main() {
    let five = Some(5);
    println!("{:?} {:?}", plus_one(five), plus_one(None));
}

4. Matches are exhaustive

The compiler checks that the arms cover every possible value. Forget None and it tells you exactly which pattern is missing:

does not compile
fn plus_one(x: Option<i32>) -> Option<i32> {
    match x { // error[E0004]: non-exhaustive patterns: `None` not covered
        Some(i) => Some(i + 1),
    }
}

This is the strongest reason to prefer match over chains of if. When you add a variant to an enum later, every match that does not handle it stops compiling, and the errors are a to-do list.

Catch-all patterns and _

fn add_fancy_hat() {}
fn remove_fancy_hat() {}
fn move_player(n: u8) { println!("move {n}"); }

fn main() {
    let roll = 9;
    match roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        other => move_player(other), // binds the value
    }
    match roll {
        3 => add_fancy_hat(),
        _ => (),                     // ignore everything else
    }
}

A named catch-all binds the value; _ matches anything without binding it. Both must come last, because arms are tried in order and anything after them is unreachable (the compiler warns).

5. if let and let else

When you care about one pattern and want to ignore the rest, match is verbose. if let is shorthand for a match with one arm and _ => (), optionally with an else.

fn main() {
    let config_max = Some(3u8);
    if let Some(max) = config_max {
        println!("max is {max}");
    } else {
        println!("no max");
    }
}

You trade exhaustiveness checking for brevity, so use it when the other cases really do not matter.

let else

let PATTERN = EXPR else { ... }; binds the pattern in the surrounding scope or runs the else block, which must leave the scope (return, break, continue or panic). It keeps the happy path flat instead of nesting it inside if let.

fn parse_kv(line: &str) -> Option<(String, i32)> {
    let Some((k, v)) = line.split_once('=') else {
        return None;
    };
    let Ok(n) = v.trim().parse::<i32>() else {
        return None;
    };
    Some((k.trim().to_string(), n))
}

fn main() {
    println!("{:?}", parse_kv("port = 8080"));
    println!("{:?}", parse_kv("garbage"));
}

6. Check yourself

Read each snippet and decide whether the compiler accepts it. Every answer was checked with rustc (edition 2024).

Q1 Does this compile?
enum Dir { N, S, E, W }
fn turn(d: Dir) -> Dir {
    match d {
        Dir::N => Dir::E,
        Dir::E => Dir::S,
        Dir::S => Dir::W,
    }
}
fn main() {}

The match is not exhaustive: Dir::W is not covered.

Q2 Does this compile?
fn main() {
    let x: Option<u32> = Some(2);
    let y = x.unwrap_or(0) + 1;
    println!("{y}");
}

unwrap_or turns the Option<u32> into a u32, so the addition is fine.

Q3 Does this compile?
fn main() {
    let n = 4;
    let s = match n {
        _ => "any",
        4 => "four",
    };
    println!("{s}");
}

It compiles with an "unreachable pattern" warning. _ matches everything, so the 4 arm never runs and it prints any.

Q4 Does this compile?
fn first(v: &[i32]) -> i32 {
    let Some(x) = v.first() else {
        println!("empty");
    };
    *x
}
fn main() {}

The else block of let else must diverge (return, break, continue or panic). Printing and falling through is not allowed.
