Rust Collections

Arrays and tuples have a fixed size known at compile time. Collections keep their data on the heap and can grow and shrink at run time. Three of them cover most programs: Vec<T> for a list, String for text, and HashMap<K, V> for lookups by key.

#rust#vec#string#hashmap

Step through it

Watch len and cap. When they meet, push must move the elements to a bigger buffer. That is why a reference into a Vec cannot survive a push.

1. Vectors: Vec<T>

fn main() {
    let mut v: Vec<i32> = Vec::new();   // type needed: nothing to infer from yet
    v.push(5);
    v.push(6);
    let w = vec![1, 2, 3];              // macro with initial values
    let mut big = Vec::with_capacity(1000); // one allocation up front
    big.extend_from_slice(&w);

    let third: &i32 = &w[2];            // panics if out of range
    let maybe: Option<&i32> = w.get(10); // None if out of range
    println!("{third} {maybe:?} {} {}", v.len(), big.capacity());

    let last = v.pop();                 // Option<i32>
    println!("{last:?} {v:?}");
}

Use indexing when an out-of-range index is a bug that should stop the program. Use get when it can happen legitimately, for example an index typed by a user.

Borrowing and reallocation

Holding a reference to an element and then pushing does not compile, even though the push affects the end of the vector. As Fig 1 shows, a push may move every element to a new buffer.

does not compile
fn main() {
    let mut v = vec![1, 2, 3, 4, 5];
    let first = &v[0];
    v.push(6);          // error[E0502]: cannot borrow `v` as mutable
    println!("{first}");
}

Iterating

fn main() {
    let mut v = vec![100, 32, 57];
    for i in &v {               // shared borrow of each element
        print!("{i} ");
    }
    for i in &mut v {           // mutable borrow: change in place
        *i += 50;               // * dereferences to the i32
    }
    for i in v {                // by value: consumes v
        print!("{i} ");
    }
    println!();
}

Different types in one vector

A vector holds one type. To store a fixed set of different types, wrap them in an enum; the compiler then knows the size of each element and forces you to handle every variant. For an open set of types, use trait objects (chapter 18).

#[derive(Debug)]
enum Cell { Int(i32), Float(f64), Text(String) }

fn main() {
    let row = vec![Cell::Int(3), Cell::Text(String::from("blue")), Cell::Float(10.12)];
    for c in &row {
        match c {
            Cell::Int(i) => print!("int {i}; "),
            Cell::Float(f) => print!("float {f}; "),
            Cell::Text(s) => print!("text {s}; "),
        }
    }
    println!();
}

2. Strings: String and &str

String is a growable, owned, UTF-8 encoded buffer, really a Vec<u8> with a guarantee. &str is a borrowed slice of UTF-8 bytes, such as a string literal or a part of a String.

fn main() {
    let mut s = String::new();
    s.push_str("foo");          // append a &str
    s.push('!');                // append a char
    let s1 = String::from("Hello, ");
    let s2 = "world".to_string();
    let s3 = s1 + &s2;          // s1 is moved; s2 is borrowed
    let s4 = format!("{s3}-{s}-{}", 42); // borrows everything, moves nothing
    println!("{s4} {s2}");
}

+ calls fn add(self, s: &str) -> String. It takes ownership of the left side, appends to its buffer and returns it, so it can avoid a copy. &s2 is a &String that deref coercion turns into &str. For anything more than two pieces, format! is clearer.

No indexing

does not compile
fn main() {
    let s = String::from("hello");
    let h = s[0]; // error[E0277]: the type `str` cannot be indexed by `{integer}`
}

A UTF-8 character takes 1 to 4 bytes. In "Здравствуйте" each letter is 2 bytes, so byte 0 is half a letter. There are three ways to look at the same text, and an index would have to pick one silently:

View"नमस्ते" (Hindi)Method
Bytes18 u8 valuess.bytes(), s.len() = 18
Unicode scalar values6 chars, two of them are combining markss.chars()
Grapheme clusters4 "letters" a reader seesnot in std; crate unicode-segmentation

Indexing is also expected to be O(1), which cannot hold when finding the n-th character means walking from the start. Slicing with byte ranges is allowed, &s[0..4], but panics if the range cuts a character in half.

fn main() {
    let hello = "Здравствуйте";
    let first_two = &hello[0..4];       // "Зд": 4 bytes
    let n_chars = hello.chars().count();
    for c in "Зд".chars() { print!("{c} "); }
    for b in "Зд".bytes() { print!("{b} "); }
    println!("\n{first_two} {} bytes, {n_chars} chars", hello.len());
}

3. Hash maps: HashMap<K, V>

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();
    scores.insert(String::from("Blue"), 10);
    scores.insert(String::from("Yellow"), 50);

    let team = String::from("Blue");
    let score = scores.get(&team).copied().unwrap_or(0); // get returns Option<&V>
    println!("{team}: {score}");

    for (key, value) in &scores {    // arbitrary order
        println!("{key}: {value}");
    }
}

Inserting owned values such as String moves them into the map. Copy values like i32 are copied. If you insert references, the referenced values must outlive the map.

use std::collections::HashMap;

fn main() {
    let text = "hello world wonderful world";
    let mut counts: HashMap<&str, usize> = HashMap::new();
    for word in text.split_whitespace() {
        let c = counts.entry(word).or_insert(0); // &mut usize
        *c += 1;
    }
    let mut sorted: Vec<_> = counts.into_iter().collect();
    sorted.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(b.0)));
    println!("{sorted:?}");
}

The entry API does one hash lookup for "find or insert", and it returns a mutable reference into the map, which is why the counter can be updated in place.

Hashing

The default hasher is SipHash 1-3. It is not the fastest, but it resists hash-flooding attacks, where an attacker sends keys chosen to collide. For trusted keys in hot code, a faster hasher can be plugged in with HashMap::with_hasher or a crate such as ahash or fxhash.

5. Check yourself

Read each snippet and decide whether the compiler accepts it. Every answer was checked with rustc (edition 2024).

Q1 Does this compile?
fn main() {
    let v = vec![1, 2, 3];
    let x = v.get(5);
    println!("{x:?}");
}

get returns Option<&i32>. It prints None instead of panicking.

Q2 Does this compile?
fn main() {
    let s = String::from("hi");
    let c = s[1];
}

Strings cannot be indexed by an integer. Use s.chars().nth(1) or a byte slice.

Q3 Does this compile?
fn main() {
    let a = String::from("a");
    let b = String::from("b");
    let c = a + &b;
    println!("{a}{c}");
}

+ takes ownership of its left operand, so a is moved into c.

Q4 Does this compile?
use std::collections::HashMap;
fn main() {
    let mut m: HashMap<char, u32> = HashMap::new();
    for ch in "abca".chars() {
        *m.entry(ch).or_insert(0) += 1;
    }
    println!("{}", m[&'a']);
}

The entry API returns &mut u32. Indexing a map with m[&k] works too, and panics if the key is missing. Prints 2.
