Rust Common Concepts

The building blocks every Rust program uses: bindings that are immutable by default, a small set of precise types, functions whose last expression is the return value, and three loops. Most of it looks familiar, but a few rules (mutability, shadowing, expressions) shape everything that follows.

1. Variables and mutability

A binding made with let is immutable. Assigning to it again is a compile error, not a runtime one, so you can read a function and know that a value without mut never changes after it is set.

does not compile
fn main() {
    let x = 5;
    x = 6; // error[E0384]: cannot assign twice to immutable variable
}

Add mut when a value really needs to change. It is a signal to the reader as much as to the compiler.

fn main() {
    let mut x = 5;
    println!("x = {x}");
    x = 6;
    println!("x = {x}");
}

Constants

const values are always immutable, must have a type annotation, can live at module level, and must be computable at compile time. By convention they use SCREAMING_SNAKE_CASE. A static is similar but has a single fixed address in memory for the whole program; see chapter 20 for static mut.

const SECONDS_PER_HOUR: u32 = 60 * 60;
static GREETING: &str = "hello";

fn main() {
    println!("{GREETING}: {SECONDS_PER_HOUR} s per hour");
}

2. Shadowing

Declaring a new variable with the same name shadows the old one. It is a new binding, so it can have a different type, and it stays immutable unless you say otherwise. Fig 1 steps through it.

fn main() {
    let guess = "42";               // &str
    let guess: u32 = guess.trim().parse().expect("not a number"); // u32
    println!("{}", guess + 1);
}

The typical use is a transformation pipeline where the intermediate names would be noise: input as text, then input as a number. Trying the same with mut fails, because a variable cannot change its type:

does not compile
fn main() {
    let mut spaces = "   ";
    spaces = spaces.len(); // error[E0308]: mismatched types
}

3. Scalar types

Rust is statically typed. The compiler infers most types, but when several are possible, such as the result of parse, you annotate. A scalar holds a single value.

TypeSizesNotes
Signed integeri8 i16 i32 i64 i128 isizeTwo's complement. i32 is the default.
Unsigned integeru8 u16 u32 u64 u128 usizeusize is pointer sized and used for indexes and lengths.
Floatf32 f64IEEE 754. f64 is the default.
Booleanbooltrue or false, one byte.
CharactercharFour bytes, one Unicode scalar value, written with single quotes.

Integer literals accept separators and suffixes: 98_222, 0xff, 0o77, 0b1111_0000, b'A' (a u8), and 57u8.

Integer overflow

In a debug build, overflowing an integer panics. In a release build (--release) it wraps around silently. Do not rely on either: when overflow is possible, pick the behaviour explicitly.

fn main() {
    let x: u8 = 250;
    println!("{:?}", x.checked_add(10));    // None
    println!("{}", x.wrapping_add(10));     // 4
    println!("{:?}", x.overflowing_add(10)); // (4, true)
    println!("{}", x.saturating_add(10));   // 255
}

Integer division truncates toward zero (-7 / 2 == -3), and % is the remainder with the sign of the left side. Conversions between numeric types are never implicit: write x as f64, or u8::try_from(n) when the value might not fit.

4. Compound types: tuples and arrays

A tuple groups a fixed number of values of possibly different types. Read it by destructuring or by position. The empty tuple () is the unit type, the value of expressions that return nothing.

fn main() {
    let tup: (i32, f64, char) = (500, 6.4, 'z');
    let (x, y, z) = tup;          // destructuring
    println!("{x} {y} {z} {}", tup.0);
}

An array has a fixed length and one element type, and lives on the stack. The length is part of the type: [i32; 5] and [i32; 6] are different types. For a growable list use Vec (chapter 8).

fn main() {
    let months = ["Jan", "Feb", "Mar"];
    let zeros = [0u8; 16];          // 16 bytes, all zero
    let first = months[0];
    println!("{first} {}", zeros.len());

    let i = months.len() + 2;       // pretend this came from user input
    if let Some(m) = months.get(i) {
        println!("{m}");
    } else {
        println!("index {i} is out of bounds");
    }
}

Indexing with months[i] is bounds checked at run time. Out of range, the program panics instead of reading whatever memory follows, which is the class of bug Rust is designed to stop. get returns an Option when you would rather handle it.

5. Functions

Functions use fn and snake_case names, and can be declared before or after they are used. Every parameter needs a type. The return type comes after ->.

fn main() {
    print_labeled(5, 'h');
    println!("{}", plus_one(41));
}

fn print_labeled(value: i32, unit: char) {
    println!("{value}{unit}");
}

fn plus_one(x: i32) -> i32 {
    x + 1 // no semicolon: this expression is the return value
}

Annotating every signature is deliberate: the types inside a body can be inferred because the edges are fixed, and a change inside one function never changes the inferred type of another.

6. Statements and expressions

This is the rule that surprises people coming from C or Java. A statement performs an action and has no value: let y = 6; is a statement, so let x = (let y = 6); does not compile. An expression evaluates to a value: 5 + 6, a function call, a macro call, a block, an if, a match.

A block { ... } is an expression whose value is its last expression. Adding a semicolon turns that expression into a statement, and the block then evaluates to ().

fn main() {
    let y = {
        let x = 3;
        x + 1          // the block's value
    };
    println!("{y}"); // 4
}
does not compile
fn plus_one(x: i32) -> i32 {
    x + 1; // error[E0308]: mismatched types, expected i32, found ()
}

If a function "returns ()" when you expected a value, look for a trailing semicolon.

return still exists for early exits. Idiomatic code uses it only there, and lets the last expression be the normal result.

7. if expressions

The condition must be a bool. There is no truthiness: if count {} with an integer is an error. Write if count != 0.

Because if is an expression, it can produce a value. Both branches must then have the same type, since the compiler must know the type of the variable at compile time.

fn main() {
    let n = 7;
    let kind = if n % 2 == 0 { "even" } else { "odd" };

    if n % 4 == 0 {
        println!("divisible by 4");
    } else if n % 3 == 0 {
        println!("divisible by 3");
    } else {
        println!("{n} is {kind}");
    }
}

A long else if chain is often clearer as a match (chapter 6).

8. Loops: loop, while and for

LoopUse whenValue
loopYou repeat until something inside decides to stop: retries, event loops.break value makes the loop return a value.
while condYou repeat while a condition holds.Always ().
for x in iterYou visit every item of a collection or range. The default choice.Always ().
fn main() {
    // loop returns a value through break
    let mut attempts = 0;
    let result = loop {
        attempts += 1;
        if attempts == 3 {
            break attempts * 10;
        }
    };
    println!("result = {result}");

    // while
    let mut n = 3;
    while n != 0 {
        println!("{n}!");
        n -= 1;
    }

    // for over an array and a reversed range
    for m in ["Jan", "Feb"] {
        println!("{m}");
    }
    for i in (1..4).rev() {
        print!("{i} ");
    }
    println!("liftoff");
}

Prefer for over indexing with while i < a.len(): it cannot go out of bounds, it skips the per-iteration bounds check, and it keeps working if the array length changes.

Loop labels

break and continue apply to the innermost loop. To leave an outer loop, give it a label that starts with a single quote.

fn main() {
    let grid = [[1, 2, 3], [4, 5, 6], [7, 8, 9]];
    let mut found = None;
    'rows: for (r, row) in grid.iter().enumerate() {
        for (c, &v) in row.iter().enumerate() {
            if v == 5 {
                found = Some((r, c));
                break 'rows;
            }
        }
    }
    println!("{found:?}"); // Some((1, 1))
}

Ranges: a..b excludes b, a..=b includes it. (0..10).step_by(2) skips, and .rev() reverses.

9. Comments and formatting

Line comments start with //. Documentation comments use /// for the item that follows and //! for the enclosing module or crate; chapter 14 shows how cargo doc turns them into HTML.

println! is a macro, marked by the !. Inside the string, {} formats with Display, {:?} with Debug, {:#?} pretty-prints, and variables can be named inline: {x}, {x:>8.2} (right-aligned, width 8, two decimals).

fn main() {
    let pi = 3.14159;
    let pair = (1, "one");
    println!("[{pi:>8.2}] [{pi:<8.3}] {pair:?}");
}

10. Check yourself

Read each snippet and decide whether the compiler accepts it. Every answer was checked with rustc (edition 2024).

Q1 Does this compile?
fn main() {
    let x = 5;
    let x = x * 2;
    println!("{x}");
}

This is shadowing, not assignment. The second let creates a new x, so no mut is needed.

Q2 Does this compile?
fn main() {
    let n = 3;
    if n {
        println!("nonzero");
    }
}

Conditions must be bool. Rust does not convert integers to booleans; write if n != 0.

Q3 Does this compile?
fn square(x: i32) -> i32 {
    x * x;
}
fn main() { println!("{}", square(3)); }

The trailing semicolon turns x * x into a statement, so the body evaluates to () instead of i32.

Q4 Does this compile?
fn main() {
    let v = if true { 1 } else { "one" };
}

Both branches of an if used as a value must have the same type.

Q5 Does this compile?
fn main() {
    let mut count = 0;
    let total = loop {
        count += 1;
        if count == 4 { break count * 2; }
    };
    println!("{total}");
}

loop is an expression, and break value sets its value. It prints 8.
