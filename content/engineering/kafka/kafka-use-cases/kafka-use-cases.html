1. What Kafka is

  
Apache Kafka is a distributed event streaming platform. Applications publish events to named topics, and any number of other applications read them, in real time, at their own pace. Kafka stores events durably in an ordered log, so a consumer can read now, later, or replay from the past.

  
That one idea fits five common jobs. The simulator above steps through each of them.

  
Kafka is not just about moving messages. It is about building scalable, reliable systems where services react to data independently.






  
2. Real-time data pipelines

  
Move data between systems without writing a custom sync for every pair. Kafka sits in the middle: sources write in, sinks read out.

  
  • Ingest data from databases, applications and external sources.
  • Connect producers and consumers through Kafka.
  • Distribute data to analytics platforms and data warehouses.

  
Typical tools: Kafka Connect and its JDBC connectors. Takeaway: move data across systems.






  
3. Event-driven systems

  
A service publishes a fact, such as OrderPlaced, to a topic. It does not know or care who reads it.

  
  • Services publish events to Kafka topics.
  • Multiple consumers subscribe to the same events.
  • Services process events independently, without tight coupling.

  
Example: order events trigger the inventory, payment and notification services, each in its own consumer group. Adding a fourth consumer needs no change to the publisher. Takeaway: decouple microservices.






  
4. Stream processing

  
Treat data as a never-ending stream and compute on it as it arrives, instead of waiting for a nightly batch.

  
  • Consume continuous streams of events.
  • Filter, aggregate and transform incoming data.
  • Publish processed results to downstream topics.

  
Technologies: Apache Flink and Kafka Streams. Takeaway: process continuous data.






  
5. Centralized logs and metrics

  
Many services emit logs, metrics and traces. Kafka buffers the burst so the monitoring backend is not overwhelmed and no data is lost when it is briefly down.

  
  • Collect logs, metrics and telemetry from multiple services.
  • Use Kafka to buffer and distribute incoming data.
  • Send data to monitoring and observability platforms.

  
Technologies: Fluentd, Elasticsearch, Grafana. Takeaway: aggregate telemetry.






  
6. CDC: change data capture

  
Instead of polling tables, read the database's transaction log and turn every row change into an event.

  
  • Capture database INSERT, UPDATE and DELETE operations.
  • Read database transaction logs.
  • Stream changes to downstream systems through Kafka.

  
Technologies: Debezium and Kafka. Takeaway: capture and distribute database changes.
