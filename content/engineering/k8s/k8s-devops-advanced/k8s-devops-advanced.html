1. Helm

  
Helm packages an app as a chart: templates plus default values.yaml. Installing a chart with your values makes a release with a revision history, so upgrades and rollbacks are single commands.


helm install web ./chart -f prod.yaml
helm upgrade web ./chart --set image.tag=2.0
helm rollback web 1






  
2. Kustomize

  
Template-free customization. A base holds plain manifests. An overlay per environment patches them: change replicas, add labels, swap the image. It is built into kubectl apply -k. Choose Helm to distribute software, and Kustomize to vary your own.







  
3. Argo CD / GitOps

  
Store desired state in Git and let an in-cluster controller pull it. Argo CD compares Git with the cluster, reports Synced or OutOfSync, and applies the difference. Automated sync applies commits. Self-heal reverts manual drift. Git then gives you review, history and rollback for free. Flux works the same way.







  
4. etcd

  
The only stateful part of the control plane. It stores all objects and uses Raft: a write commits once a majority of members have it, so run 3 or 5, never an even number. The API server is its only client. Keep it on fast disks, watch its latency, and back it up regularly.


etcdctl snapshot save backup.db






  
5. Scheduler Internals

  
Pods wait in a queue by priority. For each one the scheduler runs a scheduling cycle (filter, then score, then pick a node) and an asynchronous binding cycle that writes the result. Both are built from plugins at extension points, such as Filter, Score and Bind, so you can add your own or run a second scheduler. If nothing fits, a higher-priority Pod can trigger preemption of lower ones.







  
6. Informer / Watch

  
Controllers do not poll. A client does one list, then opens a watch from the returned resourceVersion and receives a stream of changes. An informer keeps a local cache from that stream, so reads cost nothing. It calls handlers on add, update and delete, which put object keys on a workqueue. A worker then reconciles each key.







  
7. CRD / Operator

  
A CustomResourceDefinition adds a new type to the API, such as Database, with schema validation. An operator is a controller for it that encodes operations know-how: create, back up, fail over and upgrade. Build one with Kubebuilder or Operator SDK.







  
8. Admission Webhook

  
Your own admission logic over HTTPS. The API server sends an AdmissionReview and the webhook answers allow or deny, and for a mutating webhook a JSON patch. Set a short timeoutSeconds. failurePolicy: Fail blocks requests when the webhook is down, so exclude kube-system and the webhook's own namespace. Prefer ValidatingAdmissionPolicy for simple rules.

10. HA / Disaster Recovery

  
    
    
  • Run 3 control plane nodes behind a load balancer, spread across zones, with a 3 member etcd.
    • 
    
  • Spread workers and Pods across zones. Use PDBs and anti-affinity.
    • 
    
  • Back up etcd snapshots off the cluster, and test restores. Use Velero for resources and volume snapshots.
    • 
    
  • Keep manifests in Git so a lost cluster can be rebuilt. Plan a second Region if you must survive one.
