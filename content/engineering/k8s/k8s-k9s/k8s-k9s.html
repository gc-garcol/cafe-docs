1. What K9s is

  
K9s is a terminal UI for Kubernetes. It watches the API server and shows live, auto-refreshing tables of resources. It does what you would do with a stream of kubectl get, describe, logs and exec calls, but with one key per action.

  
It talks to the cluster with your kubeconfig, so it has exactly your permissions. Install with brew install k9s or a release binary.


k9s
k9s -n shop --context kind-dev
k9s --readonly






  
2. Navigation

  
Press : to open the command prompt and type a resource name. Aliases work, so :po, :dp, :svc, :no and :ns all switch views. ? shows help and Esc goes back. :q quits.

  

    
CommandView

    
      
:podsPods in the current namespace

      
:deployDeployments

      
:svcServices

      
:nodeNodes

      
:nsNamespaces. Press Enter to switch to one.

      
:ctxContexts, to switch cluster

      
:aliasAll resource names you can type

    
  






  
3. Filter and search

  
Press / and type to filter the table. The filter is a regular expression on the name. Use /-l app=web to filter by label and /-f text for fuzzy match. Esc clears it.

  
Sort with shifted keys on common columns, such as Shift-C for CPU, Shift-M for memory and Shift-A for age. Press 0 to show all namespaces.







  
4. Inspect a resource

  
Select a row and press a key. These keys work on Pods and many other kinds.

  

    
KeyAction

    
      
EnterDrill down, for example from a Pod to its containers

      
dDescribe, with events at the bottom

      
yShow the YAML

      
lLogs. p shows the previous container's logs.

      
sOpen a shell in the container

      
Shift-FPort-forward

    
  
  
In the log view, w wraps lines, t toggles timestamps, s toggles autoscroll and f goes fullscreen.







  
5. Act on resources

  
    
    
  • e edits the object in your $EDITOR.
    • 
    
  • Ctrl-D deletes after a confirmation. Ctrl-K kills a Pod right away.
    • 
    
  • On a Deployment, s scales and r restarts the rollout.
    • 
    
  • Space marks rows so one action applies to many.
    • 
  
  
These are real changes with your credentials. Use --readonly when you only want to look.







  
6. Contexts and namespaces

  
:ctx lists contexts from your kubeconfig and Enter switches. :ns lists namespaces and Enter makes one current. The header shows both so you know where you are. Number keys jump to favorite namespaces. Check the header before any delete.







  
7. Pulses, Xray and Popeye

  
    
    
  • :pulse shows a dashboard of cluster health and resource counts over time.
    • 
    
  • :xray deploy draws the tree from a Deployment to its ReplicaSets, Pods and containers, and what they use.
    • 
    
  • :popeye runs a sanitizer that scans the cluster for misconfigurations and gives a score.
    • 
  






  
8. Customize

  
K9s keeps its config in a directory shown by k9s info. The files are config.yaml, aliases.yaml for your own command aliases, hotkeys.yaml for shortcuts that jump to a view, plugins.yaml to bind a key to an external command, and a skins folder for colors.


# plugins.yaml: press Shift-S on a Pod to run stern
plugins:
  stern:
    shortCut: Shift-S
    scopes: [pods]
    command: stern
    args: [--namespace, $NAMESPACE, $NAME]






  
9. Using it safely

  
    
    
  • Start with --readonly on production, or set readOnly: true in the config.
    • 
    
  • Read the header: context and namespace.
    • 
    
  • Prefer changing manifests in Git for real changes, and use K9s to look and debug.
    • 
    
  • Pair it with RBAC so the account in your kubeconfig cannot do more than it should.
