Skip List

A sorted linked list with express lanes on top. Random coin flips decide who gets promoted, and search takes expected O(log n) steps without any rebalancing.

Ride the express lanes

The model below is a real skip list holding 3, 6, 7, 9, 12, 17, 19, 21, 25. Each tower is one key, and its height is the number of lanes it joins. Lane 0 visits everyone. Higher lanes visit fewer towers, so you can travel far in one hop. Search walks the path step by step. Insert shows which links get rewired.

1. The idea

Searching a sorted linked list is slow because you can only move one node at a time. Binary search is fast, but it needs random access. A skip list adds extra lanes so you can skip ahead, then come back down to a finer lane when you would overshoot.

Every node is on lane 0. Each node is promoted to the next lane with probability 1/2, so lane l holds about n / 2l nodes. The result behaves like a balanced tree without ever being rebalanced.

Fig 2 · The same skip list as Fig 1. Node heights are 2, 1, 3, 1, 2, 1, 4, 1, 2. HEAD and NIL reach every lane.

2. Search: right if you can, down if you must

Start at the top lane of HEAD. Look at the next key on this lane. If it is smaller than the target, move right. Otherwise drop one lane. When you cannot drop any more, the next node on lane 0 is either the target or proof that it is missing.

x = HEAD
for lane from top down to 0:
    while x.next[lane].key < target:  x = x.next[lane]
x = x.next[0]
return x.key == target

Fig 3 · Search for 17 stands only on HEAD, 7, 12 and 17. It peeks at 19 three times and never touches 3, 6, 9, 21 or 25.

The expected cost is about two steps per lane, and there are about log₂ n lanes.

3. Insert: find the predecessors, flip coins, splice

Insert is a search that remembers where it dropped down. On each lane, the last node before the new key is its predecessor. Then flip a coin until you get tails. The number of heads plus one is the new tower height. On every lane up to that height, splice the new node in right after its predecessor.

Delete works in reverse. Find the same predecessors, and on each lane where they point at the victim, make them point past it. Then shrink the top lane if it became empty.

4. Code

const int MAXL = 16;

struct Node {
    int key;
    vector<Node*> nxt;
    Node(int k, int h) : key(k), nxt(h, nullptr) {}
};

struct SkipList {
    Node* head = new Node(INT_MIN, MAXL);
    int level = 1;                        // lanes currently in use
    mt19937 rng{12345};

    int randomLevel() {
        int h = 1;
        while (h < MAXL && (rng() & 1)) h++;   // p = 1/2
        return h;
    }

    bool find(int key) {
        Node* x = head;
        for (int i = level - 1; i >= 0; i--)
            while (x->nxt[i] && x->nxt[i]->key < key) x = x->nxt[i];
        x = x->nxt[0];
        return x && x->key == key;
    }

    void insert(int key) {
        Node* update[MAXL];
        Node* x = head;
        for (int i = level - 1; i >= 0; i--) {
            while (x->nxt[i] && x->nxt[i]->key < key) x = x->nxt[i];
            update[i] = x;                   // predecessor on lane i
        }
        int h = randomLevel();
        for (int i = level; i < h; i++) update[i] = head;
        level = max(level, h);

        Node* n = new Node(key, h);
        for (int i = 0; i < h; i++) {
            n->nxt[i] = update[i]->nxt[i];
            update[i]->nxt[i] = n;
        }
    }

    void erase(int key) {
        Node* update[MAXL];
        Node* x = head;
        for (int i = level - 1; i >= 0; i--) {
            while (x->nxt[i] && x->nxt[i]->key < key) x = x->nxt[i];
            update[i] = x;
        }
        x = x->nxt[0];
        if (!x || x->key != key) return;
        for (int i = 0; i < level && update[i]->nxt[i] == x; i++)
            update[i]->nxt[i] = x->nxt[i];
        delete x;
        while (level > 1 && !head->nxt[level - 1]) level--;
    }
};

This sketch does not reject duplicate keys. Check find(key) first, or store a count in the node.

5. Cost

Search · insert · delete
O(log n)

Expected, for any input order. The coin flips do the balancing.

Space
O(n)

About 2n pointers when p = 1/2.

Worst case
O(n)

Possible, but with vanishing probability.

Skip lists are used in practice. Redis sorted sets are built on one, and they are popular for concurrent maps because an insert only touches a few neighbouring links.

Pitfalls

  • Cap the height. MAXL around log₂ n is enough, 16 to 32 covers most uses.
  • Search with <, not <=. You want the predecessor, so that insert and delete can reuse the same walk.
  • When the new height exceeds the current level, the missing predecessors are HEAD.
  • Guarantees are probabilistic. Seed the generator properly, and do not share a predictable seed with adversarial input.
  • Pointer chasing is not cache friendly. A balanced tree or a B-tree can win on raw speed for small in-memory sets.
