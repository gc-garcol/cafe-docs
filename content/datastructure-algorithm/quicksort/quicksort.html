Quicksort

Pick a pivot, push smaller items to its left and larger items to its right, then sort each side the same way. The pivot lands in its final place after every pass.

1. The idea

  
Quicksort is divide and conquer, but the work happens before the recursion, not after. Partitioning does the real job. After one partition, the pivot sits where it belongs in the sorted array, and nothing will ever cross it again.

  
Partition once, then forget the pivot. Two smaller problems remain, and they do not interact.






  
2. Partition

  
Walk j from left to right. Whenever a[j] is smaller than the pivot, grow the smaller zone by one and swap the item into it. At the end, swap the pivot into the slot just after the zone.

  
function partition(a, lo, hi) {
  const pivot = a[hi];
  let i = lo - 1;                      // end of the "smaller" zone
  for (let j = lo; j < hi; j++) {
    if (a[j] < pivot) {
      i++;
      [a[i], a[j]] = [a[j], a[i]];
    }
  }
  [a[i + 1], a[hi]] = [a[hi], a[i + 1]];  // pivot into place
  return i + 1;
}

function quicksort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return;
  const p = partition(a, lo, hi);
  quicksort(a, lo, p - 1);
  quicksort(a, p + 1, hi);
}

  
Partitioning takes one pass, so it costs O(n) for a range of size n.






  
3. Why the pivot matters

  
If each pivot splits the range roughly in half, the recursion is log₂ n levels deep and each level does O(n) work. That gives O(n log n).

  
If the pivot is always the smallest or largest item, one side is empty and the other has n - 1 items. The depth becomes n and the total is O(n²). Press Sorted array (worst case): with the last item as pivot, an already sorted input does exactly this.

  
    
    
  • Random pivot: pick a random index and swap it to the end first. No input is reliably bad.
    • 
    
  • Median of three: use the median of the first, middle and last items.
    • 
    
  • Three-way partition: group items equal to the pivot together. It avoids quadratic time on many duplicates.
    •

5. Where it shows up

  
    
    
  • General-purpose sorting of arrays in memory. Many standard libraries use a quicksort variant, such as introsort, which falls back to heapsort when recursion gets too deep.
    • 
    
  • Quickselect: run one side of the partition only, to find the k-th smallest item in O(n) average time.
    • 
    
  • Compare with merge sort: choose merge sort when you need stability or a guaranteed O(n log n).
