Trie

A tree where each edge is one character and each path from the root spells a prefix. Words that share a start share nodes, and lookup costs O(L) for a word of length L, no matter how many words are stored.

Try the machine first

The trie starts with five words. Insert a word to add its missing nodes. Search checks for a whole word. Prefix lists every word that starts with the text you type. Double-ringed nodes mark the end of a word.

1. The idea

  
A hash set answers "is this word stored?" but knows nothing about structure. It cannot list the words that start with ca without scanning everything. A trie stores words by their letters, so shared prefixes are stored once and prefix questions become a walk down the tree.

  
The cost depends on the length of the word, not on how many words are in the set.






  
2. Insert and search

  
Each node has a map from letter to child and a flag that says whether a word ends here. The flag matters: car is a prefix of cart, but both can be words.

  
class Trie {
  root = { next: new Map(), end: false };

  insert(word) {
    let n = this.root;
    for (const ch of word) {
      if (!n.next.has(ch)) n.next.set(ch, { next: new Map(), end: false });
      n = n.next.get(ch);
    }
    n.end = true;
  }

  // the node for a prefix, or null
  find(prefix) {
    let n = this.root;
    for (const ch of prefix) {
      n = n.next.get(ch);
      if (!n) return null;
    }
    return n;
  }

  has(word)        { const n = this.find(word); return !!n && n.end; }
  startsWith(pre)  { return this.find(pre) !== null; }
}

  
Try searching for ca in the demo. The path exists, but the last node is not an end of a word, so search says no while prefix says yes.






  
3. Prefix queries

  
To list every word with a prefix, find the node for the prefix, then walk its whole subtree and collect the paths that end at a flagged node. This is the engine behind autocomplete.

  
function collect(node, path, out) {
  if (node.end) out.push(path);
  for (const [ch, child] of [...node.next].sort()) collect(child, path + ch, out);
}

  
Walking children in letter order returns the words in alphabetical order for free.






  
4. Cost

  

    
Insert / search
O(L)
L is the word length.

    
Prefix check
O(P)
P is the prefix length.

    
Memory
O(total letters)
Less when prefixes are shared.

  

  

    
ChoiceTrade-off

    
      
Array of 26 childrenFast, but wastes memory when nodes have few children

      
Hash map of childrenCompact for sparse nodes, a little slower per step

      
Radix tree (compressed)Merges single-child chains into one edge, so far fewer nodes

      
Hash set of wordsSmaller and simpler, but no prefix search

    
  






  
5. Where it shows up

  
    
    
  • Autocomplete and search suggestions: walk to the typed prefix, then list the best completions.
    • 
    
  • Spell checking: fast "is this a word?" plus nearby-word search.
    • 
    
  • Routing tables: IP routing uses a binary trie to find the longest matching prefix.
    • 
    
  • Word games: prune a board search as soon as no word starts with the current letters.
    • 
    
  • Bit tries: the same idea with 0 and 1 edges, used for integer keys and XOR queries.
    • 
  

  
If you only need membership and can tolerate false positives, a Bloom filter uses much less memory. A trie is the tool when the structure of the key matters.
