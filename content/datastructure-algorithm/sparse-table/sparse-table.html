Sparse Table

Precompute the answer for every block whose length is a power of two. Then any range minimum is just two lookups, in constant time.

1. The idea

A range minimum over a[l..r] can be rebuilt from smaller pieces. If you already know the minimum of every block of length 1, 2, 4, 8 and so on, any range is covered by a few of those blocks.

The sparse table stores exactly that. t[k][i] is the minimum of the block that starts at i and has length 2k.

Fig 2 · The full table for n = 8. Shelf k has n − 2k + 1 entries, so the table is a triangle.

2. Build: double the length each level

Level 0 is the array itself. A block of length 2k is two blocks of length 2k−1 placed side by side, so each new level costs one min per entry.

t[0][i] = a[i]
t[k][i] = min( t[k-1][i], t[k-1][i + 2k-1] )

Fig 3 · t[2][1] = min(t[1][1], t[1][3]) = min(a[1..2], a[3..4]).

There are ⌊log₂ n⌋ + 1 levels and each has at most n entries. Building the whole table is therefore O(n log n) time and memory.

3. Query: two blocks, allowed to overlap

For a range [l, r] let len = r − l + 1 and k = ⌊log₂ len⌋. The largest power of two that fits is 2k, and it is more than half of len. So one block from the left end and one block from the right end together cover the whole range.

k      = floor(log2(r - l + 1))
answer = min( t[k][l], t[k][r - 2k + 1] )

Fig 4 · Query [1, 6]: block A = a[1..4], block B = a[3..6].

Overlap is the trick. Because min(x, x) = x, counting an element twice never changes the answer.

4. Code

Precompute a tiny log table so the query stays O(1). Calling log2 from a math library works too, but it is slower and floating point can be off by one at exact powers of two.

const int MAXN = 100005, LOG = 17;   // 2^17 > 1e5
int st[LOG + 1][MAXN], lg[MAXN];

void build(const vector<int>& a) {
    int n = a.size();
    lg[1] = 0;
    for (int i = 2; i <= n; i++) lg[i] = lg[i / 2] + 1;

    for (int i = 0; i < n; i++) st[0][i] = a[i];
    for (int k = 1; (1 << k) <= n; k++)
        for (int i = 0; i + (1 << k) <= n; i++)
            st[k][i] = min(st[k - 1][i], st[k - 1][i + (1 << (k - 1))]);
}

int query(int l, int r) {            // inclusive, 0-indexed
    int k = lg[r - l + 1];
    return min(st[k][l], st[k][r - (1 << k) + 1]);
}

5. Cost

Build
O(n log n)

One min per entry, about n per level, log n levels.

Query
O(1)

Two lookups and one min. Nothing loops.

Memory
O(n log n)

The whole triangle is stored.

6. When it works

The two blocks overlap, so the operation must give the same result when an element is counted twice. This property is called idempotent.

OperationOverlap safe?Why
min, maxYesmin(x, x) = x
gcd, lcmYesgcd(x, x) = x
&, |Yesx & x = x
+, ^, ×NoThe overlap would be counted twice. Use a prefix sum, or split the range into disjoint blocks in O(log n).

Pitfalls

  • The table is static. If a single element changes, you rebuild. For updates, reach for a segment tree or a Fenwick tree.
  • Keep the loop condition i + (1 << k) <= n. Reading past the end of level k−1 is the classic off-by-one.
  • Ranges are inclusive on both ends. The second block starts at r − 2k + 1, not r − 2k.
  • Memory can bite: 106 elements with 20 levels of 4-byte ints is about 80 MB.
