Timer Wheel

A clock face for timeouts. Drop each timer into the slot where it will expire, then let one hand sweep around. Adding and cancelling a timer costs O(1).

1. The problem

A server tracks a lot of timeouts: request deadlines, TCP retransmits, session expiry, heartbeats. Most of them are cancelled before they fire, and they are created and cancelled at a high rate.

The usual answer is a min-heap ordered by expiry. It works, but every insert and cancel costs O(log n), and with millions of timers that adds up. A timer wheel trades a little precision for O(1) on both.

Do not sort timers. Bucket them by when they expire, and only look at the bucket the clock points to.

2. A single wheel

Split time into ticks, for example 1 ms each. Make an array of N slots, where each slot holds a list of timers. A pointer cursor marks the slot for the current tick.

To schedule a timer that fires after d ticks, put it in slot (cursor + d) mod N. On every tick, move the cursor forward by one and fire everything in that slot.

Fig 2 · One wheel with N = 8. The cursor sits at slot 2.

The catch is range. A single wheel can only schedule timers up to N − 1 ticks ahead. A timer with a longer delay would land on a slot the cursor reaches too early.

3. Two ways to go longer

There are two classic fixes. Both keep the O(1) feel.

Hashed wheel
rounds

Same slot formula, but store rounds = d / N in the timer. On each visit, decrement it. Fire only when it reaches 0. Simple, but a slot may hold timers that are not due, so the tick scans them.

Hierarchical wheel
cascade

Stack wheels like clock hands: seconds, minutes, hours. Far timers wait in a coarse wheel. When the coarse hand moves, its timers drop into the finer wheel.

Overflow list
fallback

Anything beyond the top wheel goes into a sorted list or a heap, and is pulled in when it comes within range. Netty and Kafka use this idea.

4. The hierarchical wheel

Take two wheels of N = 8 slots. Wheel 0 has a tick of 1. Wheel 1 has a tick of 8. A timer expiring at absolute time t with delay d = t − now goes to:

  • d < 8: wheel 0, slot t mod 8.
  • 8 ≤ d < 64: wheel 1, slot ⌊t / 8⌋ mod 8.
  • otherwise: the overflow list.

Each time now becomes a multiple of 8, the cursor of wheel 1 moves. Every timer in its new slot is re-inserted with the same rule. They now have d < 8, so they land in wheel 0. This is the cascade. Then wheel 0 fires its current slot.

Fig 3 · The cascade. Each timer is touched at most once per level, so the total work per timer is O(levels).

5. Code

A minimal two-level wheel in Java-like pseudocode. The tick loop runs on one thread. Other threads hand over new timers through a queue.

class TimerWheel {
  static final int N = 8;
  List<Timer>[] w0 = new List[N];   // tick = 1
  List<Timer>[] w1 = new List[N];   // tick = N
  long now = 0;

  void add(Timer t) {                // t.expiry is absolute
    long d = t.expiry - now;
    if (d < N)           w0[(int)(t.expiry % N)].add(t);
    else if (d < N * N)   w1[(int)((t.expiry / N) % N)].add(t);
    else                 overflow.add(t);
  }

  void tick() {
    now++;
    if (now % N == 0) {            // wheel 1 moved: cascade
      List<Timer> s = w1[(int)((now / N) % N)];
      w1[(int)((now / N) % N)] = new ArrayList<>();
      for (Timer t : s) add(t);
    }
    List<Timer> due = w0[(int)(now % N)];
    w0[(int)(now % N)] = new ArrayList<>();
    for (Timer t : due) if (!t.cancelled) t.run();
  }
}

Cancelling is just a flag on the timer, or an unlink if the slot is a doubly linked list. Production code usually uses the linked list so a cancelled timer frees memory right away.

Memory

7. When to use it

  • You have very many timers and most are cancelled before they fire: network timeouts, session expiry, retries.
  • A delay error of up to one tick is fine. Pick the tick to match: 1 ms for RPC, 100 ms or 1 s for sessions.
  • You want predictable cost. A heap has no bad case, but its constant grows with n. A wheel does not.

Avoid it when you need exact deadlines, when there are only a handful of timers, or when the clock must jump to the next expiry to save power. A wheel ticks even when idle, unless you add a way to skip empty slots.

Seen in the wild: the Linux kernel timer subsystem, Netty's HashedWheelTimer, Kafka's purgatory (a hierarchical wheel plus a delay queue), and many TCP stacks.
