Genetic Algorithm

Search by evolution. Keep a population of candidate answers, let the better ones breed, add a little random change, and repeat until a good answer appears.

1. The idea

Some problems have no formula, only a way to score an answer. A genetic algorithm borrows the trick nature uses: keep many candidates, favour the good ones, combine them, and perturb them slightly.

2. The loop

Every generation repeats the same five steps. The new population replaces the old one, and the loop stops when the score is good enough or the budget of generations runs out.

Fig 2 · One generation. Selection is where the pressure toward better answers comes from.

3. The three operators

Selection. Better individuals should breed more often, but weak ones must keep a small chance. A tournament does both: draw k random individuals and keep the fittest. A larger k means stronger pressure.

Crossover. Pick a random cut. The child takes genes before the cut from parent A and the rest from parent B. Good partial answers from two parents can end up in one child.

Mutation. Flip each gene with a small probability. It brings back genes that the whole population has lost.

Fig 3 · A single crossover at cut 5, then one mutation on gene 8.

Crossover recombines what the population already knows. Mutation adds what it does not know yet.

4. Code

The same loop as the bench above, with elitism: the best individual always survives unchanged, so the best score never goes down.

import random

GENES, POP = 12, 6
TARGET = [random.randint(0, 1) for _ in range(GENES)]

def fitness(g):                      # how many genes match the target
    return sum(a == b for a, b in zip(g, TARGET))

def tournament(pop, k=2):             # best of k random individuals
    return max(random.sample(pop, k), key=fitness)

def crossover(a, b, rate=0.9):
    if random.random() > rate: return a[:]
    cut = random.randint(1, GENES - 1)       # single-point crossover
    return a[:cut] + b[cut:]

def mutate(g, rate=0.04):
    return [1 - x if random.random() < rate else x for x in g]

pop = [[random.randint(0, 1) for _ in range(GENES)] for _ in range(POP)]
for gen in range(100):
    best = max(pop, key=fitness)
    if fitness(best) == GENES: break
    pop = [best] + [                         # elitism: keep the best as is
        mutate(crossover(tournament(pop), tournament(pop)))
        for _ in range(POP - 1)
    ]

5. Knobs that matter

KnobToo lowToo high
Population sizeLittle diversity, gets stuckSlow, many evaluations per generation
Mutation ratePopulation converges and stallsBecomes random search
Crossover rateLittle mixing of good partsGood individuals get broken up
Selection pressureDrifts without improvingPremature convergence

Try it on the bench: set mutation to 0% and the population often freezes below a perfect score. Set it to 20% and the best score jitters instead of climbing.

7. When to use it

  • Use it when you can score an answer but cannot solve for one: scheduling, layout, tuning parameters, routing.
  • Skip it when a direct algorithm exists. Shortest paths and sorting do not need evolution.
  • Design the fitness function first. The algorithm optimizes exactly what you score, including loopholes.
  • Watch for premature convergence: if every row looks the same, only mutation can still explore. Raise it or add fresh random individuals.
  • Results are random. Run several seeds before trusting one run.
