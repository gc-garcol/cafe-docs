Quad Tree

Split a square into four quarters whenever it gets crowded. Dense areas get small cells, empty areas stay as one big cell, and a search only visits the cells that touch the area you ask about.

1. The idea

  
A grid has one size for every cell. That is wasteful: a city center needs tiny cells, and an ocean needs one huge cell. A quad tree adapts. It starts with a single square that covers everything, and splits a square into four equal quadrants only when it holds too many points.

  
The quadrants are named by compass: NW, NE, SW, SE. Every split is at the exact middle, so a point's quadrant is decided by two comparisons.

  
Split where the data is. Leave the rest alone.






  
2. Insert

  
Walk down from the root. Pick the quadrant that holds the point, until you reach a leaf. Add the point there. If the leaf now has more than the capacity, split it into four children and push its points down.

  
function insert(node, p) {
  if (node.children) return insert(node.children[quad(node, p)], p);
  node.points.push(p);
  if (node.points.length > CAP && node.depth < MAX_DEPTH) {
    split(node);                // make 4 children
    for (const q of node.points) insert(node, q);
    node.points = [];
  }
}

function quad(n, p) {
  const mx = n.x + n.size / 2, my = n.y + n.size / 2;
  return (p.x < mx ? 0 : 1) + (p.y < my ? 0 : 2);
}

  
The depth limit matters. Many points at the exact same spot would otherwise split forever.






  
3. Range query

  
To find all points in a rectangle, start at the root. If a cell does not overlap the rectangle, skip it and everything below it. If it does, check its points or recurse into its children.

  
function query(node, rect, out) {
  if (!overlaps(node, rect)) return;     // prune this whole subtree
  if (node.children) {
    for (const c of node.children) query(c, rect, out);
  } else {
    for (const p of node.points) if (inside(rect, p)) out.push(p);
  }
}

  
Shrink the query box in the demo and watch the visited count fall. A small box touches only a few cells, however many points exist elsewhere.






  
4. Nearest neighbor

  
Descend into the cell that contains the target first, which gives a good guess fast. Then visit other cells only if their closest edge is nearer than the best distance so far. Cells that are farther away than the current best are pruned, the same trick as in k-d trees.

6. Where it shows up

  
    
    
  • Games: collision checks only against objects in nearby cells.
    • 
    
  • Maps and geo: map tiles are quad tree cells, and so are geohash-like indexes.
    • 
    
  • Images: compression and region merging for flat areas.
    • 
    
  • Simulation: the Barnes-Hut method groups far-away bodies to speed up n-body physics.
    • 
  

  
If points move a lot, rebuilding or reinserting each frame can cost more than it saves. For uniformly spread data, a plain grid is often simpler and just as fast.
