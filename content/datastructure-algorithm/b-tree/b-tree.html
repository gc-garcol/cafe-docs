B-Tree

A search tree with wide nodes. Each node holds many sorted keys, so the tree stays very short, and one node read from disk answers many comparisons at once. Databases and file systems are built on it.

Try the machine first

Insert keys and watch the tree grow. Each node holds at most 3 keys. When a fourth arrives, the node splits in two and its middle key moves up to the parent. Use Search to see the path of nodes a lookup reads.

1. The idea

  
A binary search tree reads one key per node. On a disk, reading a node costs one slow trip, and most of that cost is the same for 8 bytes or 8 kilobytes. So pack a whole page of keys into each node. A node with m keys has m + 1 children, and the keys tell you which child to follow.

  
With hundreds of keys per node, a tree of a billion keys is only 4 or 5 levels deep. That is 4 or 5 disk reads for any lookup.

  
Make the tree wide so it can stay short.






  
2. The rules

  
    
    
  • Keys inside a node are sorted.
    • 
    
  • For a key range between two neighboring keys, there is one child that holds exactly that range.
    • 
    
  • Every node except the root holds at least half its capacity.
    • 
    
  • All leaves are at the same depth.
    • 
  

  
The last rule is what makes the tree balanced. It is kept by growing the tree at the top, not at the bottom.






  
3. Search

  
In each node, find the first key that is greater than or equal to the target. If it is equal, you are done. Otherwise follow the child just to the left of that key, and repeat.

  
function search(node, k) {
  let i = 0;
  while (i < node.keys.length && k > node.keys[i]) i++;
  if (node.keys[i] === k) return true;
  if (node.isLeaf) return false;
  return search(node.children[i], k);
}

  
Inside a node, use binary search when keys are many. The comparisons are in memory and cheap. The node reads are the cost to count.






  
4. Insert and split

  
Find the leaf where the key belongs and add it there. If the leaf now has too many keys, split it: the middle key moves up into the parent, and the other keys form two nodes. If the parent overflows, it splits the same way. A split that reaches the root creates a new root, and that is the only way the tree gets taller.

  
function split(node) {
  const mid = node.keys.length >> 1;
  const up = node.keys[mid];                  // moves to the parent
  const right = node.keys.splice(mid + 1);       // upper half, new node
  node.keys.pop();                              // drop the promoted key
  // children are split the same way at index mid + 1
  return { up, left: node, right: makeNode(right) };
}






  
5. Delete

  
Delete is the mirror image. Remove the key, and if a node falls below half full, borrow a key from a sibling through the parent. If the sibling is also at the minimum, merge the two nodes and pull a key down from the parent. A merge can cascade upward and, at the root, shrink the tree by one level.

7. Where it shows up

  
    
    
  • File systems: NTFS, ext4 (as an HTree for directories), Btrfs, and APFS keep their metadata in B-Tree variants.
    • 
    
  • Databases: the default index in PostgreSQL, MySQL, and SQLite is a B-Tree family structure.
    • 
    
  • Key-value stores: LMDB and BoltDB are built on B-Trees.
    • 
  

  
Most databases use the B+ Tree variant, which keeps all values in the leaves. It scans ranges faster. For write-heavy loads, an LSM Tree trades read speed for sequential writes.
