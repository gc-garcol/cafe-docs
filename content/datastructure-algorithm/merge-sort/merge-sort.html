Merge sort

Split the array in half, sort each half, then merge the two sorted halves into one. Every level of splitting costs one pass, so the total is O(n log n) in every case.

1. The idea

  
Merging two sorted lists is easy and fast. Look at the front of each list, take the smaller item, repeat. That takes one pass. Merge sort uses this by turning sorting into a lot of merging.

  
A single item is already sorted. So split until each piece has one item, then merge pieces back up. Each level of the recursion merges n items in total.

  
Sorting is hard. Merging two sorted lists is not. Reduce the first to the second.






  
2. Split, then merge

  
function mergeSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return;
  const mid = (lo + hi) >> 1;
  mergeSort(a, lo, mid);
  mergeSort(a, mid + 1, hi);
  merge(a, lo, mid, hi);
}

function merge(a, lo, mid, hi) {
  const L = a.slice(lo, mid + 1), R = a.slice(mid + 1, hi + 1);
  let i = 0, j = 0, k = lo;
  while (i < L.length && j < R.length) {
    a[k++] = L[i] <= R[j] ? L[i++] : R[j++];   // <= keeps it stable
  }
  while (i < L.length) a[k++] = L[i++];
  while (j < R.length) a[k++] = R[j++];
}

  
Copy both halves first, then write back into the original array. Copying is why merge sort needs O(n) extra space.






  
3. Why it is stable

  
When two items are equal, the merge takes from the left half first (<=, not <). Items that were earlier in the input stay earlier in the output. This matters when you sort records by one field and want a previous order kept for ties, for example sorting by date and then by name.

log₂ n

5. Where it shows up

  
    
    
  • Stable sorting: many standard libraries use a merge sort variant, such as Timsort, for sorting objects.
    • 
    
  • External sorting: sort chunks that fit in memory, then merge them from disk. A heap can pick the smallest head among many chunks.
    • 
    
  • Linked lists: merge sort needs no random access and no extra buffer there.
    • 
    
  • Counting inversions: count how many items jump ahead during the merge step.
    • 
    
  • Compare with quicksort: quicksort is in place and often faster in memory, but merge sort has a guaranteed bound and is stable.
