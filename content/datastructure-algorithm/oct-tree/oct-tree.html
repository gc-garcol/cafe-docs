Octree

A quad tree for 3D. Split a cube into eight smaller cubes whenever it gets crowded. Dense regions get small cells, empty space stays as one big cell, and a search only opens the cells that touch the box you ask about.

1. The idea

  
A 3D grid wastes memory. Most of space is empty, and a uniform grid still stores every empty voxel. An octree adapts. It starts with one cube that covers everything, and splits a cube into eight equal octants only when it holds too many points.

  
Every split is at the exact center, so a point's octant comes from three comparisons, one per axis. Those three bits make a number from 0 to 7.

  
Three comparisons pick one of eight children.






  
2. Insert

  
Walk down from the root. At each level pick the octant that holds the point, until you reach a leaf. Add the point there. If the leaf now has more than the capacity, split it into eight children and push its points down.

  
function octant(n, p) {
  const h = n.size / 2;
  return (p.x < n.x + h ? 0 : 1)
       + (p.y < n.y + h ? 0 : 2)
       + (p.z < n.z + h ? 0 : 4);   // 0..7
}

function insert(node, p) {
  if (node.children) return insert(node.children[octant(node, p)], p);
  node.points.push(p);
  if (node.points.length > CAP && node.depth < MAX_DEPTH) {
    split(node);                  // make 8 children
    for (const q of node.points) insert(node, q);
    node.points = [];
  }
}

  
The depth limit matters. Many points at the exact same spot would otherwise split forever.






  
3. Range query

  
To find all points in a box, start at the root. If a cell does not overlap the box, skip it and everything below it. If it does, check its points or recurse into its children.

  
function query(node, box, out) {
  if (!overlaps(node, box)) return;    // prune this whole subtree
  if (node.children) {
    for (const c of node.children) query(c, box, out);
  } else {
    for (const p of node.points) if (inside(box, p)) out.push(p);
  }
}

  
Shrink the box in the demo and watch the visited count fall. In 3D the savings are larger than in 2D, because each skipped cell removes a bigger share of space.






  
4. Nearest neighbor and ray casting

  
For the nearest neighbor, descend into the octant that holds the target first. That gives a good guess fast. Then visit other cells only if their closest face is nearer than the best distance so far.

  
For ray casting, test the ray against the root cube, then visit child cubes in the order the ray crosses them. The first hit ends the search, so most of the scene is never touched. Renderers use this to find what a ray sees.

6. Where it shows up

  
    
    
  • Graphics: culling, ray tracing, and level of detail for large scenes.
    • 
    
  • Robotics: OctoMap stores which parts of 3D space are free or occupied.
    • 
    
  • Point clouds: LiDAR scans are downsampled and searched with octrees.
    • 
    
  • Simulation: the Barnes-Hut method groups far-away bodies to speed up 3D n-body physics.
    • 
    
  • Color quantization: an octree over RGB space reduces an image to a small palette.
    • 
  

  
If points move a lot, rebuilding or reinserting each frame can cost more than it saves. For uniformly spread data, a plain 3D grid is often simpler and just as fast.
