Segment Tree

A binary tree where every node remembers the answer for one segment of the array. Any range query is stitched from a handful of nodes, and a single change only touches one path to the root.

1. The idea

A prefix sum answers range sums fast but breaks the moment one element changes. A plain array changes fast but needs O(n) to sum a range. The segment tree sits in between: both operations cost O(log n).

The root stores the sum of the whole array. Its two children store the sums of the left and right halves. Keep halving until each leaf holds one element. With n = 8 that is four levels, and in general ⌈log₂ n⌉ + 1.

Fig 2 · The tree for n = 8. Each parent equals the sum of its two children: 12 = 7 + 5, 37 = 12 + 25.

2. Build: combine two children

Store the tree in a flat array like a binary heap. The root is t[1], and node v has children 2v and 2v + 1. Fill the leaves, then walk back up combining pairs.

t[v] = t[2v] + t[2v + 1]

Every node is computed once and there are about 2n nodes, so building costs O(n). Allocate 4n slots to be safe when n is not a power of two.

3. Query: take, skip, or split

Ask for the sum of a[l..r]. Start at the root and look at each node's segment against the query:

  • Disjoint: the segment is outside the query. Return the neutral value, 0 for sums.
  • Fully inside: return the stored value. No need to look deeper.
  • Partial: some of it is inside. Split into both children and add the results.

Fig 3 · Query [1, 6]: orange nodes are taken whole (5 + 5 + 12 + 7 = 29), blue outlines were split, faded nodes never contribute.

At every level at most two nodes are split, so a query touches about 4 log n nodes.

4. Update: walk up one path

Changing a[i] only invalidates the nodes whose segment contains i. That is exactly one node per level: the leaf and all its ancestors. Set the leaf, then recompute each parent on the way back to the root.

Fig 4 · Update a[2] from 1 to 6. Delta = +5 flows up through [2..3], [0..3] and the root.

5. Code

Recursive version, 0-indexed array, inclusive ranges. Call build(1, 0, n - 1) once, then query(1, 0, n - 1, l, r) and update(1, 0, n - 1, i, x).

const int MAXN = 100005;
int n, a[MAXN], t[4 * MAXN];          // t[v]: sum of node v's segment, root = 1

void build(int v, int l, int r) {
    if (l == r) { t[v] = a[l]; return; }
    int m = l + (r - l) / 2;
    build(2 * v, l, m);
    build(2 * v + 1, m + 1, r);
    t[v] = t[2 * v] + t[2 * v + 1];
}

int query(int v, int l, int r, int ql, int qr) {   // inclusive
    if (qr < l || r < ql) return 0;               // disjoint
    if (ql <= l && r <= qr)  return t[v];            // fully inside
    int m = l + (r - l) / 2;                         // partial: split
    return query(2 * v, l, m, ql, qr) + query(2 * v + 1, m + 1, r, ql, qr);
}

void update(int v, int l, int r, int pos, int val) {
    if (l == r) { t[v] = val; return; }
    int m = l + (r - l) / 2;
    if (pos <= m) update(2 * v, l, m, pos, val);
    else         update(2 * v + 1, m + 1, r, pos, val);
    t[v] = t[2 * v] + t[2 * v + 1];                    // recompute on the way back up
}

6. Cost

Build
O(n)

Each of the ~2n nodes is combined once.

Query / update
O(log n)

One path of length log n, with at most two splits per level.

Memory
O(n)

About 2n nodes, 4n slots allocated.

7. When to use it

The tree only needs an operation that is associative, because every segment is built from two halves joined once. Unlike the sparse table, nothing is counted twice, so sum, xor, product, min, max and gcd all work.

Prefix sumsO(n)O(1)O(n)
Sparse tableO(n log n)O(1)rebuild
Segment treeO(n)O(log n)O(log n)

Pitfalls

  • Allocate 4n nodes. 2n is only enough when n is a power of two.
  • Return the neutral element for disjoint nodes: 0 for sum, +∞ for min, -∞ for max.
  • Compute the midpoint as l + (r - l) / 2 and use inclusive ranges consistently.
  • Updating a whole range, such as "add x to a[l..r]", needs lazy propagation. Plain point updates do not.
