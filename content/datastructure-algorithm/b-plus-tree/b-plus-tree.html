B+ Tree

A B-Tree that keeps every key in the leaves, and links the leaves into a sorted chain. The upper levels only route searches. Point lookups stay fast, and range scans become a walk along the chain.

Try the machine first

Insert keys and watch leaves split. A leaf split copies the first key of the new leaf up into the parent, so the key stays in the leaves. Then run a range scan: the tree finds the first leaf once, and the arrows between leaves do the rest.

1. The idea

  
In a B-Tree, every node holds keys and values, so internal nodes spend page space on values. A B+ Tree changes two things. Internal nodes hold only keys, used as signposts, so more of them fit in a page and the tree gets even shorter. And every real entry lives in a leaf, at the same depth.

  
The leaves are chained left to right. Once you are in the leaf for the start of a range, you never go back up the tree.

  
Internal nodes route. Leaves store. The chain scans.






  
2. Search

  
Descend like a B-Tree, but never stop early. A key in an internal node is only a signpost, so an equal key means "go right", and the search always ends in a leaf.

  
function find(node, k) {
  while (!node.isLeaf) {
    let i = 0;
    while (i < node.keys.length && k >= node.keys[i]) i++;   // equal goes right
    node = node.children[i];
  }
  return node.keys.includes(k);
}






  
3. Insert and split

  
Add the key to its leaf. If the leaf overflows, split it into two leaves and copy the first key of the right leaf into the parent. The key stays in the leaf. If the parent overflows, split it like a B-Tree node: the middle key moves up and does not stay behind.

  
function splitLeaf(leaf) {
  const right = makeLeaf(leaf.keys.splice(2));
  right.next = leaf.next;                // keep the chain intact
  leaf.next = right;
  return { up: right.keys[0], left: leaf, right };   // copied, not moved
}






  
4. Range scan

  
Find the leaf that would hold the lower bound, then follow next pointers and collect keys until one passes the upper bound. The cost is one descent plus the leaves that hold the answer.

  
function range(lo, hi) {
  let leaf = findLeaf(lo), out = [];
  for (; leaf; leaf = leaf.next) {
    for (const k of leaf.keys) {
      if (k > hi) return out;
      if (k >= lo) out.push(k);
    }
  }
  return out;
}

  
A plain B-Tree has to climb back up and down through parents to reach the next key. That is why ORDER BY and BETWEEN queries favor B+ Trees.






  
5. Cost and comparison

  

    
Point lookup
O(logm n)
Always reaches a leaf, so every lookup costs the same.

    
Range scan
O(logm n + k)
One descent, then k results along the chain.

    
Fan-out
higher
Internal nodes hold no values, so more keys fit per page.

6. Where it shows up

  
    
    
  • Relational databases: InnoDB in MySQL, PostgreSQL indexes, SQL Server, and Oracle use B+ Tree indexes.
    • 
    
  • File systems: NTFS, XFS, and ReiserFS keep directories and extents in B+ Trees.
    • 
    
  • Embedded stores: SQLite stores tables as B+ Trees.
    • 
  

  
Writes go to random pages, which is costly on disk. If your load is mostly writes, an LSM Tree turns them into sequential appends.
