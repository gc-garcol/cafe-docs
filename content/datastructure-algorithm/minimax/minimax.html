Minimax

How a program picks a move in a two-player game. Assume your opponent plays their best, look ahead through the game tree, and choose the move whose worst case is the best you can get.

1. The idea

  
In a turn-based game with perfect information, such as tic-tac-toe or chess, you can draw every future as a tree. Each node is a position. Each edge is a move. The leaves are finished games, or positions you score with a heuristic when you stop looking ahead.

  
Minimax assumes both players play perfectly. You pick the child with the highest score. The opponent picks the child with the lowest score. Scores are from your point of view, so a big number is good for you and bad for them.

  
Pick the move that leaves you best off after the opponent has done their worst.






  
2. The algorithm

  
It is a depth-first recursion. A leaf returns its score. A MAX node returns the largest child value. A MIN node returns the smallest. The root's best child is your move.

  
function minimax(node, depth, isMax) {
  if (depth === 0 || isTerminal(node)) return score(node);

  if (isMax) {
    let best = -Infinity;
    for (const child of moves(node))
      best = Math.max(best, minimax(child, depth - 1, false));
    return best;
  } else {
    let best = Infinity;
    for (const child of moves(node))
      best = Math.min(best, minimax(child, depth - 1, true));
    return best;
  }
}

  
In Fig 1 with its starting scores, the left MIN node sees 5 and 9 and takes 5. The right MIN node sees 2 and 0 and takes 0. The root takes the larger, so it plays left and is guaranteed at least 5.






  
3. Alpha-beta pruning

  
Minimax looks at every leaf, and the tree grows fast. Alpha-beta keeps the same answer but skips branches that cannot change it. It carries two numbers down the recursion:

  
    
    
  • alpha: the best score MAX is already sure to get on the path so far.
    • 
    
  • beta: the best score MIN is already sure to get on the path so far.
    • 
  

  
When beta <= alpha, the two sides disagree about how good this branch is. The player above would never allow it, so the remaining siblings are cut off. In Fig 1 the left side already guarantees MAX a 5. The right MIN node finds a 2 in its first branch, so it can only end up at 2 or less. MAX will not choose it, and the second branch is never looked at.

  
function alphaBeta(node, depth, alpha, beta, isMax) {
  if (depth === 0 || isTerminal(node)) return score(node);

  if (isMax) {
    let best = -Infinity;
    for (const child of moves(node)) {
      best = Math.max(best, alphaBeta(child, depth - 1, alpha, beta, false));
      alpha = Math.max(alpha, best);
      if (beta <= alpha) break; // MIN above will avoid this branch
    }
    return best;
  } else {
    let best = Infinity;
    for (const child of moves(node)) {
      best = Math.min(best, alphaBeta(child, depth - 1, alpha, beta, true));
      beta = Math.min(beta, best);
      if (beta <= alpha) break; // MAX above will avoid this branch
    }
    return best;
  }
}

alphaBeta(root, depth, -Infinity, Infinity, true);

  
Move order matters. If the best moves are tried first, pruning cuts the most. Try captures or the previous best move before the rest.






  
4. Cost

  
With branching factor b and search depth d, plain minimax visits about bd leaves. Alpha-beta with ideal move order visits about bd/2, so it can search twice as deep in the same time. With random order it lands in between.

  

    
Minimax
O(bd)
Every leaf is scored.

    
Alpha-beta, best case
O(bd/2)
Same answer, with perfect ordering.

    
Space
O(d)
Depth-first, one path at a time.

5. Making it practical

  
    
    
  • Depth limit and evaluation function: stop at depth d and score the position with a heuristic, such as material count in chess.
    • 
    
  • Move ordering: search likely-best moves first so alpha-beta prunes more.
    • 
    
  • Iterative deepening: search depth 1, then 2, then 3, until time runs out, and reuse the best move to order the next pass.
    • 
    
  • Transposition table: cache positions reached by different move orders.
    • 
    
  • Negamax: the same algorithm written once, using score = -negamax(child), which removes the MAX and MIN branches.
    • 
  

  
Minimax is for zero-sum games with two players and full information. For games with chance or hidden information, look at expectimax or Monte Carlo tree search.
