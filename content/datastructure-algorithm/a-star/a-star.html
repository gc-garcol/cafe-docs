A* search

Find the shortest path by always expanding the node with the lowest $g + h$: the cost so far plus a guess of the cost left. A good guess lets it skip most of the map.

1. The idea

  
Dijkstra expands the node closest to the start, so it spreads out in every direction. Greedy best-first search expands the node closest to the goal, so it rushes ahead but can walk into a dead end and return a long path. A* combines both. For every node $n$ it keeps three numbers:

  
$$f(n) = \underbrace{g(n)}_{\text{best known cost from start}} + \underbrace{h(n)}_{\text{estimated cost to goal}}$$

  
$f(n)$ estimates the cost of the cheapest full path that goes through $n$. A* always expands the node with the smallest $f$.

  
Always expand the node that looks cheapest overall, not the one that is cheapest so far.

  
Switch the heuristic to None in the demo. With $h = 0$ the search becomes Dijkstra and floods a large area. With Manhattan it narrows toward the goal.






  
2. The algorithm

  
Keep an open set of nodes waiting to be expanded, ordered by $f$, and a closed set of nodes already expanded.

  
function aStar(start, goal) {
  const g = new Map([[start, 0]]), parent = new Map();
  const open = new MinHeap();         // ordered by f = g + h
  const closed = new Set();
  open.push(start, h(start));

  while (open.size) {
    const n = open.pop();
    if (closed.has(n)) continue;     // stale heap entry
    if (n === goal) return pathTo(n, parent);
    closed.add(n);

    for (const m of neighbors(n)) {
      const ng = g.get(n) + cost(n, m);
      if (ng < (g.get(m) ?? Infinity)) {
        g.set(m, ng);
        parent.set(m, n);
        open.push(m, ng + h(m));          // lazy: old entry stays, skipped later
      }
    }
  }
  return null;                       // no path
}

  
The goal is checked when it is popped, not when it is first seen. Only then is its $g$ guaranteed to be optimal. Most heaps cannot lower a key in place, so the code pushes a second entry and skips the stale one when it comes out. The demo uses a plain scan of the open list to stay short. Real code uses a heap so each pop costs $O(\log n)$.






  
3. Admissible and consistent

  
The heuristic decides everything. Write $h^*(n)$ for the true cost of the cheapest path from $n$ to the goal. Two properties matter.

  
$$\textbf{admissible:}\quad h(n) \le h^*(n) \ \text{ for every } n \qquad\qquad \textbf{consistent:}\quad h(n) \le c(n, m) + h(m) \ \text{ for every edge } (n, m)$$

  
Admissible means the guess is never too high. Consistent is a triangle inequality: the guess at $n$ is never more than one step plus the guess at the neighbor. Consistency, with $h(\text{goal}) = 0$, implies admissibility. The heuristics people actually use are almost always consistent.


  
Why admissible means optimal

  
Let $C^*$ be the optimal cost and suppose A* pops the goal with a worse cost $C > C^*$. Look at the optimal path. Its start was expanded, its goal was not yet, so some node $n$ on it sits in the open set with its optimal $g(n) = g^*(n)$. Then

  
$$f(n) = g^*(n) + h(n) \;\le\; g^*(n) + h^*(n) = C^* \;<\; C = f(\text{goal})$$

  
So $n$ had a smaller $f$ than the goal and would have been popped first. The contradiction shows the first time the goal is popped, its cost is $C^*$.


  
Why consistent means "expand once"

  
Along any edge from $n$ to $m$, consistency keeps $f$ from going down:

  
$$f(m) = g(n) + c(n,m) + h(m) \;\ge\; g(n) + h(n) = f(n)$$

  
So nodes leave the open set in non-decreasing order of $f$, exactly like Dijkstra pops by distance. When a node is popped, its $g$ is final, and a closed set is safe. With an admissible but inconsistent $h$, a closed node can later be reached more cheaply and must be reopened, which costs time.






  
4. Choosing the heuristic

  
Write $\Delta x = |x_n - x_{\text{goal}}|$ and $\Delta y = |y_n - y_{\text{goal}}|$. The right heuristic is the exact cost on the same map with all walls removed.

  

    
MapHeuristicFormula

    
      
4-way gridManhattan$\Delta x + \Delta y$

      
8-way gridOctile$\max(\Delta x, \Delta y) + (\sqrt2 - 1)\min(\Delta x, \Delta y)$

      
8-way, diagonal costs 1Chebyshev$\max(\Delta x, \Delta y)$

      
Free movementEuclidean$\sqrt{\Delta x^2 + \Delta y^2}$

      
Road networkStraight line ÷ top speed$\lVert p_n - p_{\text{goal}} \rVert / v_{\max}$ for travel time

      
AnythingZero$0$ (Dijkstra)

    
  

  
Among admissible heuristics, bigger is better. If $h_1(n) \le h_2(n)$ everywhere, A* with $h_2$ never expands a node that A* with $h_1$ skips (apart from ties). Euclidean distance on a 4-way grid is admissible but too low, so it expands more than Manhattan. The maximum of two admissible heuristics is admissible too, and at least as strong as either.

  
Try Manhattan × 3 in Fig 1. It overestimates, so the search runs very few steps, but it can return a path that is longer than the best one.

6. Weighted A*: trading cost for speed

  
Inflating the heuristic by $w \ge 1$ makes the search more eager to head for the goal. If $h$ is admissible, the result has a guaranteed quality bound:

  
$$\text{cost found} \;\le\; w \cdot C^*$$

  
The proof is the same as before with $w h(n) \le w h^*(n)$. In practice the found cost is usually much closer to $C^*$ than the bound says. Anytime planners such as ARA* start with a large $w$ to get a path fast, then lower $w$ step by step and reuse earlier work, improving the path while time remains.






  
7. Ties and details that matter

  
    
    
  • Break ties toward the goal. On open grids, many nodes share the same $f$. Preferring the larger $g$ (equivalently the smaller $h$) follows one path to the goal instead of filling a whole diamond of equal-$f$ cells.
    • 
    
  • Corner cutting. On 8-way grids, decide whether a diagonal step may squeeze between two walls. The lab does not allow it.
    • 
    
  • Units. If edges are measured in seconds, the heuristic must be in seconds too. A distance in meters used as a time estimate is either useless or inadmissible.
    • 
    
  • Unreachable goal. A* then explores everything it can reach before giving up. A quick connected-components check up front avoids this.
    •

The landmark heuristic is a good example of building a stronger $h$ from data. For a landmark $L$ with known distances $d(L, \cdot)$, the triangle inequality gives a lower bound on the distance from $v$ to the goal $t$ in an undirected graph:

  
$$h(v) = \max_{L} \,\bigl|\, d(L, t) - d(L, v) \,\bigr| \;\le\; d(v, t)$$






  
9. Cost

  

    
Best case
$O(d)$
A perfect heuristic walks straight down the path.

    
Worst case
$O(b^d)$
A weak heuristic degrades to Dijkstra.

    
Memory
$O(b^d)$
It stores every open and closed node.

  

  
$b$ is the branching factor and $d$ is the depth of the solution. On an explicit graph with $V$ nodes and $E$ edges, A* with a consistent heuristic is never worse than Dijkstra with a binary heap:

  
$$O\bigl((V + E)\log V\bigr)$$

  
The number of expansions shrinks when the heuristic error $h^*(n) - h(n)$ is small. With a constant error, the search stays close to the optimal path. With an error that grows with distance, as is common, the savings are a constant factor, not an exponential one. Memory is usually the limit before time is. IDA* trades repeated work for a footprint linear in $d$.






  
10. Common mistakes

  
    
    
  • Stopping when the goal is pushed. A cheaper route may still be waiting in the open set. Stop when it is popped.
    • 
    
  • Using Euclidean or octile distance with the wrong moves. Octile on a 4-way grid is too low, which is safe but slow. Manhattan on an 8-way grid overestimates, which breaks optimality.
    • 
    
  • Skipping a better path to an open node. If a node is reached again with a lower $g$, update its parent and push it again.
    • 
    
  • A closed set with an inconsistent heuristic. Nodes may need reopening. Either make $h$ consistent or allow reopening.
    • 
    
  • Floating-point ties. With $\sqrt2$ costs, compare with a small tolerance or use integer costs such as 10 and 14.
    • 
  






  
11. Where it shows up

  
    
    
  • Games: NPC navigation on grids and navigation meshes.
    • 
    
  • Maps and routing: road networks, often with landmark heuristics or precomputed hierarchies.
    • 
    
  • Robotics: motion planning over a discretized space, with D* Lite for replanning.
    • 
    
  • Puzzles: the 8-puzzle and 15-puzzle with Manhattan or pattern-database heuristics.
    • 
    
  • Planning and parsing: any search with a state graph and a cost estimate, including AI planners and some speech decoders.
    • 
    
  • Related search: minimax searches a game tree against an opponent, where A* searches a graph alone.
