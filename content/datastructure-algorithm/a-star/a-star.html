A* search

Find the shortest path by always expanding the node with the lowest g + h: the cost so far plus a guess of the cost left. A good guess lets it skip most of the map.

1. The idea

  
Dijkstra expands the node closest to the start, so it spreads out in every direction. Greedy search expands the node closest to the goal, so it rushes ahead but can walk into a dead end and return a long path. A* combines both.

  
g(n) = cost of the best known path from start to n
h(n) = estimated cost from n to the goal
f(n) = g(n) + h(n)   // estimated total cost through n

  
Always expand the node that looks cheapest overall, not the one that is cheapest so far.

  
Switch the heuristic to None in the demo. With h = 0 the search becomes Dijkstra and floods a large area. With Manhattan it narrows toward the goal.






  
2. The algorithm

  
Keep an open set of nodes waiting to be expanded, ordered by f, and a closed set of nodes already expanded.

  
function aStar(start, goal) {
  const g = new Map([[start, 0]]), parent = new Map();
  const open = new MinHeap();         // ordered by f = g + h
  const closed = new Set();
  open.push(start, h(start));

  while (open.size) {
    const n = open.pop();
    if (closed.has(n)) continue;     // stale heap entry
    if (n === goal) return pathTo(n, parent);
    closed.add(n);

    for (const m of neighbors(n)) {
      const ng = g.get(n) + cost(n, m);
      if (ng < (g.get(m) ?? Infinity)) {
        g.set(m, ng);
        parent.set(m, n);
        open.push(m, ng + h(m));
      }
    }
  }
  return null;                       // no path
}

  
The goal is checked when it is popped, not when it is first seen. Only then is its g guaranteed to be optimal. The demo uses a plain scan of the open list to stay short. Real code uses a heap so each pop costs O(log n).






  
3. Choosing the heuristic

  
The heuristic decides everything. Two properties matter.

  
    
    
  • Admissible: h never overestimates the true remaining cost. With an admissible h, the path A* returns is optimal.
    • 
    
  • Consistent: h(n) ≤ cost(n, m) + h(m) for every edge. Then each node is expanded at most once, which is why a closed set is safe.
    •

Try Manhattan × 3. It overestimates, so the search runs very few steps, but it can return a path that is longer than the best one. That is the usual trade: a bigger h is faster and less exact.






  
4. Cost

  

    
Best case
O(d)
A perfect heuristic walks straight down the path.

    
Worst case
O(bd)
A weak heuristic degrades to Dijkstra.

    
Memory
O(bd)
It stores every open and closed node.

  

  
b is the branching factor and d is the depth of the solution. Memory is usually the limit before time is. IDA* trades repeated work for a much smaller footprint.






  
5. Where it shows up

  
    
    
  • Games: NPC navigation on grids and navigation meshes.
    • 
    
  • Maps and routing: road networks, often with landmark heuristics.
    • 
    
  • Robotics: motion planning over a discretized space.
    • 
    
  • Puzzles: the 8-puzzle with misplaced-tile or Manhattan heuristics.
    • 
    
  • Parsing and planning: any search with a state graph and a cost estimate.
