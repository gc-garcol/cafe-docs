1. ConfigMap / Secret

  
A ConfigMap holds non-secret settings. A Secret holds sensitive values. Both are injected as environment variables or mounted files. Mounted files update in place. Environment variables do not.

  
Secret values are only base64 encoded, not encrypted. Turn on encryption at rest for etcd, restrict who can read Secrets, and consider an external store through the Secrets Store CSI driver.







  
2. RBAC

  
A Role lists allowed verbs on resources in one namespace. A ClusterRole does the same cluster-wide or for non-namespaced objects. A RoleBinding or ClusterRoleBinding grants it to users, groups or ServiceAccounts. Rules only allow. There is no deny.


kubectl auth can-i list pods -n dev --as system:serviceaccount:dev:app






  
3. ServiceAccount

  
The identity of a Pod, as opposed to a person. Each namespace has a default one. Pods get a short-lived, audience-bound token projected into the container, not a long-lived secret. Give each workload its own ServiceAccount and bind only what it needs. Set automountServiceAccountToken: false when a Pod never calls the API.

5. Pod Security Standards

  

    
LevelWhat it allows

    
      
privilegedNo restrictions.

      
baselineBlocks known privilege escalations such as host namespaces and privileged containers.

      
restrictedCurrent hardening best practice: non-root, no escalation, dropped capabilities.

    
  
  
The built-in Pod Security Admission applies a level per namespace with labels, in enforce, audit or warn mode.







  
6. Admission Controller

  
After authentication and authorization, a request passes admission. Mutating controllers may change the object, such as adding defaults or sidecars. Then validating controllers accept or reject it. Built-in ones include LimitRanger and ResourceQuota. ValidatingAdmissionPolicy lets you write rules in CEL with no webhook server.







  
7. OIDC / TLS

  
Users usually sign in through OIDC with an identity provider. The API server checks the ID token and maps claims to a user and groups, which RBAC then uses.

  
TLS protects every component link. The API server, etcd and kubelets use certificates, and kubeadm rotates them. cert-manager issues certificates for Ingress and in-cluster use.
