Kubernetes Storage

How Pods keep data. Volumes live with a Pod, PersistentVolumes outlive it, and classes and CSI drivers create them on demand.

#kubernetes#k8s#volume#pv

Claim a volume

A PersistentVolumeClaim asks for size, access mode and a class. The control plane binds it to the smallest PersistentVolume that fits, or provisions a new one when the class allows it.

standard has a provisioner, so it can create volumes on demand.

1. Volume

  
A volume is a directory mounted into containers. Its life is tied to the Pod, not the container, so data survives a container restart.

  

    
TypeUse

    
      
emptyDirScratch space shared by containers. Deleted with the Pod.

      
hostPathA path on the node. Avoid it outside system agents.

      
configMap / secretFiles built from config objects.

      
projectedMerges several sources into one directory.

      
persistentVolumeClaimDurable storage. See next.

    
  






  
2. PV / PVC

  
A PersistentVolume is a piece of storage in the cluster. A PersistentVolumeClaim is a request for it by size, mode and class. The Pod mounts the claim and never names the storage. That splits the roles: admins and drivers supply volumes, developers ask for them.







  
3. StorageClass

  
A StorageClass names a kind of storage and the driver that creates it, plus parameters such as disk type. A claim that names a class gets a volume created on demand. Set one class as default. volumeBindingMode: WaitForFirstConsumer delays creation until the Pod is scheduled, so the volume lands in the right zone.







  
4. CSI

  
The Container Storage Interface is the plugin contract for storage. Drivers such as the AWS EBS, GCE PD or Ceph drivers run as Pods. A controller part creates, attaches and snapshots volumes. A node part mounts them. Storage vendors ship their own driver with no change to Kubernetes.







  
5. Access Modes

  

    
ModeMeaning

    
      
ReadWriteOnce (RWO)Read and write by one node.

      
ReadOnlyMany (ROX)Read only by many nodes.

      
ReadWriteMany (RWX)Read and write by many nodes. Needs a shared filesystem such as NFS or CephFS.

      
ReadWriteOncePod (RWOP)Read and write by exactly one Pod.

    
  
  
Block disks are usually RWO only. The backend decides which modes are possible.







  
6. Stateful Storage

  
    
    
  • A StatefulSet uses volumeClaimTemplates to give each Pod its own claim. The claim is kept when the Pod is rescheduled.
    • 
    
  • reclaimPolicy decides what happens when a claim is deleted: Delete removes the data, Retain keeps it for manual recovery.
    • 
    
  • Use VolumeSnapshots for backups and cloning. Resize a claim by raising its size if the class allows expansion.
