1. Control plane and nodes

  
A cluster has two halves. The control plane decides what should run. Worker nodes run it.

  

    
ComponentJob

    
      
kube-apiserverThe front door. Every client and every component talks to the cluster through this REST API. It validates requests and stores them.

      
etcdA consistent key-value store. It holds all cluster state. Only the API server talks to it.

      
kube-schedulerPicks a node for each Pod that has none.

      
controller managerRuns control loops that push actual state toward desired state.

      
kubeletThe agent on each node. It starts the containers of Pods assigned to its node and reports status.

      
kube-proxyPrograms node networking rules so Services reach their Pods.

      
container runtimePulls images and runs containers, for example containerd.

    
  






  
2. The reconcile loop

  
Declare what you want. Controllers keep making it true.

  
You never tell Kubernetes to start a container. You store an object that describes the desired state. A controller watches objects of its kind, compares them with the real world, and acts on the difference. It repeats forever, so a crashed Pod is replaced with no human step.






  
3. Components talk only to the API server

  
The scheduler, controllers and kubelets never call each other. Each one watches the API server for objects it cares about and writes its result back. The scheduler sets a Pod's nodeName. The kubelet sees a Pod bound to its node and starts it. This keeps every part replaceable and lets the control plane run several copies.


kubectl apply -f deploy.yaml   # API server validates, writes to etcd
kubectl get pods -w            # watch the Pods appear and change






  
4. What a node adds

  
    
    
  • The kubelet registers the node, sends heartbeats, and runs liveness and readiness probes.
    • 
    
  • If heartbeats stop, the node controller marks the node unreachable and its Pods are rescheduled.
    • 
    
  • Add-ons such as cluster DNS run as ordinary Pods in the kube-system namespace.
