1. The scheduling cycle

  
The scheduler watches for Pods with no node. For each one it picks a node, then writes the choice to the API server as a binding. The kubelet takes it from there. If no node fits, the Pod stays Pending and the scheduler retries when the cluster changes.






  
2. Filter

  
A node must pass every check.

  
    
    
  • Resources: the free CPU and memory must cover the Pod's requests. Requests are what the scheduler counts. Limits are enforced later by the runtime.
    • 
    
  • nodeSelector and affinity: the node's labels must match what the Pod asks for.
    • 
    
  • Taints: a tainted node repels Pods unless they carry a matching toleration.
    • 
    
  • Ports, volumes, topology: other constraints such as zone spread.
    • 
  






  
3. Score

  
Each surviving node gets a score from several plugins. The defaults favor balance. A node with more free resources after placement scores higher, so load spreads out. The highest score wins and ties break at random. This demo uses free CPU plus free memory share as a simple stand-in.






  
4. Requests and limits

  

    
FieldEffect

    
      
requestsReserved on the node for scheduling. Sets the Pod's quality of service class.

      
limitsThe ceiling. CPU over the limit is throttled. Memory over the limit gets the container killed.

    
  

  
Set requests close to real use. Too low and nodes overcommit. Too high and capacity is wasted.
