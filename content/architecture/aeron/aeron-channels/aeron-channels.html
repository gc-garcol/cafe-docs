Aeron Channels and Streams

How a publisher and a subscriber find each other. A channel URI says where data travels, a stream id separates flows, and a session id tells publishers apart.

Build a channel first

A publisher and a subscriber find each other with a channel URI and a stream id. Pick a media type and set a few options. The URI and a plain reading of it update as you go.

1. Channel, stream and session

  
    
    
  • Channel: where data travels. A URI such as an endpoint and a media type.
    • 
    
  • Stream: an integer id that separates independent flows on one channel. Think of it as a port inside the channel.
    • 
    
  • Session: one publisher on one stream. Each publication gets a session id, so a subscriber can tell two publishers apart on the same channel and stream.
    • 
  

  
A subscription to a channel and stream receives an image for each session that publishes there. Streams are independent. Flow control and loss on one do not affect another.






  
2. The channel URI

  
The shape is a scheme, a media, then a query of key=value pairs joined by a pipe.

  
aeron:udp?endpoint=localhost:40123|mtu=1408
aeron:ipc

  
Aeron strips some parameters when it matches a publication with a subscription, so the two sides do not need identical strings. They need the same endpoint and stream id.






  
3. Media types

  

    
MediaWhat it does

    
      
UDP unicastOne sender to one receiver. The subscription sets the endpoint it listens on, and the publication sends to it.

      
UDP multicastOne sender to many receivers through a multicast group address. Needs network support, and an interface to bind.

      
MDCMany receivers without multicast. The publisher sends a unicast stream to each one.

      
IPCShared memory on one machine. No network, always reliable.

    
  






  
4. Multi-destination-cast

  
MDC acts like multicast for flow control. Each destination is treated as a multicast receiver, but the data goes out as separate unicast streams. It runs in one of two modes.

  
    
    
  • Dynamic: the publication sets a control address. Subscribers name that address plus their own endpoint, and join or leave by themselves. Silent subscribers time out.
    • 
    
  • Manual: the application adds and removes destinations by calling addDestination and removeDestination.
    • 
  

  
A subscription can also start without an endpoint and add destinations later. That lets one subscription mix unicast, multicast and MDC sources.






  
5. Common options

  

    
OptionEffect

    
      
reliable=falseThe subscriber accepts loss. The driver fills gaps with padding instead of waiting for retransmission.

      
term-lengthSize of each term in the publication's log buffer. A power of two.

      
mtuLargest frame sent. Messages bigger than this are fragmented.

      
session-idPin the session id, or restrict a subscription to one session.

      
interfaceThe network interface to use, mostly for multicast.

      
endpoint with port 0A wildcard port. The driver picks a free one.

    
  

  
Durations take units, such as 5s or 200ms, and sizes accept k, m and g.






  
6. Spy subscriptions

  
Prefix a UDP channel with aeron-spy: to read an outgoing publication on the same machine. The spy reads the publication buffer directly, like an IPC subscriber, beside the Sender. This is how Archive records a stream at the sending end without a network hop.

  
aeron-spy:aeron:udp?endpoint=localhost:40123
