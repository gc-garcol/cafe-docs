Aeron Reliability and Flow Control

What happens when packets are lost or a subscriber is slow. Receivers detect gaps and send NAKs, status messages set windows, and flow control gives publishers back-pressure.

Try the lossy link first

Ten packets will cross a network. Click packets to mark them as lost on the wire, then Send all. A reliable stream detects the gap, sends a NAK and gets the packet again. Switch to unreliable and the gap is filled with padding instead.

1. What Aeron promises

  
Aeron moves messages reliably between media drivers. Order is kept, gaps are found and repaired, much like TCP. That is delivery. It does not mean the subscriber finished processing a message, because a subscriber can crash right after it reads one.

  
True guarantees need the application to take part: process messages idempotently, know how far you got, and acknowledge back. Aeron gives the building blocks, and Archive and Cluster add durability on top.

  
Delivery to a driver is not the same as processing by an application.






  
2. Loss and NAKs

  
Every frame carries its position in the stream. The Receiver notices a gap when a frame arrives beyond the position it expects. After a short delay, so reordered packets are not mistaken for loss, the driver sends a NAK that names the missing range. The Sender retransmits from its log buffer.

  
    
    
  • NAKs repeat until the gap is filled, as long as the sender is considered alive.
    • 
    
  • A reliable session only exists while both ends are active. There is no store and forward when the subscriber is away.
    • 
    
  • The driver records unresolved loss in a loss report file. Monitoring tools read it.
    • 
  






  
3. Unreliable streams

  
Some subscribers prefer a hole to a delay, for example fast market data on multicast. Set reliable=false on the subscription channel. When loss is found, the driver fills the gap with padding that the subscription skips, with no wait for a NAK.

  
aeron:udp?endpoint=localhost:54325|reliable=false

  
IPC delivery and spy subscriptions are always reliable, because no network is involved.






  
4. Flow control

  
Flow control stops a publisher from overrunning a subscriber. It works per stream, so a slow stream does not slow another. It has three checkpoints.

  
    
    
  1. Application to Sender: an offer succeeds only while the publisher stays within the term window of the driver's consumption point. Otherwise it returns back-pressure.
    2. 
    
  2. Sender to Receiver: the Sender may send only up to the receiver window past what the receiver has consumed.
    3. 
    
  3. Receiver to subscription: the Receiver buffers only data inside the window it last advertised.
    4. 
  

  
Receivers advertise their state in status messages. Each one gives the highest consumed position and the window the receiver is willing to accept.






  
5. How far ahead can a publisher be

  
End to end, a publisher can be ahead of a subscriber by the publication term window plus the receiver window. Choose a term length to see it.

  

    
    

  

  
The defaults are half a term for the publication window, and 128 KB for the receiver window. Both are capped at half a term.






  
6. Multicast strategies

  
With several receivers, the Sender needs one view of their progress. A flow control strategy combines their status messages.

  

    
StrategyPace set byEffect

    
      
max (default)The fastest receiverA slow receiver may fall behind, lose its image and rejoin at the live point.

      
minThe slowest receiverNo receiver is left behind, and one slow one slows everyone.

      
taggedThe slowest tagged receiverOnly receivers you tag hold the stream back.

    
  

  
The min and tagged strategies can also require a minimum group size before the publication reports as connected.
