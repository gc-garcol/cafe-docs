1. VPC and subnets

  
A VPC is your private network in one Region. You choose its address range, such as 10.0.0.0/16. You split it into subnets, each in one Availability Zone. Instances live in subnets.






  
2. Route tables decide public or private

  
Nothing about a subnet is public by itself. A subnet is public when its route table sends 0.0.0.0/0 to an Internet Gateway. It is private when it does not.

  

    
PieceRole

    
      
Internet GatewayTwo-way door between the VPC and the internet. An instance also needs a public or Elastic IP to use it.

      
NAT GatewayLets private instances start outbound connections. The internet cannot start one back. It sits in a public subnet.

      
Route tableRules that map destination ranges to a target. The local route keeps VPC traffic inside.

    
  






  
3. Security groups and network ACLs

  
    
    
  • Security group: a firewall on the instance's network interface. It only has allow rules. It is stateful, so a reply to allowed traffic is allowed automatically.
    • 
    
  • Network ACL: a firewall on the subnet with allow and deny rules. It is stateless, so replies need their own rule.
    • 
  






  
4. A common layout

  
Put load balancers in public subnets. Put application servers and databases in private subnets. Give private subnets a NAT Gateway for updates. Reach other AWS services without the internet through VPC endpoints.
