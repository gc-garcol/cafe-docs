1. CloudWatch

  
The core observability service. Metrics are time series from AWS services and your own code. Logs collect and search log lines, and Logs Insights queries them. Alarms watch a metric, and move between OK, ALARM and INSUFFICIENT_DATA, then notify SNS or trigger scaling. Dashboards show it all. Basic EC2 metrics arrive every 5 minutes, or every minute with detailed monitoring.







  
2. CloudTrail

  
Records AWS API calls: who did what, from where and when. Management events are kept in a searchable 90 day history by default. Create a trail to store events in S3 for longer, for all Regions, and optionally for a whole organization. Turn on data events for S3 objects or Lambda invocations when needed. It is the first stop for security and change investigations.







  
3. X-Ray

  
Distributed tracing. A trace follows one request across services as segments and sub-segments, and X-Ray draws a service map with latency and errors. Instrument with the AWS Distro for OpenTelemetry or the X-Ray SDK. Use sampling to limit volume. Together the three answer different questions: CloudWatch says what is wrong, CloudTrail says who changed it, X-Ray says where the time goes.
