Where code runs. Virtual servers, groups that scale them, functions, and two ways to run containers.

Scale with the load

A load balancer spreads requests over instances, and an Auto Scaling group adds or removes instances to hold average CPU near a target. Move the load, then step time forward.

1. EC2

  
Elastic Compute Cloud gives you virtual servers. You pick an AMI (the image), an instance type and a subnet. Families are tuned for a job: t and m general purpose, c compute, r memory, i storage and p or g GPU. Attach an IAM role through an instance profile, not stored keys.

2. ASG

  
An Auto Scaling group keeps a fleet between a minimum and a maximum, with a desired size, spread over zones. A launch template says what to start. It replaces instances that fail health checks. Policies are target tracking (hold a metric near a value), step, scheduled and predictive. Scale out is quick, scale in is gradual, to avoid flapping.







  
3. Lambda

  
Run code with no servers. Upload a function, and an event starts it: an HTTP call, an S3 upload, a queue message. You pay per request and per millisecond of runtime. You choose memory from 128 MB to 10 GB, and CPU scales with it. A run can last up to 15 minutes.

  
    
    
  • Lambda scales by running more copies in parallel. Set reserved concurrency to protect downstream systems.
    • 
    
  • A cold start is the extra time to create a new environment. Keep packages small and consider provisioned concurrency for latency-critical paths.
    • 
    
  • Functions are stateless. Keep state in S3, DynamoDB or a database.
    • 
  






  
4. ECS

  
Elastic Container Service is AWS's own container orchestrator. A task definition describes containers. A service keeps a number of tasks running and registers them with a load balancer. Run tasks on EC2 instances you manage, or on Fargate, where you pay per task and manage no servers. Use a task role for the app's AWS access and an execution role for pulling images and writing logs.







  
5. EKS

  
Elastic Kubernetes Service runs the Kubernetes control plane for you across zones. Workers are managed node groups, Fargate or Karpenter-provisioned nodes. The VPC CNI gives Pods real VPC IP addresses, and IAM roles for service accounts give Pods their own permissions. Pick EKS when you want Kubernetes portability and its ecosystem, ECS when you want the simplest AWS-native path.
