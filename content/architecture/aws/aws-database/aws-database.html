1. RDS

  
Relational Database Service runs MySQL, PostgreSQL, MariaDB, Oracle, SQL Server or Db2 for you: provisioning, patches, backups and point-in-time restore.

  
    
    
  • Multi-AZ keeps a synchronous standby in another zone and fails over automatically. It is for availability, not read scaling.
    • 
    
  • Read replicas are asynchronous copies that serve reads. They can be in another Region.
    • 
  






  
2. Aurora

  
A cloud-built engine compatible with MySQL and PostgreSQL. Compute is separated from a distributed storage layer that keeps six copies across three zones and grows automatically. Replicas read the same storage, so up to 15 replicas lag very little, and failover is quick. Serverless v2 scales capacity in small steps. Global Database replicates to other Regions.







  
3. DynamoDB

  
A key-value and document database with no servers to manage. Items are found by a partition key, and optionally a sort key. Reads and writes stay in single-digit milliseconds at any size. Capacity is on-demand or provisioned. Add indexes (GSI, LSI) for other access paths, TTL to expire items, Streams for change events, and global tables for multi-Region writes.

  
Design from your queries backward. A key with uneven traffic makes a hot partition.







  
4. ElastiCache

  
Managed in-memory stores, Valkey and Redis OSS or Memcached, with sub-millisecond reads. The common pattern is cache-aside: the app checks the cache, on a miss reads the database and writes the result with a TTL. Use it to cut read load and latency, or for sessions and rate limits. Redis-compatible engines add replication and Multi-AZ failover.
