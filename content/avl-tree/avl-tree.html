AVL Tree

A binary search tree that repairs itself. After every insert or delete, it checks the height of each subtree and rotates when one side gets two levels taller than the other. Search, insert, and delete all stay O(log n).

1. The idea

  
A plain binary search tree is fast only when it is bushy. Insert 1, 2, 3, 4, 5 in order and it becomes a linked list, and every search costs O(n). An AVL tree refuses to let that happen.

  
Each node stores the height of its subtree. The AVL rule says the heights of the two children differ by at most one. When an insert or delete breaks the rule, the tree restructures with a rotation, a local change of a few pointers that keeps the in-order sequence intact.

  
height(null) = 0
height(n)    = 1 + max(height(n.left), height(n.right))
balance(n)   = height(n.left) - height(n.right)   // must be -1, 0, or +1

  
The rule is strict enough to bound the height at about 1.44 log₂ n, and cheap enough to restore with one or two rotations.






  
2. Rotations

  
A rotation lifts one child above its parent. Every key keeps its left-to-right order, so the tree is still a valid search tree. There are four ways a node can go out of balance, named after where the extra height sits.

  

    
CaseBalanceFix

    
      
Left-Leftnode +2, left child +1 or 0Rotate right at the node

      
Left-Rightnode +2, left child -1Rotate left at the child, then right at the node

      
Right-Rightnode -2, right child -1 or 0Rotate left at the node

      
Right-Leftnode -2, right child +1Rotate right at the child, then left at the node

    
  

  
function rotateRight(y) {
  const x = y.left;
  y.left = x.right;
  x.right = y;
  update(y); update(x);   // y first: it is now below x
  return x;             // new root of this subtree
}

function rebalance(n) {
  update(n);
  const b = balance(n);
  if (b > 1) {
    if (balance(n.left) < 0) n.left = rotateLeft(n.left);
    return rotateRight(n);
  }
  if (b < -1) {
    if (balance(n.right) > 0) n.right = rotateRight(n.right);
    return rotateLeft(n);
  }
  return n;
}

  
rotateLeft is the mirror image. Notice that the double rotations are just a single rotation preceded by one that turns the zig-zag into a straight line.






  
3. Insert and delete

  
Both operations are the ordinary BST versions with one extra line: after the recursive call returns, call rebalance on the way back up. Only nodes on the path from the root to the change can go out of balance, so there are at most O(log n) checks.

  
function insert(n, key) {
  if (!n) return node(key);
  if (key < n.key) n.left  = insert(n.left, key);
  else if (key > n.key) n.right = insert(n.right, key);
  return rebalance(n);
}

  
An insert needs at most one rotation (single or double) to restore the whole tree. A delete can need one rotation at every level on the way up, which is still O(log n) in total.

  
Deleting a node with two children works like a normal BST: copy the in-order successor (the smallest key in the right subtree) into the node, then delete that successor from the right subtree.

5. AVL or Red-Black?

  
    
    
  • AVL keeps the tree more tightly balanced, so lookups are a little faster. It rotates more often on updates.
    • 
    
  • Red-Black allows a looser shape, so updates do less restructuring. It is the usual choice for general-purpose maps and sets.
    • 
    
  • Pick AVL when reads dominate writes, for example in-memory indexes and lookup tables that rarely change.
    • 
    
  • Pick neither when you need a disk-friendly layout. B-trees pack many keys per node to cut page reads.
    • 
  

  
Both guarantee O(log n) in the worst case, unlike an unbalanced BST or a skip list, which are only fast in expectation or on average.
